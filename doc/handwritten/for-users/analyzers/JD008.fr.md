# JD008 : ArbitraryValueInTheoryData

🌍 **Langues :**  
🇫🇷 Français (ce fichier) | 🇬🇧 [English](./JD008.en.md)

| Propriété | Valeur |
|---|---|
| **Catégorie** | Reproductibilité (`JustDummies.Reproducibility`) |
| **Sévérité** | 🟠 Avertissement |
| **Activée par défaut** | Oui |

xUnit évalue le fournisseur de données d'une théorie à la **découverte**, avant l'exécution du moindre cas de test. Une valeur tirée là l'est donc une seule fois pour toute la campagne, hors de toute portée de graine — aussi bien `Any.Reproducibly` que `[Reproducible]`.

Trois défauts tiennent dans cette seule forme, et les trois sont silencieux :

* tous les cas de la théorie reçoivent la **même** valeur : une théorie qui se lit comme énumérant des cas arbitraires énumère une constante ;
* la valeur n'est rejouable depuis aucune graine rapportée, puisque aucune n'était épinglée au moment du tirage ;
* le tirage a lieu même pour les cas filtrés, et sa position dans la séquence se décale dès qu'on ajoute ou retire un cas.

Tirez dans le corps du test, ou faites livrer le **générateur** par le fournisseur et matérialisez-le dans le test.

## Non conforme

```csharp
public static TheoryData<string> Cases => new() {
    Any.String().NonEmpty().Generate(),      // JD008 : tiré à la découverte, partagé par tous les cas
};

[Theory]
[MemberData(nameof(Cases))]
public void It_is_accepted(string reference) { /* ... */ }
```

## Conforme

```csharp
public static TheoryData<IAny<string>> Cases => new() {
    Any.String().NonEmpty(),                 // c'est la recette qui voyage, pas la valeur
};

[Theory, Reproducible]
[MemberData(nameof(Cases))]
public void It_is_accepted(IAny<string> reference) {
    string value = reference.Generate();     // tiré par cas, dans la portée épinglée
}
```

## Ce qu'elle reconnaît comme fournisseur

Un membre nommé par un `[MemberData]` du même type ; un membre retournant `TheoryData` ou `TheoryData<...>` ; un membre retournant une séquence d'`object[]` ; et un type implémentant cette séquence, ce qui est la forme `[ClassData]`.

## Ce qui n'est pas signalé

* Un fournisseur qui livre des générateurs plutôt que des valeurs — la forme conforme ci-dessus.
* Un tirage dans un corps de test ordinaire, ce qui est précisément l'objectif de la règle.
* Un tirage depuis un contexte isolé `Any.WithSeed(...)`, ou un générateur atteint par une variable locale ou un champ plutôt qu'écrit en ligne depuis `Any` (une chaîne dérivée en ligne par `As(...)`, `OrNull()` ou `AsNullable()` reste écrite depuis `Any`, et elle est signalée).
* Un tirage dans une lambda ou une fonction locale que le membre conserve de façon démontrable sans l'exécuter : retournée, rangée dans un champ ou une propriété automatique, placée dans un tableau, une `List<T>` ou une donnée de théorie, ou passée à `new Lazy<T>(…)` ; pour une fonction locale, jamais appelée et seulement conservée ainsi. Elle tire quand on l'invoque, pas quand le membre s'exécute. Tout ce qui peut exécuter le corps sur-le-champ est signalé : une méthode ordinaire (un `Select`, un `ForEach`), tout autre constructeur — `new Service(() => …)` peut appeler son argument —, une invocation sur place, un conteneur lu sur place (`new Func<int>[] { … }[0]()`, `new Lazy<int>(…).Value`), une variable locale que le membre appelle ensuite, un accesseur `set` qui appelle sa valeur. Si vous savez que le constructeur conserve la fabrique, supprimez le diagnostic localement. Un champ ou une propriété automatique ne compte que si rien d'autre dans la même phase — les initialiseurs et les constructeurs du type — ne le relit, donc `_next = () => …; _value = _next();` dans un constructeur est signalé. Une relecture via une méthode qu'ils appellent n'est pas suivie ; la règle sous-signale alors plutôt que de se tromper.
