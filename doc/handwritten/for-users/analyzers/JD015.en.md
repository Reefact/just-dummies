# JD015: StringConstraintsAdmitNoValue

🌍 **Languages:**  
🇬🇧 English (this file) | 🇫🇷 [Français](./JD015.fr.md)

| Property | Value |
|---|---|
| **Category** | Constraints (`JustDummies.Constraints`) |
| **Severity** | 🟠 Warning |
| **Enabled by default** | Yes |

The constants written at the call site admit no value, so the chain throws a `ConflictingAnyConstraintException` the moment the arrange line runs — because two declared lengths contradict each other, because the declared characters leave nothing to draw for a shaped string, because the anchored fragments cannot fit the declared length, or because the declared constraints admit none of the values a `OneOf(...)` supplies.

This is the case [ADR-0014](../../for-maintainers/adr/0014-enforce-structural-any-conflicts-at-compile-time.md) names by hand as the one an analyzer should carry and the type system cannot:

> `Any.String().WithLength(3).StartingWith("ORD-")` conflicts because the prefix needs four characters, while `Any.String().WithLength(12).StartingWith("ORD-")` is valid; the call site and the static types are identical in both.

Only the argument's *value* tells them apart — which is what makes it value-dependent, and what puts it on the analyzer's side of the ADR's line.

## Noncompliant

```csharp
Any.String().WithLength(3).StartingWith("ORD-")                        // the prefix needs 4 characters
Any.String().WithMaxLength(6).StartingWith("SKU-").EndingWith("-EUR")  // 8 characters into a cap of 6
Any.String().AlphaNumeric().OneOf("ORD-1", "ORD-2")                    // the family allows neither value
Any.String().OneOf("abc", "def").InUpperCase()                           // the casing allows neither value
Any.String().StartingWith(" ").WithLength(1).NotBlank()                // the prefix fills it, and carries no non-blank character
Any.String().WithLength(0).NotBlank()                                  // nowhere at all to put one
Any.String().WithoutNumeric().InLowerCase().OneOf("1", "A")            // neither alone empties the pool; together they do
Any.String().WithMinLength(10).WithMaxLength(5)                        // no length satisfies both
Any.String().StartingWith("ORD-").WithLengthBetween(1, 3)              // the range form is checked the same way
Any.String().OneOf("EUR", "USD").WithLength(2)                         // no value has two characters
Any.String().Numeric().WithoutNumeric()                                // nothing left to draw
Any.String().Whitespaces().NotBlank()                                  // only whitespace to draw, and no literal supplies anything else
```

## Compliant

```csharp
Any.String().WithLength(12).StartingWith("ORD-")
Any.String().WithMaxLength(12).StartingWith("SKU-").EndingWith("-EUR")
Any.String().OneOf("ORD-1", "ORD-2")                                   // drop the family: the values are yours
Any.String().AlphaNumeric().OneOf("ORD1", "ORD2")
Any.String().StartingWith("A").WithLength(1).NotBlank()                // the prefix already carries one
Any.String().StartingWith(" ").WithLength(2).NotBlank()                // one filler position is left, which is all it asks
Any.String().WithoutNumeric().InLowerCase().OneOf("1", "A", "a")       // "a" survives both
Any.String().WithLengthBetween(5, 10)
Any.String().StartingWith("ORD-").WithLengthBetween(4, 12)
Any.String().OneOf("EUR", "USD").WithLength(3)
Any.String().AlphaNumeric().WithoutNumeric()
Any.String().Whitespaces().NotBlank().StartingWith("A")                // the prefix supplies the character NotBlank() needs
```

## The four checks, and what the library actually does

**Declared lengths.** A minimum greater than a maximum, or an exact length below the minimum or above the maximum. A minimum comes from `WithMinLength` or the lower bound of `WithLengthBetween`, a maximum from `WithMaxLength` or its upper bound, and an exact length from `WithLength`; `WithLengthBetween` counts as the two bounds it sets, and the message names it as you wrote it. These contradictions are checked first, whether or not a value set is declared, because the library checks them first: `WithLength(5).WithMaxLength(3)` throws before anything else is examined. Reversed ranges and negative lengths are ignored here: the call rejects its own argument, and [JD014](JD014.en.md) reports it.

**Characters left to draw.** On a shaped string, the declared character family or `WithChars` pool, once narrowed by the casing and the subtractions, must still offer the filler at least one character: `Numeric().WithoutNumeric()` leaves none, and the message names every subtraction that removes a character the family offers. `NotBlank()` asks for more when no anchored literal contains a non-whitespace character: the filler must then be able to produce one, so `Whitespaces().NotBlank()` is reported too; the library refuses it when it draws. Calls declared after a `OneOf(...)` are not checked this way, since nothing is drawn beside a value set; its values are checked instead (see below). Calls declared before it are, because the library checks each call as soon as it is declared: `Alpha().WithoutAlpha().OneOf("", "a")` is refused at `WithoutAlpha()`, before the value set is applied.

**Length budget.** The fragments are laid out side by side — `prefix + filler + contained values + filler + suffix`, never overlapping — so the length they need is the sum of their lengths, and that sum must fit the declared length: the exact length if there is one, otherwise the smallest declared maximum, whichever method declared it.

Two things beside the fragments enter that sum, because they enter the generator's own:

* **A repeated prefix, suffix or contained value counts once.** A prefix and a suffix each own a single slot, so re-declaring the same literal is a no-op and declaring a different one is refused outright — `StartingWith("ORD-").StartingWith("ORD-").WithLength(4)` draws `ORD-`. `Containing` has no slot of its own — it accumulates — but an **identical** redeclaration is the same no-op every other constraint gets: `Containing("XY").Containing("XY")` still needs only two characters. Two **different** fragments each claim their own room, so `Containing("XY").Containing("YX")` genuinely needs four.
* **`NotBlank()` is owed a filler position of its own**, but only where no anchored literal already carries a non-blank character. `StartingWith(" ").WithLength(1).NotBlank()` has nowhere to put it; `StartingWith("A").WithLength(1).NotBlank()` needs nothing more, because the prefix settles the guarantee. `NonEmpty()` and `NotBlank()` each set a floor of one even with no fragment at all, so `WithLength(0).NotBlank()` is reported too.

This is the arithmetic the generator performs, and [JD030](JD030.en.md) reads the same floor from the same place, so the interval one names and the budget the other enforces cannot disagree.

The budget is **skipped** for the calls declared after a `OneOf(...)`: a terminal value set changes what the fragments are checked against — they are matched against the pooled values rather than laid out — so `OneOf("aba").WithMaxLength(3).Containing("ab").Containing("ba")` is legal even though the fragments sum to 4. Calls declared before it are still laid out, because the library rejects them as soon as they are declared, before the value set is applied, so `WithMaxLength(3).Containing("ab").Containing("ba").OneOf("aba")` is reported. The only thing left out of that sum is the extra position `NotBlank()` would need: the library asks for it only when it draws, and a chain with a value set draws from that set instead.

**An emptied value set.** A constraint that admits **none** of the values a constant `OneOf(...)` writes: a character family, a custom pool, a subtraction, a casing, a length, an anchored fragment or an exclusion. There is no filler beside a value set — the caller supplies the whole string — so the constraint has nothing of its own to govern and simply removes every value, which the run time refuses at declaration. The remedy is to drop the constraint or to change the values: they are yours, and the constraint contributes nothing.

For a character constraint, that is the counterpart of the exemption below, and the reason the two read differently. An anchored literal claims its own region of a shaped string while the family claims the rest, so the two never meet; a value set claims the **whole** string, so the family's region is that supplied value itself and the two must agree ([ADR-0079](../../for-maintainers/adr/0079-constrain-what-a-dummy-draws-never-the-literals-it-was-given.md)).

Reported only when **every** value is refused. A pool one value survives still draws, so it is a narrowing rather than a contradiction, and [JD029](JD029.en.md) names the values it removed at the severity a working chain deserves. Both rules check the values against the same list of constraints, so JD029 stays silent on exactly the pools from which this rule says no value can be drawn.

**The constraints are weighed together, not only one by one.** A value must satisfy every one of them, so the pool is their intersection — and an intersection can be empty while no single set entering it is. `WithoutNumeric().InLowerCase().OneOf("1", "A")` is refused by the library because the first constraint removes `"1"` and the second removes `"A"`, yet each of them on its own leaves a value standing. Where one constraint *is* answerable for the whole pool it is named alone, because that sentence says what to remove; otherwise every constraint that refuses at least one value is named together. One that refuses none takes no part and is left out — naming it would point at a constraint whose removal changes nothing. Which of the named ones is the *smallest* set answering for it is a set cover, and this rule does not go there ([ADR-0046](../../for-maintainers/adr/0046-bound-the-generators-ambition-never-its-correctness.md)).

## What it does not flag

**A character family, a subtraction or a casing an anchored fragment contradicts.** Those constrain the characters the generator **draws**, and a fragment fixed by `StartingWith`, `EndingWith` or `Containing` is a literal you wrote rather than a draw — so `AlphaNumeric().StartingWith("ORD-")` is legal, and yields `ORD-` followed by alphanumeric characters only, the hyphen appearing in the prefix and nowhere else ([ADR-0079](../../for-maintainers/adr/0079-constrain-what-a-dummy-draws-never-the-literals-it-was-given.md)). The same holds for `WithoutNumeric().StartingWith("ORD-1")` and for `InLowerCase().StartingWith("ORD-")`. This rule used to report all three; it must not, because doing so refuses at build time a chain the run time honours.

* A non-constant fragment or length, and a `NotBlank()` beside a non-constant fragment, since that fragment may supply the character `NotBlank()` needs.
* A chain split across statements or variables. The chain must be written as one expression: following a generator through a local would need dataflow, and a rule that claims a chain is unsatisfiable must see every constraint it carries.
* A conflict-asserting negative test, where the illegal chain is the whole body of a parameterless lambda argument.
* A conflicting second call for a constraint allowed only once per generator — `Alpha().Numeric()`, two different prefixes, a casing beside a `WithChars` pool. The library refuses these as conflicting declarations rather than as values no string satisfies, and [JD034](JD034.en.md) reports them. Repeating the same call is not a conflict: the library ignores the repetition, and so does this rule.
