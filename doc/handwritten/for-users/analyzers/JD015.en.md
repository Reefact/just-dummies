# JD015: StringConstraintsAdmitNoValue

🌍 **Languages:**  
🇬🇧 English (this file) | 🇫🇷 [Français](./JD015.fr.md)

| | |
|---|---|
| **Category** | Constraints (`JustDummies.Constraints`) |
| **Severity** | 🟠 Warning |
| **Enabled by default** | Yes |

The anchored fragments written at the call site cannot fit the declared length, so the chain throws a `ConflictingAnyConstraintException` the moment the arrange line runs.

This is the case [ADR-0014](../../for-maintainers/adr/0014-enforce-structural-any-conflicts-at-compile-time.md) names by hand as the one an analyzer should carry and the type system cannot:

> `Any.String().WithLength(3).StartingWith("ORD-")` conflicts because the prefix needs four characters, while `Any.String().WithLength(12).StartingWith("ORD-")` is valid; the call site and the static types are identical in both.

Only the argument's *value* tells them apart — which is what makes it value-dependent, and what puts it on the analyzer's side of the ADR's line.

## Noncompliant

```csharp
Any.String().WithLength(3).StartingWith("ORD-")                        // the prefix needs 4 characters
Any.String().WithMaxLength(6).StartingWith("SKU-").EndingWith("-EUR")  // 8 characters into a cap of 6
```

## Compliant

```csharp
Any.String().WithLength(12).StartingWith("ORD-")
Any.String().WithMaxLength(12).StartingWith("SKU-").EndingWith("-EUR")
```

## The check, and what the library actually does

**Length budget.** The fragments are laid out side by side — `prefix + filler + contained values + filler + suffix`, never overlapping — so the length they need is the plain sum of their lengths, and that sum must fit the declared length. The budget is **skipped** once `OneOf(...)` is declared: a terminal value set changes what the fragments are checked against — they are matched against the pooled values rather than laid out — so `OneOf("aba").WithMaxLength(3).Containing("ab").Containing("ba")` is legal even though the fragments sum to 4.

## What it does not flag

**A character family, a subtraction or a casing an anchored fragment contradicts.** Those constrain the characters the generator **draws**, and a fragment fixed by `StartingWith`, `EndingWith` or `Containing` is a literal you wrote rather than a draw — so `AlphaNumeric().StartingWith("ORD-")` is legal, and yields `ORD-` followed by alphanumeric characters only, the hyphen appearing in the prefix and nowhere else ([ADR-0077](../../for-maintainers/adr/0077-constrain-what-a-dummy-draws-never-the-literals-it-was-given.md)). The same holds for `WithoutNumeric().StartingWith("ORD-1")` and for `LowerCase().StartingWith("ORD-")`. This rule used to report all three; it must not, because doing so refuses at build time a chain the run time honours.

* A non-constant fragment or length.
* A chain split across statements or variables. The chain must be written as one expression: following a generator through a local would need dataflow, and a rule that claims a chain is unsatisfiable must see every constraint it carries.
* A conflict-asserting negative test, where the illegal chain is the whole body of a lambda argument.
