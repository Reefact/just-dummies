# JD016: CollectionConstraintsAdmitNoValue

🌍 **Languages:**  
🇬🇧 English (this file) | 🇫🇷 [Français](./JD016.fr.md)

| Property | Value |
|---|---|
| **Category** | Constraints (`JustDummies.Constraints`) |
| **Severity** | 🟠 Warning |
| **Enabled by default** | Yes |

The declared count constraints cannot all hold, or the chain asks for more **distinct** elements than its element generator can produce — the cardinality gate [ADR-0004](../../for-maintainers/adr/0004-gate-distinct-collections-by-cardinality-else-bounded-draw.md) records.

Both throw at declaration time, so this rule turns an arrange-time red into a build-time red rather than closing a silent green. That is still worth it: the chain usually sits in an arrange helper several call frames away from the test that dies on it, where the message names two constraints the reader must then go hunting for.

## Noncompliant

```csharp
Dummy.ListOf(Dummy.Int32()).WithCount(0).NonEmpty()                  // fixed at 0, then required non-empty
Dummy.ListOf(Dummy.Int32()).WithMinCount(5).WithMaxCount(2)          // no count satisfies both
Dummy.ListOf(Dummy.Int32()).WithMaxCount(2).Containing(1).Containing(2).Containing(3)   // 3 items, 2 slots
Dummy.SetOf(Dummy.Boolean()).WithCount(5)                            // 5 distinct booleans do not exist
Dummy.ListOf(Dummy.Enum<Day>()).Distinct().WithCount(10)             // more than the enum has members
Dummy.SetOf(Dummy.Int16()).WithCount(70000)                          // only 65536 distinct Int16 values exist
Dummy.SetOf(Dummy.Char().OneOf('a', 'b')).WithCount(5)               // narrowed to 2 characters, not the ASCII 128
```

## Compliant

```csharp
Dummy.ListOf(Dummy.Int32()).WithCountBetween(2, 10)
Dummy.SetOf(Dummy.Boolean()).WithCount(2)
Dummy.ListOf(Dummy.Boolean()).WithCount(10)                          // no Distinct: repeats are fine
Dummy.SetOf(Dummy.Char().OneOf('a', 'b', 'c')).WithCount(3)          // fits the narrowed pool exactly
```

## Which domains it can prove

The ones the compiler settles: `Dummy.Boolean()` (2); the small primitive rows — `Dummy.Char()` (128, the ASCII pool of [ADR-0075](../../for-maintainers/adr/0075-draw-characters-from-the-whole-of-ascii.md)), `Dummy.Byte()`/`Dummy.SByte()` (256), `Dummy.Int16()`/`Dummy.UInt16()` (65536), `Dummy.Half()` (63487 — the distinct finite halves, the two zeros counting as one because they compare equal); `Dummy.Enum<T>()` (its **distinct declared values**, not its declared names — an aliased member such as `Grade { Low = 1, …, Min = 1 }` still counts 3, not 5); and a `OneOf`/`ElementOf` pool of constants (its distinct count). Anything else is unprovable and reported as nothing — **an unprovable domain must never be treated as a small one**.

A pool narrowed with `Dummy.Char().OneOf(...)` is counted for what it actually declares rather than folded back to the 128-value default: the caller's own pool can reach past ASCII on purpose, documented on the member itself, so `Dummy.Char().OneOf('a', 'b')` reads as 2, not 128.

`AllowingCombinations()` is a case in point. It *widens* an enum's universe to the OR-closure of its declared members — eight values for four flags — so counting declared members there would condemn a legal chain. The rule stands down instead of computing the closure: a deliberate false negative, found by dogfooding against `AnyEnumCombinationTests`, which asserts `WithCount(8)` succeeds.

## What it does not flag

* A count or element generator that is not a compile-time constant.
* A chain split across statements — it must be one expression.
* A conflict-asserting negative test, where the illegal chain is the whole body of a lambda argument.
