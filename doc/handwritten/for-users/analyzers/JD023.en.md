# JD023: ScalarChainAdmitsNoValue

🌍 **Languages:**  
🇬🇧 English (this file) | 🇫🇷 [Français](./JD023.fr.md)

| Property | Value |
|---|---|
| **Category** | Constraints (`JustDummies.Constraints`) |
| **Severity** | 🟠 Warning |
| **Enabled by default** | Yes |

The constant constraints narrow the domain to nothing, so the chain throws a `ConflictingAnyConstraintException` the moment the arrange line runs.

The library computes this with one emptiness test over bounds, lattice and allow-list. This rule runs the same test over the constants written at the call site — and stays silent for every argument it cannot fold.

## Noncompliant

```csharp
Any.Int32().Between(1, 10).MultipleOf(20)     // no multiple of 20 in [1, 10]
Any.Int32().Between(4, 4).Odd()               // the only value left is even
Any.Int32().GreaterThan(10).LessThan(3)       // empty interval
Any.Int32().Positive().Negative()             // empty by construction
Any.Int32().Zero().NonZero()                  // the only value left is then forbidden
Any.Int32().OneOf(5).Except(5)                // the allow-list is emptied
Any.Decimal().GreaterThan(100m).LessThan(10m) // empty interval, on a decimal
Any.Decimal().Between(1m, 2m).MultipleOf(5m)  // no multiple of 5 in [1, 2]
Any.TimeSpan().Positive().Negative()          // empty by construction, on a duration
Any.DateTime().After(DateTime.MaxValue)       // nothing lies after the last instant
```

## Compliant

```csharp
Any.Int32().Between(1, 10).MultipleOf(5)
Any.Int32().Between(1, 99).Odd()
Any.Int32().GreaterThan(-100).LessThan(100)
Any.Int32().OneOf(1, 2, 3).Except(2)
Any.Decimal().GreaterThan(1m).LessThan(2m)
Any.DateTime().After(new DateTime(2026, 1, 1)).Before(new DateTime(2026, 1, 2))
```

## The message

The diagnostic names both sides of the conflict, in the words of the exception the chain would throw. When two bounds cross, it quotes the bound the call collides with and the value that bound already requires:

```text
Any.Int32().Between(1, 6).GreaterThan(10)
JD023: No value satisfies this chain: cannot apply GreaterThan(10) because Between(1, 6) already requires values less than or equal to 6
```

When the domain is emptied by a lattice, an allow-list or an exclusion instead, the library weighs these in more detail than this rule does, so the message names every constraint written before the call rather than guessing which one the run time would single out: `cannot apply MultipleOf(20) because no value admitted by Between(1, 10) survives it`.

A strict decimal bound is worded as the strict bound it is — `GreaterThan(1) already requires values greater than 1` — and a temporal bound as the run time renders it, by the tick after an exclusive `After`: `After(2027-01-01) already requires values greater than or equal to 2027-01-02`.

## Scope, and one boundary worth knowing

**The exact types** — the integer generators (`Int32`, `Int16`, `Int64`, `Byte`, `SByte`, `UInt16`, `UInt32`, `UInt64`), `Decimal`, and the temporal ones (`DateOnly`, `DateTime`, `DateTimeOffset`, `TimeSpan`, `TimeOnly`), compared by the ticks or the day numbers they compare by. The binary floating-point families stay out: neighbours and rounding do not fold like integers. On `Decimal` a bound is strict or inclusive, as the generator keeps it, and the lattice is a `MultipleOf` step or a `WithScale` grid; on the temporal generators `After` and `Before` are the bounds and `WithGranularity` the lattice, read in every spelling of a constant [JD014](JD014.en.md) reads.

A time of day follows the window across midnight ([ADR-0125](../../for-maintainers/adr/0125-let-a-time-of-day-window-cross-midnight.md)): the first `Between(start, end)` whose start comes after its end opens a frame that starts the day at `start`, every bound written before or after it is read along the window, and a time outside it admits no value, wherever it was written — `Between(22:00, 06:00).After(12:00)` and `Before(12:00).Between(22:00, 06:00)` are both reported, as the run time refuses both. The ordinary frame, where no window crosses midnight, reads exactly as a date does.

Bounds run to the **representable extremes**. `Any.Int64().LessThanOrEqualTo(long.MinValue)` is a legal chain that yields exactly one value, and is not reported; only a bound asking for something genuinely beyond the range — `GreaterThan(long.MaxValue)` — empties the domain. The first version of this rule got that wrong, using `-long.MaxValue` as its "unbounded" sentinel, which made `long.MinValue` unrepresentable and condemned a chain the library's own suite asserts is legal.

The extremes are each type's own, not the model's: nothing is greater than `int.MaxValue` on `Any.Int32()`, nor less than 0 on `Any.UInt32()`, so `Any.Int32().GreaterThan(int.MaxValue)` and `Any.Byte().GreaterThan(255)` are reported like their `long` twin.

The model reasons in `long`, which every value of the other seven families fits. A `ulong` above `long.MaxValue` does not, so it is left unjudged rather than truncated into a bound meaning something else. Neither is a `UInt64` bound at `long.MaxValue` judged: the model's top is not the type's there, so `Any.UInt64().GreaterThan(long.MaxValue)`, which every value above `long.MaxValue` satisfies, is left alone.

## What it does not flag

* A chain with any argument that does not fold to a constant.
* A chain another rule owns first — a second value set or lattice ([JD034](JD034.en.md)), a step or a scale the guard refuses ([JD014](JD014.en.md)) — and, on a window across midnight, a granularity that does not divide a day, which the run time refuses on its own: the walk ends there rather than judging what comes after.
* A chain that narrows to exactly one value — that one is [JD038](JD038.en.md)'s.
* A `UInt64` bound at or above `long.MaxValue` — at or beyond the model's top, so the chain is left alone.
* A transposed `Between` — an argument the builder refuses before any constraint applies, which is [JD014](JD014.en.md)'s diagnosis.
* A chain split across statements — it must be one expression.
* A constraint the model does not track: the walk ends rather than guessing.
* The `DifferentFrom` an expression typed `IAny<T>` reaches. It is the rejective exclusion, which redraws at generation time and checks nothing at declaration; the rule reads only a typed builder's own `DifferentFrom`, the constructive one ([ADR-0121](../../for-maintainers/adr/0121-exclude-a-value-from-any-generator-by-redrawing.md)).
