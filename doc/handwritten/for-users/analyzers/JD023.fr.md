# JD023 : ScalarChainAdmitsNoValue

🌍 **Langues :**  
🇫🇷 Français (ce fichier) | 🇬🇧 [English](./JD023.en.md)

| Propriété | Valeur |
|---|---|
| **Catégorie** | Contraintes (`JustDummies.Constraints`) |
| **Sévérité** | 🟠 Avertissement |
| **Activée par défaut** | Oui |

Les contraintes constantes réduisent le domaine à rien : la chaîne lève une `ConflictingAnyConstraintException` dès l'exécution de la ligne d'arrangement.

La bibliothèque calcule cela par un unique test de vacuité sur les bornes, le treillis et la liste d'autorisation. Cette règle exécute le même test sur les constantes écrites au site d'appel — et se tait pour tout argument qu'elle ne peut pas replier.

## Non conforme

```csharp
Any.Int32().Between(1, 10).MultipleOf(20)     // aucun multiple de 20 dans [1, 10]
Any.Int32().Between(4, 4).Odd()               // la seule valeur restante est paire
Any.Int32().GreaterThan(10).LessThan(3)       // intervalle vide
Any.Int32().Positive().Negative()             // vide par construction
Any.Int32().Zero().NonZero()                  // la seule valeur restante est ensuite interdite
Any.Int32().OneOf(5).Except(5)                // la liste d'autorisation est vidée
Any.Decimal().GreaterThan(100m).LessThan(10m) // intervalle vide, sur un décimal
Any.Decimal().Between(1m, 2m).MultipleOf(5m)  // aucun multiple de 5 dans [1, 2]
Any.TimeSpan().Positive().Negative()          // vide par construction, sur une durée
Any.DateTime().After(DateTime.MaxValue)       // rien ne vient après le dernier instant
```

## Conforme

```csharp
Any.Int32().Between(1, 10).MultipleOf(5)
Any.Int32().Between(1, 99).Odd()
Any.Int32().GreaterThan(-100).LessThan(100)
Any.Int32().OneOf(1, 2, 3).Except(2)
Any.Decimal().GreaterThan(1m).LessThan(2m)
Any.DateTime().After(new DateTime(2026, 1, 1)).Before(new DateTime(2026, 1, 2))
```

## Le message

Le diagnostic nomme les deux côtés du conflit, dans les termes de l'exception que la chaîne lèverait. Quand deux bornes se croisent, il cite la borne que l'appel heurte et la valeur que cette borne exige déjà :

```text
Any.Int32().Between(1, 6).GreaterThan(10)
JD023: No value satisfies this chain: cannot apply GreaterThan(10) because Between(1, 6) already requires values less than or equal to 6
```

Quand c'est un treillis, une liste d'autorisation ou une exclusion qui vide le domaine, la bibliothèque les pèse plus finement que cette règle : le message nomme alors toutes les contraintes écrites avant l'appel plutôt que de deviner laquelle l'exécution désignerait — `cannot apply MultipleOf(20) because no value admitted by Between(1, 10) survives it`.

Une borne décimale stricte est formulée comme la borne stricte qu'elle est — `GreaterThan(1) already requires values greater than 1` — et une borne temporelle comme l'exécution la rend, au tick qui suit un `After` exclusif : `After(2027-01-01) already requires values greater than or equal to 2027-01-02`.

## Portée, et une limite qui mérite d'être connue

**Les types exacts** — les générateurs entiers (`Int32`, `Int16`, `Int64`, `Byte`, `SByte`, `UInt16`, `UInt32`, `UInt64`), `Decimal`, et les générateurs temporels (`DateOnly`, `DateTime`, `DateTimeOffset`, `TimeSpan`, `TimeOnly`), comparés par les ticks ou les numéros de jour qu'ils comparent. Les familles flottantes binaires restent dehors : voisins et arrondis ne se replient pas comme des entiers. Sur `Decimal` une borne est stricte ou inclusive, comme le générateur la garde, et le treillis est un pas `MultipleOf` ou une grille `WithScale` ; sur les générateurs temporels `After` et `Before` sont les bornes et `WithGranularity` le treillis, lus dans toutes les écritures d'une constante que lit [JD014](JD014.fr.md).

Une heure de la journée suit la fenêtre qui franchit minuit ([ADR-0125](../../for-maintainers/adr/0125-let-a-time-of-day-window-cross-midnight.fr.md)) : le premier `Between(start, end)` dont le début vient après la fin ouvre un cadre où la journée commence à `start`, toute borne écrite avant ou après est lue le long de la fenêtre, et une heure hors de la fenêtre n'admet aucune valeur, où qu'elle soit écrite — `Between(22:00, 06:00).After(12:00)` et `Before(12:00).Between(22:00, 06:00)` sont signalés tous deux, comme l'exécution les refuse tous deux. Le cadre ordinaire, où aucune fenêtre ne franchit minuit, se lit exactement comme une date.

Les bornes vont jusqu'aux **extrêmes représentables**. `Any.Int64().LessThanOrEqualTo(long.MinValue)` est une chaîne légale qui produit exactement une valeur, et n'est pas signalée ; seule une borne réclamant quelque chose de réellement hors plage — `GreaterThan(long.MaxValue)` — vide le domaine. La première version de cette règle s'est trompée là-dessus, en prenant `-long.MaxValue` comme sentinelle « non borné », ce qui rendait `long.MinValue` inexprimable et condamnait une chaîne que la propre suite de la bibliothèque affirme légale.

Les extrêmes sont ceux de chaque type, pas ceux du modèle : rien n'est plus grand que `int.MaxValue` pour `Any.Int32()`, ni plus petit que 0 pour `Any.UInt32()`, donc `Any.Int32().GreaterThan(int.MaxValue)` et `Any.Byte().GreaterThan(255)` sont signalés au même titre que leurs équivalents sur `Int64`.

Le modèle raisonne en `long`, où toute valeur des sept autres familles tient. Un `ulong` au-delà de `long.MaxValue` n'y tient pas : il est laissé sans jugement plutôt que tronqué en une borne qui voudrait dire autre chose. L'analyseur ignore également une borne `UInt64` égale à `long.MaxValue` : le sommet du modèle n'y est pas celui du type, donc l'analyseur ne signale pas `Any.UInt64().GreaterThan(long.MaxValue)`, que toute valeur au-delà de `long.MaxValue` satisfait.

## Ce qui n'est pas signalé

* Une chaîne dont un argument ne se replie pas en constante.
* Une chaîne qu'une autre règle possède d'abord — un second ensemble de valeurs ou un second treillis ([JD034](JD034.fr.md)), un pas ou une échelle que la garde refuse ([JD014](JD014.fr.md)) — et, sur une fenêtre qui franchit minuit, une granularité qui ne divise pas une journée, que l'exécution refuse d'elle-même : le parcours s'arrête là plutôt que de juger ce qui suit.
* Une chaîne qui se réduit à exactement une valeur — celle-là relève de [JD038](JD038.fr.md).
* Une borne `UInt64` égale ou supérieure à `long.MaxValue` — au sommet du modèle ou au-delà, l'analyseur ne signale pas cette chaîne.
* Un `Between` aux bornes transposées — un argument que le constructeur refuse avant toute contrainte, ce qui relève de [JD014](JD014.fr.md).
* Une chaîne répartie sur plusieurs instructions — elle doit être une seule expression.
* Le `DifferentFrom` qu'atteint une expression typée `IAny<T>`. C'est l'exclusion rejective, qui retire au moment de la génération et ne vérifie rien à la déclaration ; la règle ne lit que le `DifferentFrom` propre à un builder typé, l'exclusion constructive ([ADR-0121](../../for-maintainers/adr/0121-exclude-a-value-from-any-generator-by-redrawing.fr.md)).
