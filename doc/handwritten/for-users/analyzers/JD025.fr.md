# JD025 : DuplicatePoolValue

🌍 **Langues :**  
🇫🇷 Français (ce fichier) | 🇬🇧 [English](./JD025.en.md)

| Propriété | Valeur |
|---|---|
| **Catégorie** | Contraintes (`JustDummies.Constraints`) |
| **Sévérité** | 🟡 Avertissement |
| **Activée par défaut** | Oui |

La même valeur figure deux fois dans un réservoir : un ensemble de valeurs écrit avec `OneOf(...)` ou `ElementOf(...)`, ou les caractères du réservoir `WithChars(...)` d'une chaîne. Un réservoir est dédoublonné sous l'égalité par défaut à la construction du générateur : une valeur écrite deux fois n'y contribue qu'une seule fois.

La lecture que cette règle existe pour refuser est la **pondération**. Lister une valeur deux fois ressemble à « tirer celle-ci plus souvent », et la bibliothèque refuse délibérément de pondérer un réservoir — le doublon ne fait donc rien du tout, et le réservoir est plus petit d'une valeur que ce qu'il paraît.

## Non conforme

```csharp
Any.OneOf(1, 2, 1)                          // JD025 : le réservoir contient deux valeurs, pas trois
Any.OneOf("EUR", "USD", "EUR")              // JD025
Any.Int32().OneOf(3, 3)                     // JD025
Any.String().OneOf(["EUR", "USD", "EUR"])   // JD025 : les éléments d'une expression de collection sont analysés comme des arguments individuels
Any.String().WithChars("aab")               // JD025 : le réservoir contient deux caractères, pas trois
```

## Conforme

```csharp
Any.OneOf(1, 2)                             // dire ce qu'est le réservoir
Any.OneOf("EUR", "USD")
Any.String().WithChars("ab")
```

Le diagnostic porte sur la valeur répétée. Dans un réservoir `WithChars` écrit comme un littéral de chaîne simple, il porte sur le caractère répété lui-même ; avec une séquence d'échappement, un littéral verbatim ou une constante déclarée ailleurs, sur tout l'argument.

## Où l'écart se manifeste

Rien n'échoue ici, et c'est bien le problème : la conséquence tombe complètement ailleurs. Une collection distincte au-dessus du réservoir vérifie le **vrai** nombre de valeurs distinctes, et annonce un nombre que l'auteur ne retrouve pas dans son source :

```csharp
Any.SetOf(Any.OneOf(1, 2, 1)).WithCount(3)
// ConflictingAnyConstraintException : The generator can produce only 2
// distinct value(s), not enough for the 3 elements it must still supply.
```

Trois valeurs sont écrites sur la ligne ; le message en annonce deux. Cette règle désigne la ligne réellement fautive.

## Ce qui n'est pas signalé

* Un réservoir dont les éléments ne sont pas tous des constantes de compilation — un seul élément non repliable et le réservoir cesse d'être connaissable, donc la règle se retire plutôt que de signaler un parcours partiel.
* Un réservoir tenu dans une variable ou construit par une requête (`Any.ElementOf(orders)`) ; seules les valeurs écrites sur le site d'appel sont visibles.
* Des valeurs qui se ressemblent seulement : `Any.OneOf("a", "A")` est un réservoir de deux.
* Une valeur listée deux fois dans une liste d'exclusions — `Except("a", "a")`. Une exclusion n'a pas de lecture de pondération : la seconde valeur ne retire rien que la première n'ait déjà retiré, et [JD035](JD035.fr.md) la signale comme une répétition.
