# JD036: UndeclaredNumericRange

🌍 **Languages:**  
🇬🇧 English (this file) | 🇫🇷 [Français](./JD036.fr.md)

| Property | Value |
|---|---|
| **Category** | Constraints (`JustDummies.Constraints`) |
| **Severity** | 🔵 Info |
| **Enabled by default** | Yes |

An `Any.Double()`, `Any.Single()` or `Any.Decimal()` chain declares no range bounded on both sides, so **one draw in ten spans the whole type**: values near `double.MaxValue`, `float.MaxValue` or `decimal.MaxValue`, with every bound, exclusion and scale you did declare still honoured. The other nine stay ordinary: within ±1 000 000, or in a slab beside a one-sided bound you set past it — unless that bound is so large that no ordinary slab is representable beside it, and then every draw spans the declared domain.

That edge draw is deliberate ([ADR-0117](../../for-maintainers/adr/0117-draw-a-limit-value-the-type-permits-one-draw-in-ten.md)). The test not caring about the value is not the code not caring about it, and only a draw that reaches the type's limits can tell the two apart: a multiplication that overflows to infinity, a `decimal` that throws `OverflowException`, a format that breaks on twenty-nine digits. But a deliberate edge only *teaches* when something names the remedy — and a value near `double.MaxValue` in a failure message does not say `Between`. This rule says it, at the call site, which is the one place you can act on it.

**Not seeing it in `dotnet build`?** Info-level diagnostics never print there — that is MSBuild's handling of Info, not a missing rule. Raise this one to a warning in `.editorconfig` to see it in a terminal or in CI: [how](../packages/justdummies.en.md#the-analyzers-travel-inside-the-package).

## Noncompliant

<!-- jd:allow=JD036 -->
```csharp
double  anyRatio  = Any.Double().Generate();
decimal anyAmount = Any.Decimal().Positive().WithScale(2).Generate();
double  anyWeight = Any.Double().Between(0d, double.MaxValue).Generate();
```

`Positive()` closes one side only: the draw is positive every time, ordinary nine times in ten, and the tenth reaches the type's maximum. A bound written against the type's own edge, such as `Between(0d, double.MaxValue)`, closes nothing — it is the domain showing through — so it is reported like the one-sided chain it equals.

## Compliant

```csharp
double  anyRatio  = Any.Double().Between(0d, 1d).Generate();
decimal anyAmount = Any.Decimal().GreaterThan(0m).LessThanOrEqualTo(10_000m).WithScale(2).Generate();
float   anyTemp   = Any.Single().Between(-40f, 60f).Generate();
decimal anyRate   = Any.Decimal().OneOf(0.055m, 0.1m, 0.2m).Generate();
```

Declare the range the surrounding code actually accepts — a measurement's physical bounds, a contract's limit, a column's precision. A range you bound on both sides is drawn whole, end to end, wherever it lies. That is the same contract the rest of the library applies: a constraint expresses what the code **requires** of the value, never what the test asserts.

## Scope

The rule reasons about **one written expression**, rooted at an `Any.Double()`, `Any.Single()` or `Any.Decimal()` factory call — it does not follow a generator through a local, a field or a helper. A bound it cannot fold to a constant is taken as written: it closes its side.

## What it does not flag

* A range bounded on both sides: `Between(...)`, or a floor (`Positive()`, `GreaterThan`, `GreaterThanOrEqualTo`) together with a ceiling (`Negative()`, `LessThan`, `LessThanOrEqualTo`).
* A value set. `OneOf(...)` supplies the values, and no edge draw applies.
* A pin: `Zero()`, `Between(x, x)`, or a single value left on the type's own edge — `GreaterThanOrEqualTo(decimal.MaxValue)`, `Between(double.MinValue, double.MinValue)`.
* `Any.Half()`, whose whole domain already lies within the ordinary window, and the integer generators, which draw across their whole domain already.

## Why it is information, not a warning

A magnitude a test genuinely does not care about is a legitimate thing to leave unsaid — and leaving it unsaid is what lets the edge draw check that the code does not care either. The rule states a fact to weigh, never a verdict — the same posture as [JD030](JD030.en.md). Where a call site genuinely does not care, silence it there with a `[SuppressMessage]` naming `JustDummiesRule.JD036` — see [`JustDummies.DiagnosticCatalog`](../packages/justdummies-diagnosticcatalog.en.md).
