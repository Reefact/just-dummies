# JD036: UndeclaredNumericRange

🌍 **Langues :**  
🇬🇧 [English](./JD036.en.md) | 🇫🇷 Français (ce fichier)

| Propriété | Valeur |
|---|---|
| **Catégorie** | Constraints (`JustDummies.Constraints`) |
| **Sévérité** | 🔵 Info |
| **Activée par défaut** | Oui |

Une chaîne `Any.Double()`, `Any.Single()` ou `Any.Decimal()` ne déclare aucune plage bornée des deux côtés : **un tirage sur dix couvre donc tout le type** — des valeurs proches de `double.MaxValue`, `float.MaxValue` ou `decimal.MaxValue`, chaque borne, exclusion et échelle que vous avez déclarée restant respectée. Les neuf autres restent ordinaires : dans ±1 000 000, ou dans une bande à côté d'une borne unilatérale que vous avez posée au-delà — sauf si cette borne est si grande qu'aucune bande ordinaire n'est représentable à côté d'elle, et alors chaque tirage couvre le domaine déclaré.

Ce tirage au bord est délibéré ([ADR-0117](../../for-maintainers/adr/0117-draw-a-limit-value-the-type-permits-one-draw-in-ten.fr.md)). Que le test ne se soucie pas de la valeur ne veut pas dire que le code ne s'en soucie pas, et seul un tirage qui atteint les limites du type sépare les deux : une multiplication qui déborde vers l'infini, un `decimal` qui lève `OverflowException`, un format qui casse sur vingt-neuf chiffres. Mais un bord délibéré n'*enseigne* que si quelque chose nomme le remède — et une valeur proche de `double.MaxValue` dans un message d'échec ne dit pas `Between`. Cette règle le dit, au site d'appel, le seul endroit où vous pouvez agir.

**Vous ne la voyez pas dans `dotnet build` ?** Les diagnostics de niveau Info n'y sont jamais affichés — c'est la façon dont MSBuild traite Info, pas une règle manquante. Montez celle-ci en avertissement dans `.editorconfig` pour la voir dans un terminal ou en CI : [comment](../packages/justdummies.fr.md#les-analyzers-voyagent-dans-le-paquet).

## Non conforme

<!-- jd:allow=JD036 -->
```csharp
double  anyRatio  = Any.Double().Generate();
decimal anyAmount = Any.Decimal().Positive().WithScale(2).Generate();
double  anyWeight = Any.Double().Between(0d, double.MaxValue).Generate();
```

`Positive()` ne ferme qu'un côté : le tirage est positif à chaque fois, ordinaire neuf fois sur dix, et le dixième atteint le maximum du type. Une borne écrite contre le bord du type lui-même, comme `Between(0d, double.MaxValue)`, ne ferme rien — c'est le domaine qui transparaît — et elle est donc signalée comme la chaîne à un seul côté qu'elle égale.

## Conforme

```csharp
double  anyRatio  = Any.Double().Between(0d, 1d).Generate();
decimal anyAmount = Any.Decimal().GreaterThan(0m).LessThanOrEqualTo(10_000m).WithScale(2).Generate();
float   anyTemp   = Any.Single().Between(-40f, 60f).Generate();
decimal anyRate   = Any.Decimal().OneOf(0.055m, 0.1m, 0.2m).Generate();
```

Déclarez la plage que le code environnant accepte réellement — les bornes physiques d'une mesure, la limite d'un contrat, la précision d'une colonne. Une plage que vous bornez des deux côtés est tirée entière, d'un bout à l'autre, où qu'elle se trouve. C'est le même contrat que le reste de la bibliothèque applique : une contrainte exprime ce que le code **exige** de la valeur, jamais ce que le test affirme.

## Portée

La règle raisonne sur **une seule expression écrite**, enracinée dans un appel de fabrique `Any.Double()`, `Any.Single()` ou `Any.Decimal()` — elle ne suit pas un générateur à travers une locale, un champ ou un helper. Une borne qu'elle ne peut pas réduire à une constante est prise telle qu'écrite : elle ferme son côté.

## Ce qu'elle ne signale pas

* Une plage bornée des deux côtés : `Between(...)`, ou un plancher (`Positive()`, `GreaterThan`, `GreaterThanOrEqualTo`) avec un plafond (`Negative()`, `LessThan`, `LessThanOrEqualTo`).
* Un ensemble de valeurs. `OneOf(...)` fournit les valeurs, et aucun tirage au bord ne s'applique.
* Un épinglage : `Zero()`, `Between(x, x)`, ou une valeur unique laissée sur le bord du type lui-même — `GreaterThanOrEqualTo(decimal.MaxValue)`, `Between(double.MinValue, double.MinValue)`.
* `Any.Half()`, dont tout le domaine tient déjà dans la fenêtre ordinaire, et les générateurs entiers, qui tirent déjà sur tout leur domaine.

## Pourquoi c'est une information et pas un avertissement

Une magnitude dont un test ne se soucie vraiment pas est une chose légitime à ne pas dire — et ne pas la dire est précisément ce qui laisse le tirage au bord vérifier que le code ne s'en soucie pas non plus. La règle énonce un fait à peser, jamais un verdict — la même posture que [JD030](JD030.fr.md). Là où un site d'appel ne s'en soucie vraiment pas, faites-la taire à cet endroit avec un `[SuppressMessage]` nommant `JustDummiesRule.JD036` — voir [`JustDummies.DiagnosticCatalog`](../packages/justdummies-diagnosticcatalog.fr.md).
