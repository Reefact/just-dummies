# JD038: ScalarChainAdmitsOneValue

🌍 **Languages:**  
🇬🇧 English (this file) | 🇫🇷 [Français](./JD038.fr.md)

| Property | Value |
|---|---|
| **Category** | Constraints (`JustDummies.Constraints`) |
| **Severity** | 🟠 Warning |
| **Enabled by default** | Yes |

The constant constraints narrow the domain to **exactly one value**, so the chain draws a constant dressed as a draw. What is significant stays a literal: a value the test chose is written as one, and a draw that cannot vary is the hand-picked literal this library exists to replace ([ADR-0129](../../for-maintainers/adr/0129-report-a-chain-whose-constants-admit-exactly-one-value.md)).

The rule reuses [JD023](JD023.en.md)'s folding — the same walk over the same exact types, asking how much is left rather than whether anything is — and stays silent for every argument it cannot fold.

## Noncompliant

<!-- jd:allow=JD038,JD031 -->
```csharp
int     anyQuantity = Any.Int32().Between(5, 5).Generate();                                  // JD038: always 5
int     anyRetries  = Any.Int32().GreaterThanOrEqualTo(3).LessThanOrEqualTo(3).Generate();   // a floor and a ceiling that meet
int     anyPort     = Any.Int32().OneOf(8080).Generate();                                    // a value set of one
int     anyWeek     = Any.Int32().Between(1, 10).MultipleOf(7).Generate();                   // one point left on the lattice
decimal anyRate     = Any.Decimal().Between(1m, 1.4m).WithScale(0).Generate();              // 1 is the only value on the grid
```

## Compliant

```csharp
int       quantity      = 5;                                         // the value the test chose, written as one
IAny<int> portGenerator = Any.Fixed(8080);                           // a literal where a generator is required
int       anyRetries    = Any.Int32().Between(1, 5).Generate();      // a range, when the test does not care
int       anyZero       = Any.Int32().Zero().Generate();             // a pin by name reads as the constant it is
```

## The message

The diagnostic names the one value and the two ways out:

```text
Any.Int32().Between(5, 5)
JD038: Write the literal 5, or Any.Fixed(5) where a generator is required: the constraints declared on this chain admit exactly one value
```

On a time of day it also names `Any.TimeOnly()`: `Between(t, t)` stays the single value `t` on every type ([ADR-0125](../../for-maintainers/adr/0125-let-a-time-of-day-window-cross-midnight.md)), and a test that wrote it for the whole day is told what names the day.

The diagnostic is placed on the call after which one value is left, which is where you can act on it.

## Inside a generator's factory

Both ways out change the type: the literal is an `int`, `Any.Fixed(1)` an `IAny<int>`. Where the code must
produce the builder itself — the refining lambda of a scaffolded generator, a `Func<AnyInt32, AnyInt32>`,
or a field or factory typed `AnyInt32` — neither compiles. Then:

* in a refining lambda, the one value is a pin, not a refinement: call the generator's pin overload
  instead, `WithCapacity(1)` rather than `WithCapacity(c => c.Between(1, 1))`;
* in a generator you write, type the field or the factory `IAny<int>` where it may hold a constant, and
  assign `Any.Fixed(1)`;
* where the builder type cannot change, keep the chain and silence the rule on that member with a
  `[SuppressMessage]` naming `JustDummiesRule.JD038`, its justification saying why the builder is required.

## Scope

The exact types [JD023](JD023.en.md) reads, with the same folding: the integer generators, `Decimal`, and the temporal ones. A value set reduced to one value, a range whose two bounds meet, a floor and a ceiling that leave one value between them, a lattice with one point left in its range, an exclusion that leaves one.

## Why a warning

An information diagnostic never reaches a terminal or a CI log, so a rule at that severity teaches nothing where a build is read ([JD030](JD030.en.md) says how to raise one). And there is no defensive reading of a constant range reduced to one point: a team that writes `Between(5, 5)` to document that the value matters has written the literal's reason, not the literal, and the literal is clearer.

## What it does not flag

* A value pinned **by name** — `Zero()` — which already reads as the constant it is, however the chain goes on.
* A chain that admits no value, which is [JD023](JD023.en.md)'s, and a chain another rule owns first: a second value set or lattice ([JD034](JD034.en.md)), a transposed range or a refused step ([JD014](JD014.en.md)).
* A chain with any argument that does not fold to a constant: a bound computed from another draw is never reported.
* A binary floating-point generator (`Double`, `Single`, `Half`), and a `UInt64` bound at or above `long.MaxValue`, which [JD023](JD023.en.md) leaves unjudged too.
* A range wider than the few dozen values the rule walks: a domain reduced to one value by excluding a wide range one value at a time is not counted, and not reported.
* A chain split across statements — it must be one expression.

No code fix: replacing the generator with the literal changes the call site's type, and on a time of day the intent is ambiguous.
