# JD039: GeneratorPassedForItsValue

🌍 **Languages:**  
🇬🇧 English (this file) | 🇫🇷 [Français](./JD039.fr.md)

| Property | Value |
|---|---|
| **Category** | Usage (`JustDummies.Usage`) |
| **Severity** | 🟠 Warning |
| **Enabled by default** | Yes |

A generator passed where the value it draws is expected does not compile, and the compiler says only
`CS1503`, cannot convert. This rule explains that error on the argument that raised it, and names the
way out.

The case the third developer-UX trial met is a scaffolded `With…`. It takes a value to pin, or a lambda
to refine the parameter's valid base, and no generator, on purpose
([ADR-0109](../../for-maintainers/adr/0109-let-a-test-refine-a-parameters-valid-base-rather-than-replace-it.md)): a
prepared generator would replace that base with every rule it kept. So a refinement written once is
kept as the lambda it is, not as a generator. Anywhere else, the generator was simply not drawn from.

## Noncompliant

```text
AnyRoute longRoute = new AnyRoute().WithDistanceKm(465);
Shipment anyLongShipment = Any.Shipment().WithRoute(longRoute).Generate();
    // CS1503: cannot convert from 'AnyRoute' to 'Route'
    // JD039: longRoute is a generator of Route, and this parameter takes a Route: refine the parameter
    //        through the lambda overload instead, x => x.…, or pass a drawn value with Generate()

Order order = new Order(Any.String().NonEmpty(), 3);
    // CS1503: cannot convert from 'AnyString' to 'string'
    // JD039: Any.String().NonEmpty() is a generator of string, and this parameter takes a string:
    //        pass a drawn value with Generate()
```

## Compliant

A refinement reused across tests is a `Func` written once:

```csharp
// Arrange
Func<AnyRoute, AnyRoute> longRoute = r => r.WithDistanceKm(465);
Shipment anyLongShipment = Any.Shipment().WithRoute(longRoute).Generate();

// Act
bool needsRestStop = anyLongShipment.NeedsRestStop;

// Assert
Assert.True(needsRestStop);
```

Where the method takes only a value, draw it:

```csharp
string anyName = Any.String().NonEmpty().WithMaxLength(50).Generate();
```

## What it does not flag

* A call that fails for another reason: a generator of another type, a wrong number of arguments. The
  compiler's own message stands alone there.
* A call some overload accepts the generator for: that call compiles.
* A call that compiles: passing a lambda, or a drawn value, is the point.

## Why it only explains

The call already fails to compile, so the rule adds no gate of its own: it puts the reason beside the
`CS1503` the compiler already raises. It reads the candidates overload resolution rejected, and needs no
marker on the method: the argument's own type says it is a generator of `T`, and a candidate parameter
says it takes a `T`.
