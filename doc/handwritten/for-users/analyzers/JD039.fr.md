# JD039 : GeneratorPassedForItsValue

🌍 **Langues :**  
🇫🇷 Français (ce fichier) | 🇬🇧 [English](./JD039.en.md)

| Propriété | Valeur |
|---|---|
| **Catégorie** | Usage (`JustDummies.Usage`) |
| **Sévérité** | 🟠 Avertissement |
| **Activée par défaut** | Oui |

Un générateur passé là où la valeur qu'il tire est attendue ne compile pas, et le compilateur dit
seulement `CS1503`, conversion impossible. Cette règle explique cette erreur sur l'argument qui l'a
provoquée, et nomme la sortie.

Le cas rencontré par le troisième essai UX développeur est un `With…` scaffoldé. Il prend une valeur à
fixer, ou une lambda pour affiner la base valide du paramètre, et aucun générateur, à dessein
([ADR-0109](../../for-maintainers/adr/0109-let-a-test-refine-a-parameters-valid-base-rather-than-replace-it.fr.md)) :
un générateur préparé remplacerait cette base avec chaque règle qu'il a gardée. Un affinement écrit une
fois se garde donc comme la lambda qu'il est, pas comme un générateur. Partout ailleurs, on a
simplement oublié de tirer du générateur.

## Non conforme

```text
AnyRoute longRoute = new AnyRoute().WithDistanceKm(465);
Shipment anyLongShipment = Any.Shipment().WithRoute(longRoute).Generate();
    // CS1503: cannot convert from 'AnyRoute' to 'Route'
    // JD039: longRoute is a generator of Route, and this parameter takes a Route: refine the parameter
    //        through the lambda overload instead, x => x.…, or pass a drawn value with Generate()

Order order = new Order(Any.String().NonEmpty(), 3);
    // CS1503: cannot convert from 'AnyString' to 'string'
    // JD039: Any.String().NonEmpty() is a generator of string, and this parameter takes a string:
    //        pass a drawn value with Generate()
```

## Conforme

Un affinement réutilisé d'un test à l'autre est un `Func` écrit une fois :

```csharp
// Arrange
Func<AnyRoute, AnyRoute> longRoute = r => r.WithDistanceKm(465);
Shipment anyLongShipment = Any.Shipment().WithRoute(longRoute).Generate();

// Act
bool needsRestStop = anyLongShipment.NeedsRestStop;

// Assert
Assert.True(needsRestStop);
```

Là où la méthode ne prend qu'une valeur, tirez-la :

```csharp
string anyName = Any.String().NonEmpty().WithMaxLength(50).Generate();
```

## Ce qui n'est pas signalé

* Un appel qui échoue pour une autre raison : un générateur d'un autre type, un mauvais nombre
  d'arguments. Le message du compilateur se suffit alors à lui-même.
* Un appel pour lequel une surcharge accepte le générateur : cet appel compile.
* Un appel qui compile : passer une lambda, ou une valeur tirée, est le but.

## Pourquoi elle se contente d'expliquer

L'appel ne compile déjà pas : la règle n'ajoute aucune barrière à elle seule, elle met la raison à côté
du `CS1503` que le compilateur lève déjà. Elle lit les candidats que la résolution de surcharge a
rejetés, et n'a besoin d'aucun marqueur sur la méthode : le type de l'argument dit que c'est un
générateur de `T`, et un paramètre candidat dit qu'il prend un `T`.
