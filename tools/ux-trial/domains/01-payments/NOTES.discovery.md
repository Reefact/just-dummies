  `packages/justdummies-xunit.en.md` (first half), then on demand `guides/composition.en.md`, `generators/README.md`, `generators/strings.en.md`

  `--entry-point any` tried once into a scratch folder (`--output`) to see the file; I then wrote the single `AnyEntry.cs` for the eight types by hand, copying its shape.
- Generators completed by hand (all "to verify" sentinels removed):
  - `AnyIban`: value is `IAny<string>` = `Any.Combine(country, bban, (c, bban) => c + Iban.ComputeCheckDigits(c, bban) + bban)`; refining overload deleted; `AnyIban.Custom.cs` adds `InCountry(cc)`.
  - `AnyBic`: `Any.StringMatching("[A-Z]{6}[A-Z0-9]{2}([A-Z0-9]{3})?")` (retyped `AnyString` -> `AnyPattern` as the sentinel said); `AnyBic.Custom.cs` adds `InCountry(cc)`.
  - `AnyRemittanceInformation`: `Any.StringMatching(@"[A-Za-z0-9/\-?:().,'+][A-Za-z0-9/\-?:().,'+ ]{0,139}")` (first character not a space because of the blank guard).
  - `AnyParty`: name `Alpha().WithLengthBetween(1, 70)`; the account/agent tie handled by turning `_agent` into a `Func<Iban, IAny<Bic?>>` and drawing the account first in `Generate()`.
  - `AnyCreditTransfer`: amount = `new AnyMoney().WithCurrency(EUR).WithAmount(a => a.LessThanOrEqualTo(InstantCeiling))` (the instant-cap tie holds whichever priority is drawn);
    date = `Any.DateOnly().Between(2025-01-01, 2035-12-31).As(BusinessCalendar.NextBusinessDayOnOrAfter)` (factory retyped `IAny<DateOnly>`, refining overload deleted); debtor/creditor left as two independent `AnyParty`.
  - `AnyPaymentBatch`: transfers = `new AnyParty().Then(debtor => Any.ListOf(new AnyCreditTransfer().WithDebtor(debtor)).NonEmpty().WithMaxCount(100).DistinctBy(t => t.EndToEndId))`.
  - `AnyFeePolicy`: rates `Between(0m, 0.05m)`, flat fee and threshold `Between(0m, 1000m)`.
  - `AnyMoney` was fully inferred (`guard`) and untouched.
- Tests (9 classes, 120 test methods, 185 cases with theory rows): `IbanTests`, `BicTests`, `MoneyTests`, `RemittanceInformationTests`, `PartyTests`, `BusinessCalendarTests`,
  `FeePolicyTests`, `CreditTransferTests` (construction, refusals in order, instant ceiling at/over, cross-border, whole lifecycle), `PaymentBatchTests` (1/100/101 transfers, single debtor by value, distinct ids, control sum).

## Frictions and surprises, in order
1. `dotnet test --project Tests.Discovery` (the command given in my brief, and the form the project README uses with `--solution`) failed on SDK 10.0.114:
   `MSBUILD : error MSB1001: Unknown switch ... Switches appended by response files: --project`. `dotnet test Tests.Discovery` then failed with
   `Microsoft.Testing.Platform.MSBuild.targets(395,5): error : Testing with VSTest target is no longer supported by Microsoft.Testing.Platform on .NET 10 SDK and later. If you use dotnet test, you should opt-in to the new dotnet test experience`.
   The xUnit adapter page, the getting-started and the template say nothing about it. I added `domains/01-payments/global.json` with `{"test":{"runner":"Microsoft.Testing.Platform"}}` and everything worked. A newcomer on the .NET 10 SDK has to find that elsewhere.
2. First `any generate Iban`: `✗ Iban: this project has not been restored, so its package references cannot be read. Restore it, then run the command again: dotnet restore`. Clear and actionable; I did `dotnet restore` in the test project. (I did not check the exit code of `any` here.)
3. Every scaffolded file is written into the *test project's folder* but in the *domain's namespace* (`namespace Payments.Domain;`) because "Defaults to the target type's own". `--namespace` exists, but the docs recommend running from the test project and say nothing of the consequence: test-side classes (`AnyIban`) live in the production namespace. Harmless here, slightly surprising; I kept it.
4. The recap marked a lot of parameters `to verify, unread guards`, which makes sense, but for `Iban` the only hint was `Validate(value);` (a helper that does not return the value) and the generated body was `Any.String().NotBlank()`. Nothing in the doc says how to generate "a string carrying a computed check", except the Luhn sample in the CLI page ("Draw the body, then derive the check digit"), which I found by scrolling the CLI page: it was exactly the pattern needed (`Any.Combine(country, bban, (c, b) => c + Check(c, b) + b)`). I used the domain's own `Iban.ComputeCheckDigits` in the generator.
5. Replacing the scaffolded `AnyString` by something else is a multi-place surgery. The sentinel text for `Bic` told me exactly what to retype (`AnyString` -> `AnyPattern` in 3 places) and that worked first time. For the `Iban` (an `IAny<string>` from `Combine`) I had to follow the CLI page's "refinement that ends in `.As`" paragraph: type factory/field/ctor `IAny<string>` and delete the refining overload. I deleted the overload; it was a manual edit of four spots per generator (done three times: Iban, CreditTransfer date, PaymentBatch transfers).
6. A tie between two parameters (account country vs agent country in `Party`) has no scaffold support (`ties agent to account` is only a message). The CLI page offers "derive one draw from another inside `Generate()`" — but the scaffolded `_agent` is an `IAny<Bic?>` fixed at construction, so I had to change its type to a `Func<Iban, IAny<Bic?>>` and edit the ctor, three `With…` methods and `Generate()`. It works, but a pinned `WithAgent(lambda)` now must be consistent with the account by hand. No `Then`-style hook is generated.
7. `any` gave me nothing for "two parties with different accounts" in `CreditTransfer` (`ties debtor to creditor`): I relied on the entropy of the IBAN generator (26^2 x 36^11+ values) and left it uncoerced. `DifferentFrom` on a `Party` generator would be useless since `Party` has no equality. I did not find a documented way to draw "a second Party whose Account differs from the first" other than a hand-written `Generate()`.
8. First compile of the tests passed with no analyzer warning at all (no JD030 info either, as the doc predicted for Info level). I wrote a lot without a single diagnostic; I could not tell whether that means I was clean or the analyzers were silent. No hesitation for the user, but also no feedback.
9. Pass-through assertions: `Assert.Same(anyAccount, party.Account)` or `Assert.Equal(anyCurrency, money.Currency)` put an `any` name in the assertion, which the getting-started page calls "not a dummy". I hesitated for a while about tests whose subject is "what I gave is kept". I replaced the Money one by a literal (`Currency.CHF`) and kept the `Same` assertions for objects whose *value* is irrelevant (the identity is what is asserted). The page does not discuss pass-through/round-trip tests.
10. Seeds are printed as signed 32-bit values (`seeded with -1842371520 ... [JustDummies.Xunit.Reproducible(Seed = -1842371520)]`). It is a valid C# literal; just noted it looks odd next to the doc's example `1743029518`.
11. Real failures on first run (6), all my tests meeting the domain: (a) three were *domain defects* (trailing line break accepted or mis-reported, below); (b) two were my wrong expectation on `ParamName`: `ArgumentOutOfRangeException.ThrowIfGreaterThan(text.Length, 140)` reports `"text.Length"`, not `"text"` (CallerArgumentExpression; also `"endToEndId.Length"`); I dropped the `ParamName` assertion; (c) one was my own regex misunderstanding (`DEUTDE1F` is a valid BIC: digits are allowed in the location code). The `[Reproducible]` output (seed, test output) was shown for each failure, as documented.
12. Domain observations (kept as skipped tests or notes, not fixed): the three regex-based guards use `$`, which in .NET also matches before a trailing `\n`:
    `new Bic("DEUTDEFF\n")` is accepted; `new RemittanceInformation("Invoice 42\n")` is accepted (a line break is not in the SEPA set); `new Iban("DE89370400440532013000\n")` passes the format check and then `BigInteger.Parse` throws `FormatException` instead of `ArgumentException`.
    Also: `TransferPriority` is not validated, so `(TransferPriority)99` bypasses the instant ceiling and `FeeFor` treats it as standard (documented in MODEL.md as intended; I did not test it). `Money.ToString()` uses the current culture (`12,50 EUR` under fr-FR); not tested.

## What worked well
- The getting-started page is genuinely enough to write the first test: the "literal vs dummy" argument, the `anyXxx` naming and the Arrange/Act/Assert convention were applied from the first minute, and the "if an `any` reaches your assertion" box changed several of my tests (the calendar tests, the IBAN equality tests).
- `any generate` + the build-stopping `TODO_verify_…` sentinels: the compiler showed me the exact work list, and the comment at each sentinel quoted the guard and told me what to retype for a regex. Nothing slipped through silently: every constraint I forgot would have been a visible error.
- Wherever the scaffolder could read the guard (`Money`, `endToEndId`, `messageId`, FeePolicy flat fee/threshold) the recipe was right as generated, with the domain constant referenced (`Money.MaximumAmount`).
- `Any.Combine`, `.Then(...)`, `.DistinctBy(...)`, `.As(BusinessCalendar.NextBusinessDayOnOrAfter)` composed well; a batch with one debtor and distinct end-to-end ids, built by construction, took five lines.
- Refusals read well in test code: `Any.Enum<Currency>().DifferentFrom(Currency.EUR)`, `Any.Int32().Between(0, 99).DifferentFrom(rightCheck)`, `Any.String().Alpha().WithLength(71)`.
- The generated `With…(value)` / `With…(lambda)` pairs made `Any.CreditTransfer().WithRequestedExecutionDate(date).Generate()` and `Any.Party().WithAccount(a => a.InCountry("FR"))` read exactly like the intent.
- `[assembly: Reproducible]` printed the seed on every failure; 12 repeated runs stayed green.

## Fluency: 4 / 5
The path from README to a green suite was short and mostly guided by the tool's own sentinels and the CLI page, and the composition primitives did what the page promised. Points off for the `dotnet test --project` / .NET 10 MTP opt-in being undocumented where a newcomer looks first, and for the amount of manual surgery needed once a parameter is tied to another (Party agent/account) or the factory's type changes (three generators): the scaffold stops at a message, and the cure is a hand edit of 4-6 places per generator.
