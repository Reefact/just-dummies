Agent: the same model and effort as every session of this trial. Library: JustDummies 1.0.0-uxtrial.1 (packed from main).

  `any generate Bic Iban Money RemittanceInformation Party FeePolicy CreditTransfer PaymentBatch --output Generators --entry-point any`
  (`Currency` and the two enums are covered by `Any.Enum<>()`). It wrote 16 files (generator + `Any.X()` entry point each) and left 12 `to verify` parameters, so the build stopped as designed.
- Completed by hand:
  - `AnyBic`: `Any.StringMatching("[A-Z]{6}[A-Z0-9]{2}([A-Z0-9]{3})?")`, retyped `AnyString` to `AnyPattern` on the four places the doc lists; `AnyBic.Custom.cs` adds `InCountry(cc)`.
  - `AnyIban`: country + `[A-Z0-9]{11,30}` combined, check digits computed with `Iban.ComputeCheckDigits`, so the recipe is `IAny<string>` (field, ctor, `Func<IAny<string>,IAny<string>>`); `AnyIban.Custom.cs` adds `InCountry(cc)`.
  - `AnyRemittanceInformation`: `Any.StringMatching(@"[A-Za-z0-9/?:().,'+-][A-Za-z0-9/?:().,'+ -]{0,139}")` (first char not a space, so never blank), retyped to `AnyPattern`.
  - `AnyParty`: name `Any.String().Alpha().WithLengthBetween(1, 70)`; `Generate()` draws the account first and the agent afterwards in the account's country, unless a test pinned the agent (a `_agentPinned` flag set by `WithAgent(value)` and `WithoutAgent()`).
  - `AnyFeePolicy`: both rates `Between(0m, 0.05m)`.
  - `AnyCreditTransfer`: amount base `new AnyMoney().WithCurrency(Currency.EUR)`; date base `Any.DateOnly().Between(2020, 2035).As(BusinessCalendar.NextBusinessDayOnOrAfter)` (recipe retyped to `IAny<DateOnly>`); `Generate()` draws the priority first and takes the amount from a second recipe kept under `InstantCeiling` when it is `Instant` (`_instantAmount`, fixed by the amount pin, rebuilt by the amount lambda).
  - `AnyPaymentBatch`: transfers recipe is a hand-written `AnyBatchTransfers : IAny<IReadOnlyList<CreditTransfer>>` (one debtor party, 1 to 20 transfers, ids from `Any.ListOf(...).Distinct()`); recipe retyped `IAny<...>`.
- Tests (9 files, 135 methods, 230 cases):
  BicTests, IbanTests, MoneyTests, RemittanceInformationTests, PartyTests, FeePolicyTests, BusinessCalendarTests, CreditTransferTests, PaymentBatchTests. They cover accept/refuse boundaries, the documented check order (via `ParamName`), equality, the fee computation (literal tariff, rounding away from zero), the calendar, the whole status matrix (state x action) and the batch rules. `[assembly: Reproducible]` in `Tests/AssemblyInfo.cs`.
- Result: green with 225 passed and 5 skipped (the 5 domain defects below, each kept as a skipped test with its reason). First green run after fixing my own mistakes, then 14 consecutive further runs, all green (fresh seeds each run).

## Frictions and surprises, in order
1. **`dotnet test --project Tests.Regular` does not work out of the box.** First `dotnet test --project .` (net10 SDK): `MSBUILD : error MSB1001: Unknown switch ... Switch: --project`. After adding nothing but running `dotnet test Tests.Regular`: `Testing with VSTest target is no longer supported by Microsoft.Testing.Platform on .NET 10 SDK and later. If you use dotnet test, you should opt-in to the new dotnet test experience.` The fix is a `global.json` with `{ "test": { "runner": "Microsoft.Testing.Platform" } }`, which I put at W. The xUnit adapter page (the pages I read) says nothing about it, and the library's own README quotes `dotnet test --project ...` as if it worked. A regular user has a global.json by now, but a fresh consumer solution does not. Docs gap in `justdummies-xunit.en.md` (install section).
2. **`any generate` before `dotnet restore`:** `✗ Bic: this project has not been restored, so its package references cannot be read. Restore it, then run the command again: dotnet restore`. Clear message, exit 2, cost one run. Fine, but the doc says to run it from the test project without mentioning the restore.
3. **Eight `to verify` blocks for a payments domain is the normal case, and the tool is honest about it.** The ones I expected (regex in `Bic`, `RemittanceInformation`, `Iban.Validate(value)`) were all flagged, with the guard text quoted and the retype instructions for `AnyPattern`. I followed the "retype in four places" recipe for Bic and Remittance: it worked first time and the compiler guided the leftover spots.
4. **`Iban`/`Party`/`CreditTransfer`/`PaymentBatch` cannot be scaffolded to a usable generator, and nothing in the docs shows the cross-field pattern for a graph of aggregates.** The doc covers "a guard ties two parameters" at the scalar level (OrderedPair, start + duration, derive in `Generate()`), but my real needs were: (a) an agent whose country follows the account's, (b) an amount whose cap depends on the priority, (c) batch transfers sharing one debtor with distinct ids. I used "derive one draw from another inside `Generate()`" for all three. It works, but the doc warns that a `With…` pin then no longer reaches the draw, and that is what bit me (next point). I had to re-implement the pin bookkeeping by hand (`_agentPinned`, `_instantAmount`) in the generated file, which `--force` will wipe.
5. **A pin on one side of a tie makes a test seed-dependent, as the doc says, and I walked into it.** `PaymentBatchTests.The_control_sum_of_a_single_transfer_is_its_amount` pinned `.WithAmount(anyAmount)` (an EUR amount up to 999 999 999.99) and left the priority drawn: in about 40 % of runs `Instant` was drawn and the constructor refused: `System.ArgumentException : An instant transfer is capped at 100000 EUR. (Parameter 'amount')` at `AnyCreditTransfer.Generate()`. The first green run of the suite was a lucky draw; the 12-run loop showed it (6 failures out of 12). The seed in the report replayed it. Nothing wrong with the library here, my generator tie was not pin-aware. Fix: `.WithPriority(TransferPriority.Normal)` in the test. It cost two loops of runs to see, since the failure is a property of the pin, not of the code. Idea: a recap/analyzer hint on `Pin on a tied parameter` is probably impossible, but the doc could add this exact "pin the amount, forgot the priority" example.
6. **Stale incremental build after I moved a folder of test files.** I `cp`-ed `Tests/` aside, un-skipped the five defect tests with `sed` to verify them, then `mv`-ed the backup back: `dotnet test` reported the un-skipped tests failing although the source had the `Skip` attributes again (file mtimes older than the last compile, so MSBuild did not rebuild). `touch`ing the files fixed it. Not a library issue, listed because the failure text looked like a library problem for a minute.
7. **`ArgumentOutOfRangeException.ParamName` is `"endToEndId.Length"` / `"text.Length"`**, not the parameter name (the domain uses `ThrowIfGreaterThan(endToEndId.Length, 35)`). My first assertion `Assert.Equal("endToEndId", refusal.ParamName)` failed. Domain observation, not a library one; I assert the exception type only.
8. **Mistakes of mine, caught instantly by the suite:** a BIC literal with a digit in the bank part, an IBAN literal with an 11-character BBAN that I had counted as 10. Both reported as `failed ... (code: "A1B2C3D4")` with the domain's own message. Fine.
9. **`Any.Decimal().Negative()` / `GreaterThan(Money.MaximumAmount)` with `.WithScale(2)`** worked, but I had to think about whether the unconstrained `Any.Decimal().Negative()` (no scale) is ok for `FeePolicy` (it is: guard fires before anything else). No friction, just a check that the order of the domain guards makes the other constraints moot.
10. **Nothing from the analyzers.** 0 warnings on a clean `dotnet build --no-incremental`. I half-expected JD030 info (`Any.String()` unconstrained) in the scaffold; `Any.String()` rows were all replaced before the first build. I also call `Generate()` inside the `AnyBatchTransfers.Generate()` and `AnyCreditTransfer.Generate()` (chained draws): no diagnostic, consistent with the docs (Generate() is ordinary code there).

### Domain defects the draws and the edge cases revealed (all kept as skipped tests)
- **D1 — a trailing line feed passes three regex validations.** `new Bic("DEUTDEFF\n")` (9 characters, accepted), `new RemittanceInformation("invoice 42\n")` (accepted) and `new Iban("DE89370400440532013000\n")` (passes the format check, then `BigInteger.Parse` throws `FormatException: The value could not be parsed.` instead of `ArgumentException`). Cause: `$` matches before a final `\n`; use `\z` or `RegexOptions` equivalent. Tests: `BicTests.A_code_followed_by_a_line_feed_is_refused`, `RemittanceInformationTests.A_text_followed_by_a_line_feed_is_refused`, `IbanTests.A_value_followed_by_a_line_feed_is_refused_as_an_argument`. Seed-independent (literals).
- **D2 — `Money.ToString()` is culture-dependent.** Under `fr-FR`, `new Money(1234.5m, Currency.EUR).ToString()` is `"1234,50 EUR"` (`{Amount:0.00}` uses the current culture). Test: `MoneyTests.An_amount_is_written_the_same_way_whatever_the_culture_of_the_machine`.
- **D3 — `PaymentBatch` keeps the caller's list.** Adding a transfer of another debtor to the `List<CreditTransfer>` after construction changes `NumberOfTransactions` from 1 to 2 and bypasses the single-debtor, unique-id and 100-transfer checks. Test: `PaymentBatchTests.A_batch_is_not_changed_by_a_later_change_of_the_list_it_was_built_from`. (MODEL.md is silent on copying; I treat it as an invariant leak.)

## What worked well
- The guard table in the CLI page predicted exactly what the tool did: `Money` (`ThrowIfNegativeOrZero`, `ThrowIfGreaterThan(MaximumAmount)`, `decimal.Round(...) != amount` to `.Positive().LessThanOrEqualTo(Money.MaximumAmount).WithScale(2)`) and `CreditTransfer.endToEndId` came out fully inferred and referencing the public constant.
- The "does not compile until you resolve it" design is excellent for a domain full of regexes and helper validations: the build listed exactly the 12 places to look at, and the TODO comment quotes the regex and tells me which four lines to retype.
- `Any.StringMatching` handled `[A-Z0-9]{11,30}`, the optional group of the BIC and the escaped class of the SEPA character set without surprise; `Any.Combine` + `.As(BusinessCalendar.NextBusinessDayOnOrAfter)` gave a valid-by-construction date in two lines.
- `[assembly: Reproducible]` plus the seed message on failure: the control-sum failure came with a replayable seed in the output each time.
- `.Distinct()` on `Any.ListOf` and `Any.Enum<>().DifferentFrom(...)` / `.Except` were exactly what I needed; no reading of source required.
- The `partial` class + `*.Custom.cs` idea (InCountry on Iban/Bic) fits the way I wanted to build cross-border cases (`WithDebtor(d => d.WithAccount(a => a.InCountry("DE")))` reads well).

## Fluency: 4 / 5
The DSL, the scaffolder and the adapter did what I expected and the diagnostics were honest; I lost time only on the environment (the `dotnet test --project` / Microsoft.Testing.Platform opt-in) and on the part the tool deliberately leaves to me: ties between fields of an aggregate graph (agent/account country, priority/amount cap, shared debtor with distinct ids). The doc shows the building blocks for scalar ties but not a worked example for a graph of value objects with `With…` pins, so I rebuilt the pin bookkeeping by hand and then tripped on one pin of my own. Everything else was fast.
