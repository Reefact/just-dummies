## Frictions and surprises, in order
1. `dotnet test --project Tests.Discovery` (the command given in the brief) fails on this machine's SDK 10.0.114: first `MSBUILD : error MSB1001: Unknown switch ... Switch: --project`, and with `dotnet test Tests.Discovery`: `Microsoft.Testing.Platform.MSBuild.targets(395,5): error : Testing with VSTest target is no longer supported by Microsoft.Testing.Platform on .NET 10 SDK and later... opt-in to the new dotnet test experience`. I expected the template project to just run. Fix: a `global.json` with `{ "test": { "runner": "Microsoft.Testing.Platform" } }` at the workspace root. Nothing in the JustDummies docs mentions it (the xUnit page says "xunit.v3 4.0.2 or later" and nothing about the runner), so a newcomer on SDK 10 would hit this before seeing any dummy.
2. First `any generate ...`, before any restore: `✗ PolicyNumber: this project has not been restored, so its package references cannot be read. Restore it, then run the command again: dotnet restore`. Clear and actionable (I did exactly that), but the CLI page's "Requires" section only says the package must be in the project; the restore prerequisite is not written there.
3. `CoveragePeriod`: the recap marked both `start` and `end` `to verify, guard, unread guards` ("ties end to start") and the file contained a strict `Any.OrderedPair` over the whole `DateOnly` range (0001..9999). That honours `end > start` but not `end <= start.AddYears(1)`, so a draw would fail at nearly every run. I understood this from the page ("A direct order is drawn for you ... Every other rule between parameters is marked `to verify`") only after reading it twice: the paired scaffold looks finished, and the TODO line is the only thing saying it is not. I followed the "start and a duration" recipe, but that means discarding the scaffolded `With...` surface and rewriting the file; a later `--force` would erase it (the page says so). Not the tool's fault, but the cost is real: the best-looking part of the scaffold had to be thrown away.
4. `CarPolicy` (claims must be dated inside the period): the recap says `unread guards` for `period` and `claims` and I had to write the tie myself. The page names this case explicitly ("a claim inside a policy period") but none of its four recipes shows how to draw a *collection of children* constrained by a sibling parameter. I used "derive inside `Generate()`", which breaks the `With...` contract the page warns about: I had to add a `_claimsAreDefault` flag, set it in both `WithClaims` overloads, and copy it in the copy constructor. I first forgot the copy constructor line, which would have silently re-dated pinned claims after any later `With...` call; the compiler can't catch that. A documented recipe for "children inside a parent" (probably with `.Then`) would have saved me this.
5. `Claim.responsibility` was flagged `to verify, unread guards` for the `switch` expression whose default arm throws, and the file refused to compile until I deleted the two TODO lines. The scaffolded recipe (`Any.Enum<Responsibility>()`) was already right. The guard table lists `!Enum.IsDefined(p)` as read but not the switch-arm throw; I could not tell from the page that this is a "nothing to add" case other than by thinking it through. Same for `BonusMalus` (`Validate(coefficient);` void helper, I replaced the recipe with `Between(Floor, Ceiling)` which was the point of the mark).
6. Regex guard (`PolicyNumber`): the TODO comment told me exactly what to do ("retype AnyString to AnyPattern here, on the recipe field, in the recipe constructor and in the Func of WithValue"). It took one replace and compiled first time; the only hesitation was whether `Any.StringMatching` understood `\d` and the anchors-free form. The strings page answered it. Note that `WithValue(v => v.DifferentFrom(...))` still works on the retyped `AnyPattern`.
7. My own mistake that the library helped me understand: I expected `Renew().Renew()` of the calendar year 2026 to end on 2028-12-31. It ended on 2028-12-30 (`Next()` keeps the number of days, 365, and 2028 has 366). `MODEL.md` documents `End.AddDays(Days)`, so the domain does what its model says; I changed the test and recorded it as a domain observation below. No library issue.
8. The test output on failure printed `[JustDummies] These arbitrary values were seeded with 2123845064. Reproduce this run with [JustDummies.Xunit.Reproducible(Seed = 2123845064)].`: exactly what the getting-started page promised, and it made the investigation of friction 7 trivial. No friction, noting it because I hesitated about reading the tool's output.
9. Every link on `PROJECT-README.md` / `README.md` pointing outside `docs/` (`doc/handwritten/for-users/...`, `../../../CONTRIBUTING.md`) is dead in the trial layout. Expected, since the trial copies only the user docs, so I just navigated by file name.
10. The getting-started page shows `Any.OrderReference()` (an extension member) in its examples. A newcomer reading it first cannot tell that this needs C# 14 and `--entry-point any`; I only learned it from the CLI page. I used `new AnyCarPolicy()` everywhere, which always works.

## What worked well
- The scaffold got the plain value objects right on the first run (`Deductible` with `.Between(0m, Deductible.Ceiling).WithScale(2)`, `Driver` with `NotBlank()` and `Between(0, 80)`, `Claim` with `NonEmpty()` and `Positive()`), and it referenced my public constants rather than copying numbers.
- Unfinished work is a compile error at the exact line, with the guard quoted and its source line; the "a TODO is not a failure" idea is true in practice.
- Composition: `CarPolicy` reached `new AnyDriver()`, `new AnyDeductible()` and so on on its own, and the `With...(Func<...>)` overloads read very well in tests: `new AnyCarPolicy().WithDriver(d => d.WithYearsLicensed(2)).WithBonusMalus(b => b.WithCoefficient(1.20))` says what the test is about and leaves the rest arbitrary.
- The dummy/assertion discipline from the guides made me keep premium inputs as literals while drawing the policy number, vehicle, level, deductible and claims, which also checks that the premium ignores them.
- `[assembly: Reproducible]` and the seed in the failure output; 15 repeated green runs.
- No analyzer diagnostics at all on the test project, including on the hand-edited generators.

## Domain observations (for the model owners, not library findings)
- `PolicyNumber`: the regex ends with `$`, which .NET also matches before a trailing `\n`, so `"POL-2026-FR123456\n"` is accepted (test skipped: `A_number_followed_by_a_line_feed_is_refused`). `\d` also accepts non-ASCII digits.
- `CarPolicy.Claims` returns the private `List<Claim>` as `IReadOnlyList<Claim>`; `(List<Claim>)policy.Claims` lets a caller bypass `DeclareClaim`'s period check (test skipped: `The_claims_cannot_be_modified_through_the_property`).
- `Renew()` carries the driver over unchanged, so a driver with 2 years licensed stays "young" forever (documented in the model, tested as such).
- `Next()` keeps the number of days, not the calendar year, so a renewed policy drifts (2027 year renews to a period ending 2028-12-30).
- `DeclareClaim` does not refuse a claim id already present (documented, tested as such).
