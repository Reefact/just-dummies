# Regular notes — 05 CAD drawing
Agent: the same model and effort as every session of this trial. Library: JustDummies 1.0.0-uxtrial.1 (packed from main).

## What I did
- Pages read, in order: `PROJECT-README.md`, `guides/getting-started.en.md`, `packages/justdummies-xunit.en.md`, `packages/justdummies-cli.en.md` (the whole "what the last column means", "adjusting a parameter", "when a guard ties two parameters" parts), `guides/composition.en.md`, then `generators/numbers`, `strings`, `enums-and-choices`, `dates-and-times`, `collections` as a reference. Not read: analyzers pages (no diagnostic ever surfaced in `dotnet build`), reproducibility guide (the xUnit page was enough).
- Project `Tests.Regular/Drafting.Tests.Regular.csproj` from the template. I had to add a `global.json` (see friction 1) in the domain folder to run `dotnet test --project`.
- `any` commands: `dotnet restore` (the tool refuses an unrestored project), then one batch
  `any generate PartNumber DrawingReference DrawingScale IsoTolerance Dimension Fit Drawing BomItem --entry-point any`.
  Recap: 8 files + 8 entry points; 6 types written with sentinels (`PartNumber`, `DrawingReference`, `DrawingScale`, `IsoTolerance`, `Fit`, `Drawing`), `BomItem` with a `TODO` (self-referencing), `Dimension` clean.
- Generators completed by hand:
  - `AnyPartNumber`: `Any.StringMatching("P[0-9]{6}(-[A-Z0-9]{2})?")`, retyped `AnyString` -> `AnyPattern` (4 places).
  - `AnyDrawingReference`: number `Any.StringMatching("(MEC|ELE|HYD)-[0-9]{5}")` (AnyPattern retype), revision `Any.Char().OneOf("ABCDEFGHJKLMNPRTUVWY".ToCharArray())`.
  - `AnyDrawingScale`: tie "1 on one side" written in `Generate()` (draw a Boolean, then `n:1` or `1:n`).
  - `AnyIsoTolerance`: zone `Any.String().OneOf("H","JS","h","js")`.
  - `AnyDimension`: nominal `Any.Double().Between(0.001, 19.6)` (valid in mm and inches, 19.6 in = 497.8 mm); tolerance left as scaffolded (`OrNull`).
  - `AnyFit`: hole zone `Except("h","js")`, shaft zone `Except("H","JS")` through nested `WithTolerance(t => t.WithZone(z => ...))`; `Generate()` rewritten so the shaft takes the hole's nominal (converted if the shaft is in inches).
  - `AnyDrawing`: `issuedOn` `Any.DateOnly().Between(Drawing.EarliestIssue, 2100-01-01)`.
  - `AnyBomItem`: `children` default = a fixed empty list (leaf); `part` sentinel removed. A hand-written `BomTrees.AnyTree(depth)` builds bounded trees whose part numbers come from a pool of distinct ones.
- Tests (173 methods, 400 cases, 7 skipped on domain defects): `PartNumberTests` (11), `DrawingReferenceTests` (18), `DrawingScaleTests` (12), `IsoToleranceTests` (14), `StandardToleranceTests` (10, the whole IT6..IT11 table at each range's upper bound and just above it = 156 theory cases), `DimensionTests` (25), `FitTests` (19), `DrawingTests` (33), `BomItemTests` (32). `[assembly: Reproducible]` in `AssemblyInfo.cs`.
- Result: green (393 passed, 7 skipped). Repeated runs: 12 then 60 fresh-seed runs; 1 failure out of the first 12 (my own test, friction 8), none out of the 60 after the fix.
- The 7 skipped tests are domain observations, each run un-skipped to confirm it really fails: `\n` accepted by both regexes (x2), non-ASCII digits in a part number, `FitKind.Interference` unreachable, `Dimensions` exposes the mutable list, int overflow in `TotalQuantityOf`, culture-dependent `Dimension.ToString`.

## Frictions and surprises, in order
1. **`dotnet test --project Tests.Regular` does not work out of the box.** `MSBUILD : error MSB1001: Unknown switch ... Switch: --project`; and `dotnet test Tests.Regular` gives `Testing with VSTest target is no longer supported by Microsoft.Testing.Platform on .NET 10 SDK ... opt-in to the new dotnet test experience`. Fix: a `global.json` with `{ "test": { "runner": "Microsoft.Testing.Platform" } }` above the project. Nothing I read (the xUnit adapter page, the getting-started page) says an xUnit v3 project on .NET 10 needs it. Expected a line in the xUnit page.
2. **`any` needs a restored project, and says so well** (`this project has not been restored ... dotnet restore`). Fine, but the first command I typed in a fresh folder was wasted. Minor.
3. **`Dimension.nominal` scaffolded as `Any.Double().Positive()` with no mark at all**, although `Dimension` refuses a nominal above 500 mm (in `Validate()`, called after the property assignments) and the nominal in inches is converted. The recap row is clean: no `to verify`, not even a hint. `Positive()` draws up to `1e308` one draw in ten, so every test that makes a dimension would fail about once in ten runs, far from the cause. I caught it only because I had read the domain. The docs do say "a helper the tool does not recognise called below the first assignment to state earns no mark", so it is as documented, but it is exactly the silent case that "a TODO is not a failure" argues against; a `void` private method that throws, called from the constructor body, would deserve at least `to verify`. (The doc says a `void` helper called for its effect `Validate(value);` "is marked as before" — here it was not, because it is below the first assignment.)
4. **Two-parameter ties have no help beyond the doc's four forms** (`DrawingScale`: "one of the two terms is 1"; `Fit`: hole and shaft of the same nominal). The tool marks both parameters `to verify ... ties numerator to denominator` and stops the build, correctly. But the way out is to rewrite `Generate()` by hand, which `--force` erases, and then the `With…` pins on the tied parameters no longer behave (`WithNumerator(5)` is ignored half the time on my scale; a pinned shaft on `AnyFit` is overwritten by the hole's nominal). The doc warns about it; in practice I wrote a comment in the file and used literals in tests that care. I'd have liked a `With…`-aware way (an `Any.OneOf` of two generators combined, or a `Then` on the recipe) shown for an "either/or" tie like `1:n | n:1`, the doc's samples are all order/duration/check-digit/difference shapes.
5. **Self-referencing aggregate (`BomItem.children`) is a `TODO` with no sample of the bounded recursion** the comment asks for ("Write one here with a depth bound you choose"). I chose: default = leaf, plus a separate hand-written `BomTrees.AnyTree(depth)` helper. It took the longest of the whole job (distinct part numbers by construction, a pool of 60 sized for the worst tree). A short documented pattern for "a tree dummy with a depth bound" would have saved the time.
6. **Regex retype is mechanical but touches four places** (field, `AnyValid…`, recipe ctor parameter, `Func<…>` of the refining overload). `sed s/AnyString/AnyPattern/` did it; the doc listing those places is accurate. Good, only noting that it is manual.
7. **Refining a nullable parameter works but is easy to forget the semantics of**: `Any.Dimension().WithTolerance(t => t.WithZone(z => z.Except("h","js")))` draws a non-null tolerance; `WithoutTolerance()` gives null. I re-read the doc to be sure (it is stated in "null, sometimes, always or never"). Clear once found.
8. **First repeated-run failure was my own test, and the seed message was clear.** `Revising_a_released_drawing...` failed 1 run in ~12: `MEC-28736 rev Y sheet ... has no revision letter left` followed by `[JustDummies] These arbitrary values were seeded with -1489703168. Reproduce this run with [JustDummies.Xunit.Reproducible(Seed = -1489703168)]`. The draw hit the one revision letter (`Y`) that `Revise()` cannot go past: the test was about revising, so the revision was not a dummy. I constrained it (`WithRevision(letter => letter.Except('Y'))`) in a helper. Nothing to blame on the library; the message made the diagnosis a one-minute job.
9. **Domain observations the draws and the table-driven tests revealed** (details in the findings): regex `$` accepts a trailing `\n`; `\d` accepts Unicode digits; `FitKind.Interference` is unreachable with H/JS/h/js; `Dimensions` leaks the mutable `List<Dimension>`; unchecked `int` overflow in the BOM totals; `Dimension.ToString` is culture-dependent. Skipped with `Skip = "domain defect: …"`; the seed is irrelevant for the deterministic ones, I said so in the skip text.
10. **`Any.Char()` has no family or `OneOf(string)`**: `Any.Char().OneOf(char[])` is fine, I had to look up the signature in the numbers/strings pages (chars are only covered under "Strings and characters" briefly). Minor docs gap: a one-line sample for `Any.Char().OneOf(...)`.
11. **No analyzer diagnostic appeared in any build** (0 warnings every time). Either my code was clean or the Info-level ones (JD030, JD031...) are hidden by default as documented; I did not raise the severity.

## What worked well
- The batch `any generate A B C ...` with `--entry-point any` gave a coherent set of files in one go; the recap tells which parameters are safe (`guard`, constants such as `BomItem.MaximumQuantity` and `IsoTolerance.FinestGrade` were referenced by name, nice) and which need a decision.
- The build-breaking `TODO_verify_…` sentinel is a good work list; each comment named the guard and its line.
- `Between`/`Except`/`OneOf`, `StringMatching` for both formats, `WithX(lambda)` composing through nested generators (`WithTolerance(t => t.WithZone(...))`), and the `Any.Dimension().WithNominal(…).WithUnit(…)` pins all read very naturally in the Arrange step.
- `[assembly: Reproducible]` plus the seed printed only on failure: exactly what I needed when my one drawn-value failure occurred.
- Constraint conflicts and impossible requests never surfaced as library errors during the whole job, which says the generated base was sound once edited.

## Fluency: 4 / 5
The DSL and the xUnit adapter are second nature: 173 test methods came out quickly and the suite was green on the first run, and the only repeated-run failure was my own over-broad dummy, diagnosed from the printed seed. What cost real time was the domain's shape rather than the DSL: the unreadable `Dimension` guard (silent, friction 3), the two ties (friction 4), the recursive BOM (friction 5), and getting `dotnet test` to run at all (friction 1). Each is documented or explainable, but together they were the slowest part of the day.
