## Frictions and surprises, in order
1. **`dotnet test --project Tests.Expert` does not work as given.** Exact output (SDK 10.0.114): `MSBUILD : error MSB1001: Unknown switch ... --project .` — and `dotnet test Tests.Expert` gives `error : Testing with VSTest target is no longer supported by Microsoft.Testing.Platform on .NET 10 SDK and later. If you use dotnet test, you should opt-in to the new dotnet test experience.` (xunit.v3 4.0.2 brings MTP). I expected the documented command to run. I added a `global.json` in the domain folder with `{ "test": { "runner": "Microsoft.Testing.Platform" } }`; then `dotnet test --project Tests.Expert` works. Neither the xUnit adapter page nor getting-started mentions it; a new user on .NET 10 hits this before any JustDummies line.
2. **The scaffolder's first call is a wall of `to verify`, and the recap does not say which are domain-semantic and which are only regex.** `Sscc`, `Ean13`, `BinLocation`, `PalletReceipt` stop the build (by design, and the build error names the line, which I appreciated). But for `Ean13` the sentinel says only `unread guard at Ean13.cs, line 7: Validate(code);` and for `Sscc` `...; and 1 more`: the check-digit rule is invisible, since the guard that matters sits in `Gs1.HasValidCheckDigit` two calls away. I had to read the domain to know a check digit was required. Expected (or acceptable): a hint such as "a helper of another type is called with this parameter". Did: wrote the generator from the domain source.
3. **Retyping on `.As(...)` replacement is mechanical but error-prone to do by hand.** For `Sscc`/`Ean13` I had to change `AnyString` to `IAny<string>` in four places and rewrite the XML doc remark (`Func&lt;AnyString, AnyString&gt;`); a naive search-and-replace of `AnyString` to `IAny<string>` produced `Func&lt;IAny<string>, ...` in the doc comment (unescaped `<`), which I fixed by hand. The CLI page describes the edit well; a `--replace`-style helper or the tool offering the retyped skeleton when it recognises a checksum/regex guard would remove the busywork. (`AnyPattern` for the regex case: same four places.)
4. **A refining `With…(Func<IAny<string>, IAny<string>>)` is nearly useless after retyping.** `Any.Sscc().WithValue(v => v.DifferentFrom(first.Value))` compiles (`DifferentFrom` exists on any `IAny<T>`) and works, but it is the only thing an `IAny<string>` lambda can do; the other string constraints (`StartingWith`, length) are gone and, more importantly, a check-digit-bearing generator accepts `v => v.DifferentFrom(...)` while `v => v.OneOf("garbage")` would hand the constructor a value it refuses. The docs say so ("nothing for a lambda to refine"); I mention it because the retype makes the pin and the lambda behave very differently from the other generators of the same family, and a reader of the test sees no difference.
5. **JD036 on the scaffolder's own output.** Raising the JD rules to warning (`dotnet_diagnostic.JDxxx.severity = warning`) reports three `JD036: This floating-point dummy declares no range: one draw in ten spans the whole type` on lines scaffolded by the tool: `AnyTemperatureRange.cs(33,16)` (`Any.Decimal().GreaterThanOrEqualTo(-40m)`), `(37,16)` (`LessThanOrEqualTo(40m)`) and `AnyReceiptLine.cs(63,16)` (`Any.Decimal().Positive()`). The temperature ones are false positives in effect: the two recipes are fed to `Any.OrderedPair(..., strict: true)`, so each end is bounded by the other and the `[-40, 40]` domain holds. The unit-weight one is a true positive, and it matters (see 9). Expected: no JD036 on a recipe that the tool itself tied in an ordered pair. It is Info by default so the build is silent, which is why I only found it by raising the severity.
6. **The recap hides the `OrderedPair`.** `any generate TemperatureRange` printed `minCelsius ... Any.Decimal().GreaterThanOrEqualTo(-40m) guard` and `maxCelsius ... LessThanOrEqualTo(40m) guard`, nothing about the `minCelsius >= maxCelsius` guard being turned into `Any.OrderedPair(..., strict: true)`. The file is right and the CLI page documents it, but from the recap alone I assumed the tie was not handled and went to read the file to check. A third column word (`paired`) would have saved the check.
7. **`x.Equals(null)` makes the compiler decide `x` may be null afterwards** (`CS8602` on the next line using the drawn object, `SsccTests` first draft). Not a JustDummies issue; I reordered the two assertions. Recorded because it appears in any "is not equal to null" test written against a drawn value.
8. **`A_value_with_a_trailing_line_feed_is_not_an_sscc` passes for the wrong reason.** The domain's `^[0-9]{18}$` lets `"…\n"` through the pattern; the SSCC is only refused because the check digit then reads `'\n' - '0'`. Fine here, and a good example of why I derive the malformed input from a drawn *valid* SSCC. The same flaw is exposed, with no safety net, by `BinLocation.Parse("A-12-03\n")` and `SupplierCode "SUP-00042\n"` (domain findings below).
9. **A default draw of `ReceiptLine` throws `OverflowException` when its weight is read, about 9 % of the time.** Probe: 3000 `Any.ReceiptLine().Generate()` then `.WeightKg`: 273 overflows. Cause: the scaffolded `Any.Decimal().Positive()` (JD036 above) reaches `decimal.MaxValue` one draw in ten (documented ADR behaviour), and the domain has no upper bound on `unitWeightKg`. Per the brief this is the draw revealing a domain gap, not flakiness; my weight and inspection tests pin the unit weight as a literal because the weight is exactly what they are about, so the suite is stable. I kept `Every_line_the_constructor_accepts_can_report_its_weight` as a skipped test.
10. **No friction from `[Reproducible]` itself.** I confirmed the seed report on a deliberately failing probe (`[JustDummies] These arbitrary values were seeded with -880703961. Reproduce this run with [JustDummies.Xunit.Reproducible(Seed = -880703961)].`), under MTP and on a test that failed from an `Assert.Fail`. Note: the seed is printed under `Standard output` below the stack trace, easy to miss in the terminal summary.

## What worked well
- The scaffold-then-own model is right for this domain: the object graph (`PalletReceipt` -> `ReceiptLine` -> `Ean13`/`Quantity`/`LotNumber`) came out composed through `new AnyEan13()` etc. with nothing to write, and `Any.PalletReceipt().WithReceivedAt(...).WithLines(...)` reads as the arrange step I would have written by hand.
- `WithX(literal)` as the visible mark of "this value is the point": in `A_pallet_is_overweight_only_when...` the line is built from `Line(100, 100, 11.5m, ...)` and the shelf life is `AmpleShelfLife().Generate()`, so the one thing that varies in the theory (the tare) is the only literal that moves.
- Pinning one end of the scaffolded `OrderedPair` bounds the other: `Any.TemperatureRange().WithMaxCelsius(-18m)` gave me "any minimum below -18" for the zone theory with no extra code.
- Pinning an *invalid* value through the generator (`Any.BinLocation().WithRack(0).Generate()`) means a refusal test states only the one invalid argument; the other two are dummies. `Any.OrderedPair(..., strict: true)` for "minimum above maximum" is exactly the tool for the inverted-range test.
- The build error for an unresolved `TODO` is excellent (names the file, the line, and the guard).
- `Any.Char().Numeric().Except(c)` to turn a valid check digit into a wrong one is a clean idiom; `Any.String().Alpha().WithLength(20)` for "the content is arbitrary, the length is the point".
- Replay is trustworthy: 43 green runs, and the one failing probe printed a seed in the documented shape.

## Fluency: 4 / 5
The library itself was fluent: the vocabulary composed without surprises, the docs answered every question I had (the CLI page is thorough), and not one test needed a workaround for a library behaviour. Points were lost on the edges: the `dotnet test --project` setup under .NET 10 (not a JustDummies page, but the first thing a new user meets), the busywork of retyping `AnyString` to `IAny<string>`/`AnyPattern` by hand after a checksum/regex `TODO`, a recap that does not show the ordered-pair tie it made, and JD036 firing (when raised) on lines the scaffolder itself wrote.
