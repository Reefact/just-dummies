## Frictions and surprises, in order
1. **`dotnet test --project Tests.Expert` does not run on the .NET 10 SDK as given.** Output: `MSBUILD : error MSB1001: Unknown switch. … --project Tests.Expert`; the fallback `dotnet test Tests.Expert` gives `Testing with VSTest target is no longer supported by Microsoft.Testing.Platform on .NET 10 SDK and later. If you use dotnet test, you should opt-in to the new dotnet test experience`. Nothing in the docs mentions it (the xunit page tells how to install `xunit.v3`, not how to run it). I added a `global.json` with `"test": { "runner": "Microsoft.Testing.Platform" }` at the workspace root; then `--project` worked. A consumer following the docs hits a wall before the first test.
2. **`any generate` before a restore**: `✗ Nir: this project has not been restored, so its package references cannot be read. Restore it, then run the command again: dotnet restore`. Clear and actionable, but a first-time user has just created the csproj; one line in the CLI page ("restore first") would save the detour. Exit code 2.
3. **The recap is excellent where it can read, and says exactly what it could not**: `nir: unread guard at Patient.cs, line 15: if (birthDate.Year % 100 != nir.BirthYearTwoDigits …) { ... — ties birthDate to nir`. I knew in ten seconds which four files needed me. The `to verify` sentinels (`TODO_verify_the_generator_for_value`) blocked the build as promised, and the retype recipe `AnyString` to `AnyPattern` (four places) was accurate for Molecule.
4. **A check digit does not fit the scaffolded shape at all.** For `Nir(string value)` the file is one `IAny<string>` field, one `AnyString` recipe and `WithValue(Func<AnyString, AnyString>)`. The doc section "Draw the body, then derive the check digit" gives the idea (`Any.StringMatching(...).As(body => body + key)`) but then `AnyNir` has no way to say "male", "born in May 85", "Corsican", which is exactly what Patient and the tests need. I rewrote the whole file with one field per component and domain verbs (`OfSex`, `BornIn`, `InDepartment`). Fine, the file is mine, but `--force` would destroy it and the doc does not say that a composed value object usually ends up hand-written.
5. **I fell into the documented trap "a lambda after a pin takes the pin's place".** In `AnyPrescriptionLine.Generate()` I wrote `_dosageRecipe.WithUnit(u => u.Except(UnitsRefusedWith(route)))` to make the unit suit the route. A test of mine, `Any.PrescriptionLine().WithDosage(d => d.WithUnit(DoseUnit.Tablet))`, then silently got non-tablet doses with non-oral routes, and my sanity test failed with 280 lines of `Assert.True() Failure` (seed -1522562456 reported, replayable). The pinned unit inside a nested generator was overridden by my own lambda. The CLI page does warn ("a lambda written after it starts from the recipe the pin left"), but one reads it as a rule about the test's call site, not about the generator author's own `Generate()`. I redrew the dosage first and chose the route after it; for a pinned route I redraw the dosage up to 100 times. Cost: 20 minutes.
6. **There is no supported way to ask "is this parameter pinned?" inside `Generate()`.** Every tie I had to write (unit/route, issue date/patient, birth date/NIR) needs to know which side the test fixed, because the fixed side must drive the other. The doc ("When a guard ties two parameters") says "Pin both, or write the tie in `Generate()`" and shows ties between two draws, never a pin on one side. I used `!ReferenceEquals(_dosage, _dosageRecipe)`, which works because a pin replaces `_dosage` and a lambda resets it to the recipe, but it leans on the generated file's private structure. A documented idiom (or a scaffolded `bool _xPinned`) would remove the guess.
7. **Info-level analyzers are invisible, so I forced them on.** The docs say Info "never prints in dotnet build". I added a throwaway `.editorconfig` with `dotnet_diagnostic.JD001..JD038.severity = warning` and got 5 `JD030` (string dummy declares no length, on my `Any.String().NotBlank()` names in tests) and 1 `JD036` (`Any.Decimal().Negative()` "floating-point dummy declares no range"). Useful, and I fixed all six (`WithMaxLength(60)`, `GreaterThanOrEqualTo(-1_000_000m)`), but a developer would not see them without that trick. `JD036` says "floating-point" for a `decimal`, a small wording miss.
8. **The scaffolder itself triggers JD030.** It writes `Any.String().NotBlank()` for names (guard `IsNullOrWhiteSpace`), which JD030 flags; documented as by design, but the first build of a fresh scaffold is "clean" only because Info is silent.
9. **`TreatmentDuration(int days) { Validate(days); }`**: a private static `void` helper with plain `days < 1 || days > MaxDays` guards is `to verify` (`unread guard … Validate(days);`), so the scaffold is `Any.Int32()` plus a build stop. Documented ("a `void` helper called for its effect is marked"), and the fix was one line, but this is the most common shape of a guard extracted for reuse and the constants are all public.
10. **xUnit side, not the library:** `InlineData` cannot carry a `decimal`, so Dosage cases moved to `TheoryData<decimal, …>`. Mentioning it because every money/dose test hits it and `JustDummies.Xunit` is the natural place for a hint.

## What worked well
* The seed report. The only failure I produced printed `[JustDummies] These arbitrary values were seeded with -1522562456. Reproduce this run with [JustDummies.Xunit.Reproducible(Seed = -1522562456)].` in the test output, no wrapping needed with the assembly-level attribute.
* The bounds compose as promised: `Any.DateOnly().Between(1900-01-01, 2030-12-31)` then `.AfterOrEqualTo(patient.BirthDate)` narrows instead of conflicting; `WithPatient(p => …)` / `WithBirthDate(b => b.BeforeOrEqualTo(d))` read well; `Except` accumulates over a test's own refinement.
* `Any.StringMatching("[0-9]{11}")`, `"[a-z][a-z -]{0,79}"`, `"[0-9]{2}|2[AB]"` covered every format of the domain, no refused construct.
* `DifferentFrom` on a scaffolded `IAny<Nir>` (equality by value) and `.WithName(n => n.DifferentFrom(...))` on a pattern: two distinct values in one line.
* `Whitespaces().WithMaxLength(10)` as "any blank string", empty included: found nothing, but it is the right dummy for `IsNullOrWhiteSpace` guards.
* The generated `With…` pair (pin / lambda) read naturally at call sites: `Any.Patient().WithBirthDate(Dates.On("2000-06-15"))` keeps the NIR consistent without the test saying so.
* `any --entry-point any` (C# 14 extension on net10) gave `Any.Nir()`, `Any.Prescription()` with no friction.

## Fluency: 4 / 5
The library did what the docs said every time, and the tests read as I wanted: literals only where the assertion is about them (dates, NIR keys, amounts), dummies for everything the code must merely accept, 24 green runs on fresh seeds. What cost me was the edge of the scaffolder rather than the DSL: three of the four non-trivial generators (check digit, birth date tied to NIR, unit tied to route) ended up essentially hand-written, I had to discover the pin-detection idiom myself and lost time to the "lambda replaces the pin" trap inside my own `Generate()`, and the test runner command from the brief does not work on the .NET 10 SDK without an undocumented `global.json` opt-in.
