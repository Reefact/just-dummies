# Regular notes — 08 patient record
Agent: the same model and effort as every session of this trial. Library: JustDummies 1.0.0-uxtrial.1 (packed from main).

## What I did
- Read, in order: `MODEL.md`, the `Domain/` sources, `docs/PROJECT-README.md` (skimmed), `guides/getting-started`, `packages/justdummies-xunit`, `packages/justdummies-cli` (what the last column means, guard table, "When a guard ties two parameters", "Adjusting a parameter", "When the replacement is another kind of generator"), `guides/composition`, and the dates, numbers, strings and enums generator pages.
- `dotnet restore`, then `any generate Nir Dosage Molecule TreatmentDuration Patient PrescriptionLine Prescription --entry-point any` (first attempt, before restore, said "this project has not been restored"). Result: 7 generators + 7 `Any.X()` entry points; Nir, Molecule, TreatmentDuration, Patient, PrescriptionLine and Prescription were `to verify` and did not compile until completed.
- Generators completed by hand:
  - `AnyNir`: body from `Any.StringMatching(...)` then `.As(body => body + key)` (retyped the recipe to `IAny<string>`); a neighbouring `AnyNir.Birth.cs` adds `BornIn(year, month)` and `OfSex(sex)`; `NirKeys` is an independent key computation so the generator does not lean on `Nir.ComputeKey`.
  - `AnyMolecule`: `Any.StringMatching("[a-z][a-z -]{0,79}")`, retyped to `AnyPattern`. `AnyTreatmentDuration`: `Between(1, MaxDays)`.
  - `AnyPatient`, `AnyPrescription`, `AnyPrescriptionLine`: the scaffolded `Generate()` replaced by a hand-written one that draws the tied parameters together (NIR <-> birth date, patient <-> issue date, dose unit <-> route), with a "pinned" field per tied parameter so that pinning one side makes the other follow. Prescriber RPPS: `Any.StringMatching("[0-9]{11}")`.
- Tests (127 methods, 182 cases with the theory rows): `NirTests` (17), `DosageTests` (12), `MoleculeTests` (11), `TreatmentDurationTests` (8), `PatientTests` (21), `PrescriptionLineTests` (12), `PrescriptionTests` (46). They cover the key computation (including key 97 and 1, Corsica 2A/2B), every refusal and its exception type, the order of the checks in `Prescription` (via `ParamName`), boundaries (365 days, 10 lines, 80 characters, 10 000 mg, three decimals), ages and minority around birthdays and a leap-day birth, the three-month dispensing window with month-end clamping, treatment end, parental consent, and the whole life cycle (Sign / Dispense / Cancel from each state, state unchanged after a refusal). `[assembly: Reproducible]` on the project.
- Result: green, 178 passed + 4 skipped (domain defects, below). After the final build: 15 consecutive runs green (fresh seeds each time).

## Frictions and surprises, in order
1. `dotnet test --project Tests.Regular` (the command of the brief) fails on this SDK: `MSBUILD : error MSB1001: Unknown switch ... Switch: --project`; with a plain `dotnet test Tests.Regular`: `error : Testing with VSTest target is no longer supported by Microsoft.Testing.Platform on .NET 10 SDK and later ... opt-in to the new dotnet test experience`. Neither the docs nor the xunit page mention it; I added `W/global.json` with `{"test":{"runner":"Microsoft.Testing.Platform"}}`, after which `--project` works. The PROJECT-README only says the repo pins its SDK in `global.json`. A consumer on .NET 10 with xunit.v3 hits this on day one.
2. `any generate Nir ...` before restoring: `✗ Nir: this project has not been restored, so its package references cannot be read. Restore it, then run the command again: dotnet restore`. Clear and actionable; I just lost one run.
3. Every tied rule is hand work, and it is a lot of it here. The three ties of this domain (NIR carries birth year+month; issue date >= birth date; Tablet/Puff need compatible route) each marked two parameters `to verify`, as documented. The documented answers ("derive inside `Generate()`") work, but then the generated `With…(value)` pins no longer reach the draw, so I had to add my own `_fixedX` fields in the generated file and branch on them (4 cases for Patient). I would have liked a seam for that: `Generate()` lives in the generated file, so `any generate --force` would erase all of it; the partial class cannot override it. Nothing in the docs gives a pattern for "pin one side, the other follows" for a scaffolded aggregate (only the OrderedPair case).
4. The check-digit case is documented ("Draw the body, then derive the check digit", `.As(body => body + ...)`), which made the NIR easy. But the recap line for Nir (`Any.String()  to verify, unread guards`) points at the regex advice (retype to `AnyPattern`), which would not have been enough here: the key is a second guard ("and 1 more"). It does say "and 1 more", so I read the constructor, but the TODO text itself does not mention the key.
5. Mistake of mine caught by the tools: `Any.OneOf(years)` with a `List<int>` gave `warning JD013: Use Any.ElementOf to draw from the collection's elements: passed to OneOf it binds T to System.Collections.Generic.List<int> ...` plus `CS1503`. The analyzer message told me the fix directly.
6. `Any.Nir().DifferentFrom(other)` on a scaffolded generator (an `IAny<Nir>`) works through the redraw route; fine, but no analyzer/doc hint when a hand-made `As` generator's domain is large enough that it will practically never loop.
7. `TreatmentDuration`: `Validate(days)` (a private static void helper holding `days < 1 || days > MaxDays`) is marked `to verify` with `Any.Int32()`. Documented ("a void helper called for its effect is marked as before"), but this is the most common way to factor a guard, and the scaffolded `Any.Int32()` would have drawn out-of-range values most of the time. The build stops there, so it is safe; I just wrote `Between(1, TreatmentDuration.MaxDays)` by hand.
8. `Molecule` row reads `Any.String().NotBlank().WithMaxLength(80)  to verify, guard, unread guards`: a recipe that is kept and still blocks the build, as documented; but the regex then replaces it entirely, so the two inferred guards are discarded. Not a defect, just redundant work.
9. Wanting "a minor / an adult" patients, I wrote `Any.Patient().WithBirthDate(new DateOnly(2010, 6, 15))`. Because I had made the NIR follow the birth date, this reads well; without my hand-written tie, `WithBirthDate` alone would have thrown on most draws. That is a consequence of friction 3, not a separate issue.
10. The reproducibility message on failure shows up only in the failing test's "Standard output" block, once per failure: `[JustDummies] These arbitrary values were seeded with 436635632. Reproduce this run with [JustDummies.Xunit.Reproducible(Seed = 436635632)].` Good. (It appeared for my three literal-input domain-defect tests as well, which is noise: no draw reaches those assertions.)
11. Domain findings made by tests (not library issues), see the skipped tests: a trailing line feed passes `Nir`, `Molecule` and the RPPS pattern (`$` matches before a final `\n`); the RPPS `\d` accepts non-ASCII digits (probed: Arabic-Indic digits accepted); `AgeOn` makes a 29 February birth turn a year older on 28 February in a common year (`IsMinorOn(2022-02-28)` is false for a 2004-02-29 birth). I kept the last one as a characterisation test; it follows the written formula but is arguably a business question.

## What worked well
- The scaffold + entry points (`Any.Patient()`, `Any.PrescriptionLine()`) made the tests read as the intent: only the value a test is about is a literal (`2.5m`, `10` days, `2024-11-30`), the rest is `anyXxx`.
- `to verify` stopping the build at the exact line was the right call for this domain: every default that would have been wrong (NIR, dose/route, issue date) was flagged, none slipped through silently.
- The lambda refinement `WithDosage(d => d.WithAmount(2.5m).WithTimesPerDay(3))` and `WithRoute(r => r.DifferentFrom(...))` were exactly what the tests needed; `Any.ElementOf`, `Any.Enum().Except(...)`, `DifferentFrom` on a scaffolded generator, `Any.Decimal().Negative().WithScale(3)` all behaved as documented.
- `[assembly: Reproducible]` plus 15 runs with fresh seeds: no draw-dependent failure at all; the only failures were literal-input domain defects.
- Analyzer feedback (JD013) was precise and immediate.

## Fluency: 4 / 5
Day-to-day use was smooth: scaffolding, entry points, the DSL and the xUnit adapter did what the docs said, and the diagnostics were useful. Points lost for the first-run `dotnet test --project` / MTP opt-in wall on .NET 10 (a consumer-side blocker with no documentation), and for the amount of hand-written, `--force`-fragile code needed to make three rules between parameters hold while keeping the `With…` pins meaningful, which is the real cost of this domain.
