Agent: the same model and effort as every session of this trial. Library: JustDummies 1.0.0-uxtrial.1 (packed from main).

Scaffold result: 3 types came out clean (`MeasurementUnit`, `DilutionFactor`, `SpecimenQuality`), 7 were marked `to verify` (`SampleId`, `AnalyteCode`, `Measurement`, `ReferenceRange`, `Specimen`, `LabResult`, `LabReport`).
Generators completed by hand:
- `AnySampleId`, `AnalyteCode`: the guard was a helper `Validate(value)` / a `Regex`; I replaced `Any.String()` with `Any.StringMatching("S[0-9]{10}")` / `"[0-9]{1,5}-[0-9]"` and retyped `AnyString` to `AnyPattern` (a global replace), deleted the sentinel lines.
- `AnyMeasurement`: base `Any.Double().GreaterThanOrEqualTo(0d)` (the `switch` expression with `< 0 => throw` was not read).
- `AnyReferenceRange`: the scaffold had already paired `lower`/`upper` with a strict `OrderedPair` and read `lower >= 0`; I only had to tie the critical limits: four bands that meet but never cross (`criticalLow` -50..0, `lower` 0..500, `upper` 500..1000, `criticalHigh` 1000..2000) so that `criticalLow <= lower < upper <= criticalHigh` holds by construction.
- `AnySpecimen`: rewritten by hand (see friction 5): `collectedAt` drawn in 2020..2030, `receivedAt = collectedAt + transit` with transit in `[0, 72 h]`.
- `AnyLabResult`: rewritten by hand (friction 6): the measurement takes the range's unit, `reportedAt = specimen.ReceivedAt + delay`.
- `AnyLabReport`: rewritten by hand: the sample id is drawn first, the analytes are drawn as a distinct list, every result is built for that sample id.
- `AnyMeasurementUnit`, `AnyDilutionFactor`, `AnySpecimenQuality`: used as scaffolded.

Tests written (5 files, 129 methods, 205 cases with theory rows, 3 skipped on purpose):

## Frictions and surprises, in order
1. `dotnet test --project Tests.Discovery` does not work out of the box on the .NET 10 SDK. First `MSBUILD : error MSB1001: Unknown switch ... Switch: --project`; then, in the project folder, plain `dotnet test`: `Microsoft.Testing.Platform.MSBuild.targets(395,5): error : Testing with VSTest target is no longer supported by Microsoft.Testing.Platform on .NET 10 SDK and later. If you use dotnet test, you should opt-in to the new dotnet test experience.` The fix is a `global.json` with `{ "test": { "runner": "Microsoft.Testing.Platform" } }`. No page of the JustDummies docs mentions it, and the xUnit package page only says "xunit.v3 4.0.2 or later". A newcomer on .NET 10 hits this before running one test. I added the global.json in the workspace root.
2. `any generate` before any restore: `✗ SampleId: this project has not been restored, so its package references cannot be read. Restore it, then run the command again: dotnet restore`, exit 2. The message is clear and tells the fix; the docs' install steps do not say a restore is needed first. Minor.
3. The scaffold of ten types in one command was impressive and the work list is exact: after I had completed the first four types, `dotnet build` stopped with exactly six `CS0103: The name 'TODO_verify_the_generator_for_sampleId' does not exist` (one per marked parameter), at the right lines. But the compiler message alone does not say why; the reason is in the `// TODO(any): verify against LabReport.cs, line 14: ...` comment above and in the recap printed at generation time, which scrolls away on a ten-type run (about 120 lines). I read the generated files to recover it. A later `any generate X --dry-run`/`--format json` would also have given it, but I only learned that from the docs after the fact. Low.
4. `Measurement` was marked `to verify, unread guards` for `Value = value switch { double.NaN => throw ..., < 0 => throw ... }`. The docs list the shapes read (throwing `if`, throw helpers); a `switch` expression with throw arms is not among them and is not mentioned as unread either, so I only knew to bound the base after reading the domain. Expected-but-not-promised, so docs only. Related: the proposed base was a bare `Any.Double()` that draws negatives, so the unedited file would have thrown on most runs (it is a `to verify`, so it did not compile anyway; fine).
5. `Specimen` (`receivedAt - collectedAt > StabilityWindow`, "ties receivedAt to collectedAt") was the first real design decision. The scaffold had paired `collectedAt`/`receivedAt` with `Any.OrderedPair` (non-strict, correct for `receivedAt < collectedAt`) but over `Any.DateTimeOffset()` unbounded, i.e. years 0001..9999, so a pair almost never fits in 72 hours. The docs offer four forms (start + duration, derive inside `Generate()`, ...) and warn that "`WithEnd(…)` sets a field your `Generate()` does not read". Following "derive in `Generate()`" meant that the whole pair machinery of the file (the `AnyOrderedPair` field, two pin fields, a private `CollectedAtAndReceivedAt()`, four `With…` overloads wired to it) became either dead or wrong, so I rewrote the 250-line file into 130 lines by hand rather than editing the recipe. Expectation: one line to change in the base. What I would have liked: a documented minimal edit that keeps the generated `With…` consistent, or a scaffold that proposes the start+duration shape when it sees `b - a > constant`.
6. `LabResult` and `LabReport`: four parameters of `LabResult` and both of `LabReport` are `to verify`, for rules that cross objects (`measurement.Unit.Equals(range.Unit)`, `reportedAt < specimen.ReceivedAt`, `result.Specimen.Id.Equals(sampleId)`, analytes distinct). The docs' "When a guard ties two parameters" section covers two parameters of one type (dates, check digit, differing strings). A tie that goes through a *property of a composed generated value* (the unit inside the measurement vs inside the range; the specimen id inside each result vs the report's id) has no sample. I solved it by deriving inside `Generate()` (draw the range, then `_measurementRecipe.WithUnit(range.Unit)`; build each result with `.WithSpecimen(s => s.WithId(sampleId))`; draw analytes as `Any.ListOf(new AnyAnalyteCode()).WithCount(n).Distinct()`), which worked first time because the generated `With…` methods compose well, but I had to track "was this parameter pinned?" with my own fields (`_measurementPin`, `_reportedAtPin`) to avoid overriding a pin. A documented pattern for that would save time.
7. Small trap I met in my own tests, not the library: after `sed`-removing and restoring `Skip =` on two test files, `dotnet build` reported up to date and `--no-build` ran the stale (un-skipped) binary: 15 consecutive "red" runs which were my mistake (file mtime restored by `mv`). The seed was printed each time, which at least made it obvious the failures were deterministic domain facts, not draws.
8. The trailing-newline and Unicode-digit facts about `AnalyteCode` came from thinking about `Regex` anchors, not from JustDummies; but `Any.AnalyteCode()` (which draws `[0-9]{1,5}-[0-9]`) can of course never exhibit them. Nothing wrong with the library, just a reminder that a generator draws valid values, not the awkward valid-by-regex ones; they are literals in the tests.
9. Documentation layout: links in the docs bundle point to `doc/handwritten/for-users/...` and `../../for-maintainers/adr/...` (ADR links in nearly every page, even in the CLI page's "TODO is not a failure" paragraph). In my copy of the docs those targets do not exist (the pages sit in `docs/guides`, `docs/packages`...), so every cross-link and every ADR reference is dead. Possibly an artefact of how the trial copied the docs, not of the repository. Low.
10. The CLI page is 920 lines and everything a newcomer needs after a `to verify` (retyping to `AnyPattern`, the ties) is in the second half; "Getting started" ends with the scaffolder as one row of a "Where to go next" table, so on my first run I had to find it from the project README (which does show `any generate Order` and the recap) and then read the whole page. It was well written and I did not get lost, but the path "scaffold, resolve the six build errors" deserves a short step-by-step page.
11. No analyzer diagnostic reached me at all (default severity Info for JD030 etc. does not print in `dotnet build`, as the docs say). Neither good nor bad; I never saw the safety net work.

## What worked well
- `any generate A B C ... --entry-point any` on ten types in one go: ordered cross-references (`new AnySampleId()` inside `AnySpecimen`) worked even though I scaffolded in an arbitrary order, and `Any.Specimen()`, `Any.LabResult()` read exactly like `Any.Int32()`.
- The scaffolder reads real guards: `ThrowIfNegative`, `ThrowIfLessThan`/`GreaterThan`, `decimal.Round(value,2) != value` -> `Between(1m, 1000m).WithScale(2)`, `value <= 0`/`> 50` -> `Positive().LessThanOrEqualTo(50d)`, a constant of mine (`MeasurementUnit.MaxLength`) is referenced by name, `lower >= upper` -> strict `OrderedPair`. Three types needed no hand edit.
- Failing at build time with an identifier that does not exist, exactly where the unreadable guard is, is a good design: I cannot forget a `to verify`.
- Refinement lambdas in tests read well: `Any.Specimen().WithId(sampleId)`, `Any.SampleId().WithValue(v => v.DifferentFrom(...))`, `Any.MeasurementUnit().WithSymbol(s => s.DifferentFrom(...))`, `Any.SpecimenQuality().WithHemolysisIndex(h => h.Between(101, 500))`. The distinction "dummy / literal" in the docs guided me constantly: ranges, flags, times and values the assertion is about are literals; unit, ids, analytes, specimen type, transit are drawn.
- `[assembly: Reproducible]` one-liner, and the failure output with a ready-to-paste `[JustDummies.Xunit.Reproducible(Seed = ...)]`.
- Generators for numbers/dates were honest about their limits (`Any.Double()` can reach the type's limits one draw in ten; one-sided bounds), so I bounded `Undiluted` inputs with `Between(...)` or used `double.MaxValue` as a deliberate literal for the overflow test. No surprise failure.
- The 30+ repeated runs never failed: with the ties written by construction there was no redraw loop and no flakiness, and the suite takes ~2-3 s.

## Fluency: 4 / 5
The first hour is smooth: the README, the ten-minute guide and the scaffolder produced a compiling, mostly correct arrange layer for ten types in minutes, and the library's vocabulary (`Between`, `DifferentFrom`, `WithX(lambda)`, `Any.Enum`) was guessable. I lose a point for the parts that were not documented as a path: the `dotnet test` / MTP opt-in on .NET 10, and above all the cross-object ties of an aggregate (specimen/result/report), where the generated structure had to be rewritten by hand rather than completed, and where I had to invent how to keep the pins coherent.
