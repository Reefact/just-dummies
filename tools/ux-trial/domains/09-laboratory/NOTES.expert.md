# Expert notes — 09 Laboratory
Agent: the same model and effort as every session of this trial. Library: JustDummies 1.0.0-uxtrial.1 (packed from main).

## What I did
- Pages read, in order: `PROJECT-README.md`, `guides/getting-started.en.md`, `guides/core-concepts.en.md`, `guides/composition.en.md` (the ordered-pair part), `packages/justdummies-cli.en.md` (all of it, including "When a guard ties two parameters"), `packages/justdummies-xunit.en.md`, and the generator pages `numbers`, `dates-and-times`, `strings` (patterns), `collections`, `enums-and-choices`. Not read: analyzer pages (I switched all JD001–JD038 to warning in a throw-away `.editorconfig` at the end: zero diagnostics on the final code, file removed again).

- `any generate SampleId AnalyteCode MeasurementUnit DilutionFactor Measurement ReferenceRange SpecimenQuality Specimen LabResult LabReport --entry-point any --output Generators` (one run, ten types, `Any.X()` entry points).
- Result of the scaffold: 4 types compiled as is (`MeasurementUnit`, `DilutionFactor`, `SpecimenQuality`, plus `Measurement` after one line), 2 needed a one-line retype (`SampleId`, `AnalyteCode`: `Any.String()` becomes `Any.StringMatching(...)`, `AnyString` becomes `AnyPattern`, exactly the 4-line edit the docs describe), and 4 tied-parameter types (`ReferenceRange`, `Specimen`, `LabResult`, `LabReport`) were rewritten by hand (see friction 4).
- Generators completed by hand:
  - `AnySampleId`: `Any.StringMatching("S[0-9]{10}")`; `AnyAnalyteCode`: `[0-9]{1,5}-[0-9]`.
  - `AnyMeasurement`: value `Any.Double().Between(0d, 100_000d)` (the scaffold only knew `Any.Double()`).
  - `AnySpecimen`: draws a collection instant (2020–2030) and a transit in `[0, Specimen.StabilityWindow]`; received = collected + transit. `WithCollectedAt`, `WithReceivedAt`, `WithTransit` pins.
  - `AnyReferenceRange`: kept the scaffold's strict `OrderedPair` for lower/upper (bounded 0..1000); critical limits derived from the drawn bounds, present/absent one draw in ten unless `WithCriticalLimits()`/`WithoutCriticalLimits()`.
  - `AnyLabResult`: draws the numeric value only, takes the unit from the drawn range; reported = specimen.ReceivedAt + delay (0..7 days); pins `WithValue`, `WithRange`, `WithSpecimen`, `WithAnalyte`, `WithReportedAt`.
  - `AnyLabReport`: one specimen carrying the drawn sample id, 1 to 5 results of distinct analytes (`Any.ListOf(Any.AnalyteCode()).WithCount(n).Distinct()`).
  - `Any.Instant()` (my own extension member): an instant between 2020 and 2030, so date arithmetic never reaches the ends of `DateTimeOffset`.
- Tests: 129 methods, 213 cases (theories expanded), in `Tests/`: `SampleIdTests` (6), `AnalyteCodeTests` (8), `MeasurementUnitTests` (8), `DilutionFactorTests` (4), `MeasurementTests` (13), `ReferenceRangeTests` (18: construction order, the full Classify table incl. both bounds, critical limit equal to a bound, NaN), `SpecimenQualityTests` (15), `SpecimenTests` (11: 72 h exactly / +1 tick, instants vs wall clocks), `LabResultTests` (26: guard order, flags/phone call, the Release/Amend lifecycle, failed amendments change nothing), `LabReportTests` (16), `GeneratorsTests` (3: 1 000 draws of every generator must construct).
- Style: `[assembly: Reproducible]` once (global usings in `Tests/Assembly.cs`), every drawn value named `anyXxx`, literals only where the assertion is about them (range limits, tick boundaries, 72 h, dates in turnaround tests), Arrange/Act/Assert.
- Final result: green. First complete run 212/212 (2 skipped), then 15 + 14 + 11 additional runs with fresh seeds, all green (now 213 cases, 3 skipped). Skipped = 3 domain defects (below), each with the reported seed.

## Frictions and surprises, in order
1. **`dotnet test --project Tests.Expert` does not work as given.** SDK 10.0.114, xunit.v3 4.0.2 project: `MSBUILD : error MSB1001: Unknown switch ... Switch: --project`. Plain `dotnet test Tests.Expert` then fails with `Microsoft.Testing.Platform.MSBuild.targets(395,5): error : Testing with VSTest target is no longer supported by Microsoft.Testing.Platform on .NET 10 SDK and later. If you use dotnet test, you should opt-in to the new dotnet test experience`. Fix: a `global.json` with `{ "test": { "runner": "Microsoft.Testing.Platform" } }` at W. None of the JustDummies pages (`getting-started`, `justdummies-xunit`) mention it, though `PROJECT-README` itself advertises `dotnet test --solution`. A newcomer on .NET 10 hits this before the first test; the xunit page should carry a line or the template should ship the `global.json`.
2. **Generated files do not compile on purpose, and the recap reads clearly** (`value  string  Any.String()  to verify, unread guards`, "The file will not compile until you resolve it. That is deliberate."). I expected that from the docs; it worked as advertised: `error CS0103: The name 'TODO_verify_the_generator_for_sampleId' does not exist` listed twelve places, which was a usable work list. But the project's own tests did not even build until all ten were resolved, including the ones I did not need yet.
3. **`Measurement`'s `value switch { double.NaN => throw …, … < 0 => throw … }` is not read.** The recap shows only `Value = value switch { ...` (truncated), so the reader cannot tell which arm defeated the tool; it was one switch expression with three plain throwing arms, i.e. exactly "finite and non-negative", which the `if (!double.IsFinite(p))` and `p < 0` rows would have handled. Result `Any.Double()` marked to verify. (Cost: one line, but it is the guard shape a modern C# value object uses most.)
4. **The four types with tied parameters were rewritten wholesale, and that is where the scaffold costs more than it gives.** `Specimen` (`receivedAt - collectedAt <= 72h`), `ReferenceRange` (critical limits vs bounds), `LabResult` (`measurement.Unit == range.Unit`, `reportedAt >= specimen.ReceivedAt`), `LabReport` (results share the sample id, distinct analytes). For each the tool correctly says "ties X to Y", and the docs' "Draw a start and a duration" advice is exactly right, but it conflicts with the scaffold's structure: the per-parameter fields, recipe fields, copy constructor and two `With…` per parameter (about 250 lines for `AnyLabResult`) all assume parameters are independent. Replacing `collectedAt, receivedAt` by `collectedAt, transit` changes the parameter list, so the generated `With…` methods are wrong and had to be deleted, not edited. I ended with 40–140 line hand-written files, much more readable than the scaffold. Idea: when a tie is detected, offer a "skeleton" (`Any.Combine`/`Then` stub in `Generate()`) instead of per-parameter `With…`.
5. **The scaffold paired `lower`/`upper` automatically, strict (`Any.OrderedPair(_lowerRecipe, _upperRecipe, strict: true)`) — a real help**, but it paired them at the unbounded default (`Any.Double()`, nine in ten within ±1e6, the tenth near `double.MaxValue`). Since the tie to the critical limits had to be added by hand anyway, I redid the bounds (0..1000). Not wrong, just the scaffold had no way to know what "ordinary" is for a lab.
6. **The same tool does not pair `criticalLow`/`lower` because of the `is not null &&` wrapper.** `if (criticalLow is not null && criticalLow.Value > lower)` is a `&&` so it is "not read" (documented: "a `&&` is not read"), and the optional-vs-bound tie is the most common shape of a nullable limit. The message "ties criticalLow to lower" shows the tool understood the intent; it just refuses to act. Fine and honest, but I would have liked the docs' list of "to verify" shapes to mention the nullable-limit case, since it is so frequent.
7. **Seed noise on non-drawing failures.** A test that draws nothing (my `new AnalyteCode("2345-7\n")` case, a pure literal) failed and still printed `[JustDummies] These arbitrary values were seeded with -943412796. Reproduce this run with [JustDummies.Xunit.Reproducible(Seed = …)]`. With `[assembly: Reproducible]` every failure carries it, so the message is accurate for the library but misleading for the reader (no arbitrary value was involved; replaying changes nothing). I had to write "no draw involved, seed X reported anyway" in the `Skip` reasons to follow the brief.
8. **`DifferentFrom` on a scaffolded generator is a pleasant surprise**: `Any.SampleId().DifferentFrom(anyId)` compiles and reads like the intent. I first wrote `Any.SampleId().WithValue(v => v.DifferentFrom(anyId.Value))` because the CLI page's "Adjusting a parameter" section only shows `With…` lambdas, and its `Crossing` example shows `DifferentFrom` on a plain `IAny<string>` inside `Then`. The shorter form is in `packages/justdummies-cli.en.md` only as one sentence ("On any other generator, a scaffolded one included, `DifferentFrom` redraws…"); a small example next to the scaffolded `With…` description would have saved a rewrite.
9. **Distinct analytes are not automatic**: two plain `Any.AnalyteCode()` draws in one report collide about once in a million runs and the failure would be a `LabReport` refusal (the right exception type, so easy to mistake for the test's point). I caught it at design time (`DistinctAnalytes(n)` helper using `Any.ListOf(...).WithCount(n).Distinct()`), because I know `LabReport` rejects equal analytes; nothing in the tooling points at it. JD028 only fires for reference types without `Equals`.
10. **`Any.Double()` default is a trap for domains with overflow** — documented well (`numbers.en.md`: nine in ten within ±1e6, the tenth at the type's limit) and JD036 exists; I bounded `Measurement` at 100 000 before ever running `Undiluted`, so the limit draw never bit me. Worth noting that the scaffold itself produced the unbounded `Any.Double()` for `Measurement.Value` (friction 3), which `Undiluted` would turn into `ArgumentException` one run in ten at the type's limit. The scaffold's "to verify" kept me from shipping that.
11. `Assert.Throws<ArgumentException>` is exact-type in xUnit; the domain throws `ArgumentOutOfRangeException` and `ArgumentNullException` for distinct cases, so each refusal test names the type, which is how I caught the `DilutionFactor` rule that the range is judged before the decimals. Not a library matter, but the library's `ParamName` checks were all useful.
12. Domain findings produced by ordinary refusal cases (not hunted): (a) `AnalyteCode` accepts `"2345-7\n"` (the `$` anchor matches before a final line break); (b) `AnalyteCode` accepts non-ASCII Unicode digits (`\d`), while `SampleId` insists on ASCII digits; (c) `LabReport.Results` returns the private `List<LabResult>` typed as `IReadOnlyList`, so `as IList<LabResult>` then `.Clear()` empties the report and breaks "at least one result". Also observed and left as documented: a `NaN` critical limit is accepted (comparison is false) and then silently never triggers; `Measurement.ToString()` uses the current culture.

## What worked well
- `any generate` with several types in one run, then the recap table: the `to verify` column told me, per parameter, which of my ten generators were safe and which needed a rule, and it was right every time. `MeasurementUnit` (`NotBlank().WithMaxLength(MeasurementUnit.MaxLength)`, even referencing the public constant), `DilutionFactor` (`Between(1m, 1000m).WithScale(2)`) and `SpecimenQuality` (all three guards, including `Positive().LessThanOrEqualTo(50d)` out of a `!(v > 0)` NaN-safe guard) needed zero edits and are correct.
- `--entry-point any` makes arrange blocks read `Any.LabResult().WithRange(potassium).WithValue(2.5)` next to `Any.Double()`; with the pin/lambda split (`WithHemolysisIndex(100)` vs `WithVolumeMillilitres(v => v.GreaterThanOrEqualTo(SpecimenQuality.MinimumVolumeForChemistry))`) the tests state what matters and nothing else.
- The "constraint states an invariant, never the assertion" rule is a genuinely good review tool: it made me decide, test by test, what stays a literal (the 72 hours, `3.5/5.1/2.5/6.5`, the instants of the turnaround cases) and what is drawn (units, sample ids, analytes, the specimen, report times).
- `[assembly: Reproducible]` + seed in the failure output: the three domain-defect tests came with a seed immediately; replay needs no wrapper.
- `Distinct()` on a list of `AnalyteCode` (value equality) and `.OrderedPair(..., strict: true)` did what the docs say first time. 213 cases ran green 40+ times without a single failure on a drawn value.
- Analyzers: zero diagnostics at warning level on the final code; no false alarm.

## Fluency: 4 / 5
The path from nothing to a green suite was short for the six simple types and the docs for the value-object, `.As`, `OrderedPair` and `Then` patterns matched what the library did, with no guessing at API names. I lose one point because the type that matters most to a laboratory (entities with a tie between parameters: window, shared unit, shared id) is where the scaffolder hands over, and the scaffold's per-parameter structure then fights the hand-written rule; I rewrote four of ten generators from scratch. The first `dotnet test` step was also blocked for reasons the JustDummies pages do not mention.
