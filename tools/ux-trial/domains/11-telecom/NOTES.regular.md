## Frictions and surprises, in order
1. `dotnet test --project Tests.Regular` fails out of the box: `MSBUILD : error MSB1001: Unknown switch.` (`--project` is forwarded to MSBuild). With `dotnet test Tests.Regular` the error is `Testing with VSTest target is no longer supported by Microsoft.Testing.Platform on .NET 10 SDK and later ... opt-in to the new dotnet test experience`. I had to create a `global.json` (`{ "test": { "runner": "Microsoft.Testing.Platform" } }`) at the workspace root. None of the pages I read (getting-started, xunit package page, project README) says a consumer on the .NET 10 SDK needs this; the project README only says the repository pins the SDK in `global.json`. Cost: a few minutes.
2. `any generate` before a restore: `✗ Msisdn: this project has not been restored, so its package references cannot be read. Restore it, then run the command again: dotnet restore`. Clear and actionable; I only note it because the CLI page never mentions the prerequisite.
3. A regex guard means four small manual edits (field type, constructor parameter, factory, the `Func`) plus deleting the TODO. The comment lists them precisely, and it is fast once you know it, but it is the same mechanical edit each time (Msisdn, Iccid). A `--regex-as-pattern` style option, or the tool translating a pattern already inside the regular subset, would remove it. Expected from the docs; no surprise.
4. `BillingPeriod`: the tool recognised `start >= end` and wrote an `OrderedPair`, but the second guard (`end.DayNumber - start.DayNumber > 31`) is "unread" and the tool flagged both parameters `to verify`. Good, since the scaffolded pair would have drawn periods of years. But the page offers "draw a start and a duration" as a recipe and nothing for a pair that is both ordered and bounded: I discarded the generated file and wrote the whole class by hand, losing the `WithStart`/`WithEnd` pins the tool generates (`WithEnd` is not reproduced). Expected a hint in the tool's comment that an `OrderedPair` is already in place and only a maximum gap is missing.
5. `UsageRecord`: `if (kind == UsageKind.Sms && quantity != 1)` (a `&&`) is, as documented, not read. The "derive one draw from another inside `Generate()`" advice works, but its consequence is mine to design: I added a `_quantityPinned` flag so a test pinning `WithQuantity(2)` on an Sms still reaches the constructor's refusal rather than being silently replaced by 1. The doc mentions that a derived parameter's pin stops reaching the draw, but gives no pattern for keeping the pin meaningful.
6. `Plan` name over 40 characters: the exception's `ParamName` is `"name.Length"` (the domain calls `ArgumentOutOfRangeException.ThrowIfGreaterThan(name.Length, 40)` and the caller-argument-expression becomes the name). Not a JustDummies matter; recorded as a domain defect and I stopped asserting `ParamName` on that test.
7. `AnyPattern` offers no way to say "starts with 336/337" (`StartingWith` is on `AnyString` only). The CLI page anticipates it ("a narrower pattern is a named recipe") and the partial-class `FrenchMobile()` took me five lines, reaching the private `_digitsRecipe`/`_digits` fields the page tells you to use. It works; it is also the only place where I wrote against generated private fields, which feels fragile against a re-scaffold (the compiler would catch it, as promised).
8. For a "second value that differs from the first" (`Any.Imei().DifferentFrom(first)`), the scaffolded `IAny<Imei>` supports it directly on the generator, relying on the class's `Equals` override. It worked first time; for `Msisdn` the lambda `WithDigits(d => d.DifferentFrom(first.Digits))` also works. No friction, noted because both forms exist and I had to remember which applies.
9. Unbounded draws did not hurt any test: a drawn plan can carry fees or rates near `decimal.MaxValue` (`GreaterThanOrEqualTo(0m)` reaches the limit one draw in ten) and a drawn usage quantity can approach `long.MaxValue`. I never mixed such draws into an arithmetic assertion (billing tests pin plan and quantities), so the suite stayed green; but a reviewer might ask whether `BillFor` is safe at those magnitudes. I did not go looking.

## What worked well
- `any` read the numeric guards correctly, including the less obvious `decimal.Round(monthlyFee, 2) != monthlyFee` (`WithScale(2)`), the `ThrowIfNegativeOrZero` family and `ThrowIfNullOrWhiteSpace` + length (`NotBlank().WithMaxLength(40)`), and composed `MobileLine` through `new AnyMsisdn()` / `AnyImei` / `AnyPlan`.
- The `to verify` marks were each on a guard I would indeed have had to read myself, and the build stopping at them kept me honest (the Luhn check digit, the SMS tie, the 31-day gap).
- `With…` pins and lambdas read well in tests: `Any.Plan().WithTier(Unlimited)` leaves allowance and rate arbitrary, which is exactly the claim of the test.
- `[assembly: Reproducible]` plus the seed printed under "Standard output" of a failing test (`seeded with -709140740 ... [Reproducible(Seed = ...)]`) is the right amount of ceremony.
- Draws revealed nothing flaky: every refusal test with an arbitrary value (`Any.Int64().Negative()`, `Any.DateOnly().Before(...)`, `Any.TimeSpan().Negative()`) stayed green over 13 runs.

## Domain observations (tests kept, marked Skip, or characterised)
- `Msisdn`, `Iccid`: `"33612345678\n"` and a 19-digit ICCID + `\n` are accepted (`$` matches before a final line feed). Tests `Refuses_digits_followed_by_a_line_feed` and `Refuses_a_value_followed_by_a_line_feed` are skipped as domain defects (not seed-dependent).
- `UsageRecord`: `(UsageKind)99` is accepted while `Plan` refuses an undefined `PlanTier`. `Refuses_an_undefined_kind` skipped.
- `MobileLine.Usage`: the backing `List<UsageRecord>` is returned as `IReadOnlyList`, so `((IList<UsageRecord>)line.Usage).Add(...)` mutates the line. `Exposes_usage_as_a_list_that_cannot_be_modified_from_outside` skipped.
- `Plan`: `ParamName` of the length refusal is `name.Length`.
- Characterised, not skipped (the model says so explicitly): usage dated before activation is metered; a suspended or terminated line is still billed the fee and overage; a past period is billed at the current plan.

## Fluency: 4 / 5
Daily use was smooth once the project ran: scaffolding eight types took one command, the recap told me exactly which three generators (Imei, UsageRecord, BillingPeriod) needed thought, and the DSL covered every constraint I needed (`MultipleOf`, `WithScale`, `NotBlank`, `DifferentFrom`, `Negative`, `AfterOrEqualTo`). Points lost for the `dotnet test --project` setup that no page mentions (the most expensive surprise) and for the two ties (an ordered pair with a maximum gap, and kind vs quantity) where the tool rightly stops but leaves a full rewrite rather than a small patch of the generated file.
