## Frictions and surprises, in order
1. `any generate EmployeeId ...` right after creating the csproj: `✗ EmployeeId: this project has not been restored, so its package references cannot be read. Restore it, then run the command again: dotnet restore`. Clear and actionable; I ran `dotnet restore` and went on. (Minor: the message is good, but the CLI page does not say a restore is a prerequisite.)
2. `dotnet test --project Tests.Regular` (the command of the brief and of the repo's own CONTRIBUTING) fails on a plain SDK 10 workspace: `MSBUILD : error MSB1001: Unknown switch ... --project`. And `dotnet test` inside the folder: `Testing with VSTest target is no longer supported by Microsoft.Testing.Platform on .NET 10 SDK and later ... opt-in to the new dotnet test experience`. I had to add a `global.json` with `{ "test": { "runner": "Microsoft.Testing.Platform" } }`. Nothing in the JustDummies.Xunit page mentions it, although xunit.v3 4.0.2 on .NET 10 needs it.
3. The scaffold of `EmploymentContract` marks 4 of 6 parameters `to verify, unread guards` because validation lives in a `Validate(type, hiredOn, endsOn, weeklyHours)` helper (void). Expected given the docs (a `void` helper is marked). Cost: the four TODOs all point to the same line 9, and the per-parameter recipes cannot express the cross rules (type vs weekly-hours ceiling, type vs endsOn nullability, endsOn > hiredOn). I edited `Generate()` by hand as the docs suggest ("derive one draw from another inside Generate()"). The consequence documented there bit as announced: my derived `endsOn` no longer comes from its field, so I had to remove the lambda overload `WithEndsOn(Func<...>)` and make the field nullable to keep the pins. Workable but it is the most manual part of the day, and every edit is invisible to a later `--force`.
4. `AnyPayslip`: same story for `period` vs `contract.HiredOn` (the tool says `ties period to contract`, good wording). I derived the period in `Generate()` with `Any.DateOnly().Between(...).As(day => new PayPeriod(...))`. No compiler/analyzer help to notice that a test pinning only the contract with a late `hiredOn` plus a pinned period would fail on every run: that is on me.
5. Scaffolded `PayslipLine.amount` is `Any.Decimal().Positive().WithScale(2)`: unbounded above. Because the docs say a one-sided bound is drawn near ±1 000 000 nine times in ten but the tenth reaches the type's limit, a list of such lines could overflow `TotalBonuses` (`decimal` sum) one day. I capped it at 5 000 on reading the numbers page. No problem happened, but the tool gave no hint (the domain has no cap, so there is nothing to infer). Same reasoning for `Any.Decimal().Negative().WithScale(2)` and `Any.Int32().LessThan(2000)` in refusal tests: harmless there because the value only goes into a throwing constructor.
6. To get a valid label for a refusal test (`new PayslipLine(anyLabel, kind, amount)` with only the amount invalid) I wrote `Any.PayslipLine().Generate().Label`: drawing a whole line to keep one field. The scaffold keeps `AnyValidLabel()` private, so the single address for "a valid label" is not reachable from a test. I accepted the waste rather than repeat `Any.String().NotBlank().WithMaxLength(40)` (a second copy of the invariant). A public `Valid…` accessor or a `Any.PayslipLine().Label()` would be welcome.
7. Test naming vs the docs' advice: the docs keep "always / never" out of names; I had to rephrase a few ("The net pay never goes below zero" is deterministic here, with pinned values, so I kept it). No tool issue.
8. No analyzer diagnostic fired anywhere (build with zero warnings), including on the scaffolded `Any.String()` in label (JD030 is Info, invisible by default, as documented).

## What worked well
- `any generate A B C D E F --entry-point any` scaffolded six types in one go, in the right dependency order of names (`new AnyEmployeeId()` referenced before it was complete), and the build then listed exactly what was left. The recap column (`guard`, `AnyX`, `to verify`) was accurate: `HourlyRate` (`Positive().LessThanOrEqualTo(HourlyRate.Ceiling).WithScale(2)`, using my public constant), `PayPeriod`, `PayslipLine` and `hoursWorked` (`Between(0m, 300m)`) needed nothing.
- The regex case is spelled out right in the TODO comment, including the retype list, so `AnyString` -> `AnyPattern` took two minutes.
- `With…(value)` pins plus `Any.Payslip().WithContract(c).WithPeriod(p).WithHoursWorked(h)` made the arrange blocks short, and unpinned parts (lines, employee id, label) stayed visibly arbitrary: e.g. the seniority-bonus tests do not pin lines, which proves the bonus ignores them.
- `[assembly: Reproducible]` in one file; no seed was ever needed over 38 runs.
- `Any.DateOnly().Before(date)`, `Any.Decimal().Negative().WithScale(2)`, `Any.Int32().GreaterThan(12)` read exactly like the domain refusals.

## Fluency: 4 / 5
Scaffolding and the DSL were smooth and the docs found each detail in one lookup. Points lost for the `dotnet test --project` setup (undocumented `global.json` opt-in on .NET 10) and for the cross-parameter rules of the contract and the payslip, which are normal for the library's design but still the bulk of the manual work: the recipe model has no room for them, so I rewrote two `Generate()` methods by hand and lost the lambda overloads for the affected fields.
