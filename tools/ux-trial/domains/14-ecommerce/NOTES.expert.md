# Expert notes — 14 e-commerce
Agent: the same model and effort as every session of this trial. Library: JustDummies 1.0.0-uxtrial.1 (packed from main).

## What I did
- Pages read, in order: `PROJECT-README.md`, `guides/getting-started.en.md`, `guides/composition.en.md`, `packages/justdummies-cli.en.md` (whole, including "Adjusting a parameter", "When a guard ties two parameters"), `packages/justdummies-xunit.en.md`, then the generator pages on demand (`generators/README`, `enums-and-choices`, `strings`, `collections`, grep of `numbers` and `dates-and-times`).
- `dotnet restore`, then one `any` run for the whole domain:
  `any generate Money DiscountPercentage Quantity Sku ShippingAddress GiftCard PromoCode OrderLine Order --output Generators --entry-point any`
  Recap: 9 files + 9 `.Entry.cs`. Seven carried a `to verify` sentinel (Money.currency, DiscountPercentage.value, Sku.value, ShippingAddress.postalCode/countryCode, GiftCard.number/pin, PromoCode.maxUses, Order.lines).
- Generators completed by hand (all in `Tests.Expert/Generators`):
  - `AnyMoney`: currency `Any.String().OneOf("EUR","USD","GBP")` (type stays `AnyString`, no retyping). Plus `AnyMoney.Custom.cs` exposing `ValidCurrencies()`/`ValidAmounts()` (the valid bases are private, CS0122 as documented).
  - `AnyDiscountPercentage`: `Any.Decimal().Between(0m, 100m).WithScale(1)`.
  - `AnySku`: `Any.StringMatching(@"[A-Z]{3}-\d{4}")`, retyped `AnyString` -> `AnyPattern` everywhere (4 places).
  - `AnyShippingAddress`: country `OneOf("FR","BE","DE")`; postal code is tied to the country, so `Generate()` is now `_countryCode.Then(country => Any.Combine(street, city, postal-by-country, ...))`, the postal-code recipe field/ctor parameter/lambda overload were removed and the pin kept.
  - `AnyGiftCard`: number `Any.String().Numeric().WithLength(16)`, pin `Any.Int32().Between(0, 9999)`.
  - `AnyPromoCode`: `maxUses` `Any.Int32().Positive()`. The date pair came out right (non-strict `OrderedPair`, strict for Order's placed/deadline).
  - `AnyOrder`: lines drawn with one currency via `OneOf(...).Then(currency => Any.ListOf(new AnyOrderLine().WithUnitPrice(p => p.WithCurrency(currency))).WithCountBetween(1, 5).As(l => (IReadOnlyList<OrderLine>)l))`; the recipe field became an `IAny` and the list-lambda overload `WithLines(Func<...>)` was deleted (only the pin remains).
- Tests (`Tests.Expert/Tests`, `[assembly: Reproducible]`, never `var`): 147 test methods, 262 cases (255 run, 7 skipped).
  MoneyTests (construction, check order, equality, ToString, Plus, Times, Less incl. half-away-from-zero midpoints), DiscountPercentageTests, QuantityTests, SkuTests, ShippingAddressTests (each rule + check order + IsDomestic), GiftCardTests (ctor + Redeem), PromoCodeTests (ctor + check order + AppliesTo bounds), OrderLineTests, OrderConstructionTests (ctor, order of checks, lines copied), OrderLifecycleTests (full state matrix), OrderPricingTests (subtotal/discount/total/units, shipping fee matrix incl. threshold and post-discount). Test data builders in `OrderBuilders.cs`.
- Result: green first time on the first full run (254 passed, 3 skipped); after adding tests, 12 + 40 + 10 further runs, all green (262 cases, 7 skipped by design). One red seen on the way, see friction 9.

## Frictions and surprises, in order
1. `dotnet test --project Tests.Expert` (the command the brief gives) fails on SDK 10.0.114 with
   `MSBUILD : error MSB1001: Unknown switch ... --project Tests.Expert`; plain `dotnet test Tests.Expert` fails with
   `Testing with VSTest target is no longer supported by Microsoft.Testing.Platform on .NET 10 SDK and later ... https://aka.ms/dotnet-test-mtp-error`.
   Neither the JustDummies docs nor `getting-started` say a `global.json` `{"test":{"runner":"Microsoft.Testing.Platform"}}` is required with `xunit.v3` on .NET 10. I added that file at the workspace root (W) and `--project` worked. (docs/getting-started or the xunit page could carry a one-line warning.)
2. First `any generate Money ...` before a restore: `✗ Money: this project has not been restored, so its package references cannot be read. Restore it, then run the command again: dotnet restore`. Clear and actionable; I restored and re-ran.
3. The recap's `to verify` rows for closed value sets are the most common gap in this domain and the tool offers no hint about the idiom: `currency switch { "EUR" or "USD" or "GBP" => ... }` and `countryCode is not ("FR" or "BE" or "DE")` both give `Any.String()` + sentinel (`unread guards`). The fix is `Any.String().OneOf("EUR","USD","GBP")`, which I only found in `enums-and-choices.en.md` ("a typed builder's OneOf"), not in the CLI page, whose only worked retyping example is `StringMatching`. I expected the tool to read an `is not (constants...)` / switch-on-constants guard as `OneOf`, or at least name `OneOf` in the TODO comment.
4. Same for `if (!(pin >= 0 && pin <= 9999))` (GiftCard): the recap says `unread guard`, the docs say `&&` is never read, but this is the negation of a `||` pair, which IS read when written `pin < 0 || pin > 9999`. A De Morgan normalisation of `!(a && b)` would have inferred `Between(0, 9999)`. Likewise `MaxUses = maxUses > 0 ? maxUses : throw ...` (conditional-throw expression) was unread, although `p ?? throw` is. I wrote `Between(0, 9999)` and `Positive()` by hand.
5. `DiscountPercentage` delegates to a private `static void Validate(decimal)`; the tool marks `value` `to verify` with a bare `Any.Decimal()` (docs: "a void helper called for its effect ... is marked as before"). It is a one-level helper whose body only throws on `value`: reading it like the value-returning `Guard(x)` helper would have produced `Between(0m,100m)` + the `Round(value,1)` -> `WithScale(1)` row the tool does know. Low priority, documented.
6. Regex guards (`Sku`, `ShippingAddress`) are by design never read. Replacing `Any.String()` by `Any.StringMatching(...)` means retyping `AnyString` -> `AnyPattern` in four places of a ~75-line file (field, `AnyValid…`, recipe ctor, `Func` overload). It is documented and mechanical, but I did it with a search-and-replace, and the compiler caught nothing wrong: good. The sentinel text even says where to retype.
7. A rule tying two parameters (postal-code format depends on the country) is the part that costs the most. The docs' "Derive one draw from another inside `Generate()`" form works, but the scaffold has five coupled places per parameter (field, recipe field, primary ctor, copy ctor, two `With…`); making the postal code derived meant touching all five (nullable field, deleting the recipe field and the lambda overload, keeping the pin). Consequence the docs predict and I confirmed: `Any.ShippingAddress().WithPostalCode("1234")` is only valid if the country is also pinned to BE; otherwise the seed decides. I left a comment on the field. I would have liked a documented, supported hook for "this parameter's recipe is a function of another parameter" so as not to rewrite `Generate()` by hand.
8. `Order.lines` carries a cross-element rule ("all lines share one currency"; guard `lines.Select(l => l.UnitPrice.Currency).Distinct().Count() > 1`). The element generator cannot receive a currency from the list level, so `Any.ListOf(new AnyOrderLine())` is wrong in 2/3 of cases with 2+ lines. I built it with `OneOf(...).Then(currency => ListOf(new AnyOrderLine().WithUnitPrice(p => p.WithCurrency(currency))))`. That works and the nested `With…(lambda)` is pleasant, but the result is an `IAny<List<..>>`, so the scaffolded recipe type `AnyList<OrderLine>` and the `WithLines(Func<AnyList<OrderLine>,...>)` overload had to go; tests can no longer say `.WithLines(l => l.WithCount(3))`. The docs show "A collection's elements, drawn another way" but not "elements sharing a value chosen once at the list level".
9. Unbounded money: the scaffolded `AnyMoney` amount is `GreaterThanOrEqualTo(0m).WithScale(2)` (a faithful reading of the constructor), which one draw in ten reaches `decimal.MaxValue` territory. My test `An_undefined_shipping_method_is_accepted_by_the_order_but_has_no_fee` asserted `order.Total` throws `ArgumentOutOfRangeException` on a fully drawn order; it passed on the first runs and then failed with `OverflowException: Value was either too large or too small for a Decimal.` (seed 1638907644 via `[Reproducible(Seed = 1638907644)]`; the failure output printed the seed exactly as documented, which made this a 2-minute diagnosis). Verdict per the two rules: `Total` adds the lines before asking for the fee, so the lines did take part in the outcome -> I pinned a literal subtotal in that test; and the domain does have a defect that the draw revealed (Money has no ceiling, arithmetic overflows with an unrelated exception type): recorded, with a skipped literal reproduction. I deliberately did not cap `AnyMoney` to hide it.
10. `any` could not know the domain-level fact "an `OrderLine` unit price and the order currency go together", and happily wrote `new AnyMoney()` for the line price. That is the correct, honest scaffold; the `to verify` mark on `Order.lines` pointed at the right guard (line 42), which is what made friction 8 quick to find.
11. Namespace: the scaffolded generators land in the domain's own namespace (`Shop.Domain`) inside the test assembly. It compiles and the entry point `Any.Money()` reads well, but an expert would normally want `--namespace Shop.Domain.Tests.Generators`; I kept the default to stay close to the documented flow. (Not a defect; the option exists.)
12. Quirk worth knowing: a negative `Times(-1)` on an amount of `0` does not throw (0 * -1 == 0). My test therefore uses a non-zero price. Domain behaviour, not library.

## What worked well
- The recap table with `guard`/`AnyX`/`to verify` is excellent triage: it told me exactly which 7 parameters needed a decision, and the unreadable ones fail the build at the exact line instead of drawing silently.
- `OrderedPair` detection: `placedAt >= deadline` became `strict: true`, `validUntil < validFrom` non-strict, and the `WithPlacedAt(DateTime)` pin bounds the other side. No work needed.
- The `With…(pin)` / `With…(lambda)` pair gives the tests the Arrange I wanted: `Any.Order().WithLines(...).WithDiscount(new DiscountPercentage(20m)).WithShippingAddress(a => a.WithCountryCode("FR"))` reads like the rule under test, and everything else stays visibly arbitrary. Nested refinement (`WithUnitPrice(p => p.WithCurrency(...))`) is a real pleasure.
- `[assembly: Reproducible]` plus a seed printed in the failure output and replayable on the attribute: the single red I had was diagnosed from the seed alone.
- `Any.Decimal()...WithScale(2)` read from `decimal.Round(amount, 2) != amount` automatically; `DifferentFrom` on every builder made the "not equal" tests honest (`DifferentFrom(anyMoney.Currency)`) without hand loops.
- Generator-aware errors: refining past the base (`DifferentFrom` after `OneOf`) behaved as documented.

## Fluency: 4 / 5
The scaffold plus recap got ~80 % of the domain to a compiling, correct base in one command, the `With…` surface made Arrange blocks intention-revealing, and the seed report turned the only red into a quick diagnosis. I lose a point for the two places where the hand edit is heavy and under-documented (a parameter whose recipe depends on another parameter, and a collection whose elements must share a value), for the closed-set guards (`is not (...)`, `switch`) that the tool does not turn into `OneOf` nor point to it, and for the undocumented `global.json` requirement before any test can run on .NET 10.
