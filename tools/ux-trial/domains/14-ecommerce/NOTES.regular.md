# Regular notes — 14 e-commerce
Agent: the same model and effort as every session of this trial. Library: JustDummies 1.0.0-uxtrial.1 (packed from main).

## What I did
- Read, in order: `MODEL.md`, `Domain/*.cs`, `docs/guides/getting-started.en.md`, `docs/packages/justdummies-cli.en.md` (whole, it is the reference I needed most), `docs/packages/justdummies-xunit.en.md`, the generator pages (`strings`, `numbers`, `dates-and-times`, `collections`, `enums-and-choices`), `docs/guides/composition.en.md` and the "Arbitrary does not mean dummy" section of `core-concepts`.
- Created `Tests.Regular/Shop.Domain.Tests.Regular.csproj` from the template, `dotnet restore`, then
  `any generate Money DiscountPercentage Quantity Sku ShippingAddress GiftCard PromoCode OrderLine Order --entry-point any`
  (one run, nine types, `Any.Xxx()` entry points). Result: 9 generators, 0 build errors after hand completion.
- Generators completed by hand:
  - `AnyMoney`: currency `Any.String().OneOf("EUR","USD","GBP")` (switch-expression guard unread).
  - `AnyDiscountPercentage`: `Any.Decimal().Between(0m, 100m).WithScale(1)` (guard hidden in a `void Validate` helper).
  - `AnySku`: `Any.StringMatching("[A-Z]{3}-[0-9]{4}")`, retyped `AnyString` -> `AnyPattern` on factory, field, ctor, `WithValue` Func (as the doc says).
  - `AnyGiftCard`: number `Numeric().WithLength(16)`, pin `Between(0, 9999)`.
  - `AnyPromoCode`: `maxUses` `Positive()`.
  - `AnyShippingAddress`: country `OneOf("FR","BE","DE")`; postal code is tied to the country, so I removed its recipe/field/refining overload and derive it in `Generate()` (`[0-9]{4}` for BE, `[0-9]{5}` otherwise); `WithPostalCode(string)` pin kept.
  - `AnyOrder`: lines must share one currency; base is now `Any.OneOf("EUR","USD","GBP").Then(currency => Any.ListOf(new AnyOrderLine().WithUnitPrice(p => p.WithCurrency(currency))).NonEmpty().As(l => (IReadOnlyList<OrderLine>)l))`, retyped the recipe to `IAny<IReadOnlyList<OrderLine>>`. `placedAt/deliveryDeadline` were scaffolded as a strict `OrderedPair` with no edit.
- `global.json` added in W (`"test": {"runner": "Microsoft.Testing.Platform"}`) so that `dotnet test --project` works (see friction 1).
- Tests (156 test methods, 300 cases with theories), one class per type plus `Dummies.cs` (shared generators) and `[assembly: Reproducible]`:
  MoneyTests (20), DiscountPercentageTests (5), QuantityTests (7), SkuTests (9), ShippingAddressTests (17), GiftCardTests (16), PromoCodeTests (26), OrderLineTests (6), OrderTests (38: construction, check order, copied lines, subtotal/discount/total/units, undefined shipping method, full lifecycle matrix), ShippingFeePolicyTests (12: each method, country, threshold at 49.99/50/50.01, threshold after discount, currency).
  Rule I followed: what a test is about (amounts, thresholds, statuses, boundaries) is a literal or a pin; what it needs and does not care about (street, city, pin, number, sku, the other currency, the order behind a state transition, the placement instant of a refused deadline) is drawn.
- Result: green with `dotnet test --project Tests.Regular`: 300 cases, 294 passed, 6 skipped (all documented domain defects, see below), 0 failed. Then 12 more runs (fresh `[Reproducible]` seeds each), 12/12 green, same numbers.
- Domain defects kept as `Skip = "domain defect: ..."` tests: Money.ToString is culture-sensitive; Sku and postal code accept a trailing line feed and non-ASCII digits (4 tests); GiftCard.Redeem accepts a negative amount.

## Frictions and surprises, in order
1. `dotnet test --project Tests.Regular` fails out of the box on SDK 10.0.114: `MSBUILD : error MSB1001: Unknown switch. ... Switch: --project`. `--project` only exists in Microsoft.Testing.Platform mode, selected by a `global.json` `"test": {"runner": "Microsoft.Testing.Platform"}`. The consumer docs never mention it (`PROJECT-README.md` only says the repo pins its SDK in `global.json`, and shows `dotnet test --solution`). I wrote the global.json myself; a newcomer copying the xunit adapter page would be stuck on a cryptic MSBuild error.
2. `any generate Money` before `dotnet restore`: `✗ Money: this project has not been restored, so its package references cannot be read. Restore it, then run the command again: dotnet restore`. Clear and actionable, only noting that it needs a restore of the test project first (not in the CLI page's first sample).
3. Scaffold quality on this domain: 9 types, 5 needed a hand completion for guards the tool cannot read: `switch` expression on currency, `void Validate(value)` helper (DiscountPercentage), a regex (Sku), `number.All(char.IsAsciiDigit)` and `!(pin >= 0 && pin <= 9999)` (GiftCard), a ternary-throw in an assignment (`maxUses > 0 ? maxUses : throw`, PromoCode). All are documented as unreadable, so no surprise, but `!(a >= 0 && a <= 9999)` is a plain range, one De Morgan from a shape the doc says it reads (`!(p > N)`); I expected `Between(0, 9999)`. The comment on each `TODO` line is precise (file, line, guard quoted), which made each fix a one-liner.
4. Tied parameters (ShippingAddress postal code vs country) are the expensive case. The tool flags both parameters `to verify`, but the fix is not a one-liner: the doc offers `Then`/`As`/`Combine` in `Generate()`, yet a per-parameter recipe cannot depend on another parameter, so I deleted the postal-code recipe field, ctor parameter, copy-ctor line and refining overload by hand (about 6 edit sites) and wrote the derivation in `Generate()`. It works and survives, but the next `--force` loses it, and `WithPostalCode(Func)` no longer exists. The doc's "derive one draw from another inside Generate()" paragraph is the right idea but gives no worked example for a string tied to a string.
5. Collection whose elements share a rule (all lines in one currency): `Any.ListOf(new AnyOrderLine())` cannot express it. To draw the currency first I had to retype the recipe from `AnyList<OrderLine>` to `IAny<IReadOnlyList<OrderLine>>`, which loses `WithLines(l => l.WithCount(3))` (the lambda now receives a bare `IAny`). The documented path (`.As(...)` result is an `IAny<T>`) covers the retype, but not the loss of count refinement; I kept the pin `WithLines(value)` which is what my tests use. An `AnyList` factory taking a `Func<..>` or a `WithCount` on the retyped recipe would avoid this.
6. Unbounded money: the scaffold gives `Any.Decimal().GreaterThanOrEqualTo(0m).WithScale(2)`, which, per the numbers page, reaches `decimal.MaxValue / 100` on the tenth draw. Probe (deleted afterwards): computing `Any.Order().Generate().Total` 300 times threw `OverflowException` 112 times. No test of mine does that (arbitrary amounts are only compared, never summed), so the suite stays green, but a first property-looking test ("an order's total is not negative") would fail 3 times in 8. Honest reading: Money has no maximum, so the draw is valid and the domain overflows (recorded as a domain finding), not a library problem; I did not bound the generator to hide it.
7. `Any.OneOf("EUR","USD","GBP")` return type: I needed to declare it as a method return type in `Dummies.cs`; the docs only show `IAny<string>`/`var`-less usages with `Generate()`. I guessed `AnyOneOf<string>` and it compiled, but the type is not in the docs. Returning `IAny<string>` would have worked too (`DifferentFrom` is available on it); I kept the guess. Minor docs gap.
8. `Any.DateTime()` is unconstrained over the whole type including 10 percent limit draws, so a refused-deadline test that does `Any.DateTime().Before(anyPlacedAt)` could hit `DateTime.MinValue` and produce an empty domain. I bounded every instant with `Dummies.Instant()` (2000-2100) from the start, as the dates page recommends, so I never saw the failure; noting it because the scaffolded `AnyOrder` itself draws `placedAt`/`deliveryDeadline` over the full range (valid but extreme dates reach every default `Any.Order()` in other tests).
9. Style: the lambda-with-parameter convention (`p => p.WithCurrency(currency)`) read fine. `Any.Money()` / `Any.Order()` entry points via `--entry-point any` needed no extra using because the extension lives in `Shop.Domain` and my tests are in `Shop.Domain.Tests.Regular`.
10. Domain defects revealed while writing the cases (all kept as skipped tests): (a) `Money.ToString()` uses the current culture: under fr-FR `new Money(1234.5m,"EUR").ToString()` is `1234,50 EUR` (this one failed for real, seed 2056292743, the test draws nothing); (b) `Sku` accepts `"TSH-0042\n"` and `"TSH-٠٠٤٢"`; (c) `ShippingAddress` accepts postal codes `"75001\n"` and `"٧٥٠٠١"` (same `$`/`\d` pattern); (d) `GiftCard.Redeem(-10)` credits the card. MODEL.md documents (b)/(c) as intended pattern behaviour, but they are almost certainly not wanted.

## What worked well
- One `any generate A B C ... --entry-point any` run gave nine consistent generators; the graph of types composed itself (`OrderLine` -> `AnySku`, `AnyQuantity`, `AnyMoney`; `Order` -> `AnyShippingAddress`...).
- The `TODO(any)` mechanism: the build tells you exactly which guards to read, with file, line and the quoted statement; nothing silently wrong.
- `OrderedPair` for placedAt/deliveryDeadline was inferred correctly (strict) and pins bound the other side, which made the refused-deadline tests trivial.
- `With…` pin vs lambda split matches the "what the test is about vs what it needs" distinction; `Any.Order().WithLines(literal lines)` reads very close to intent.
- `[assembly: Reproducible]`: zero ceremony, seeds printed on the one real failure.
- Analyzers stayed quiet on the final code.

## Fluency: 4 / 5
Everyday use is smooth: scaffold once, resolve a handful of TODOs, tests read like specifications. I lose a point for the `dotnet test --project` / `global.json` stumble (undocumented for consumers) and for the cost of the two "tied draws" (postal code vs country, lines sharing a currency), where the escape hatch works but means editing the generated file's plumbing in several places and losing refinement overloads.
