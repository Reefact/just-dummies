# Regular notes — 15 hotel booking
Agent: the same model and effort as every session of this trial. Library: JustDummies 1.0.0-uxtrial.1 (packed from main).

## What I did
- Pages skimmed, in order: `PROJECT-README.md`, `guides/getting-started.en.md`, `packages/justdummies-xunit.en.md`, `packages/justdummies-cli.en.md` (the whole tool page: guards table, "Adjusting a parameter", "When a guard ties two parameters"), `generators/README.md`, `generators/strings.en.md` (Patterns section), parts of `dates-and-times.en.md` / `numbers.en.md`, `guides/composition.en.md` (OrderedPair).
- `Tests.Regular/Booking.Domain.Tests.Regular.csproj` from the template, `dotnet restore`, then
  `any generate Money RoomNumber GuestName StayPeriod CancellationPolicy GuestProfile Room Reservation --output Generators --entry-point static:Arbitrary`
  (8 generators + 8 `.Entry.cs`, root `Arbitrary`).
- Generators completed by hand:
  - `AnyMoney`, `AnyRoomNumber`, `AnyGuestProfile` (email, phone, nationality, loyalty number): regex guards replaced by `Any.StringMatching(...)`, retyped `AnyString` -> `AnyPattern` on the factory, the recipe field, the recipe constructor and the `Func` of the refining overload (the TODO comment names these four places exactly).
  - `AnyGuestProfile.dateOfBirth`: `Any.DateOnly().Between(1900-01-01, 2008-01-01)`.
  - `AnyRoom`: nightly rate `Between(0.01m, 10_000m)`; capacity depends on the type, so `Generate()` draws the type, then `_capacityRecipe.LessThanOrEqualTo(max(type))`; a pinned capacity (`WithCapacity(int)`) is honoured as is (bool `_capacityPinned` added).
  - `AnyReservation`: same idea for the guests (`WithCountBetween(1, room.Capacity)` unless pinned).
  - `AnyStayPeriod`: rewritten (`checkIn` + `nights` 1..30, `WithNights`) because the scaffolded `OrderedPair` cannot express the 30-night cap.
- Tests (159 methods, 301 cases; 295 green, 6 skipped as domain defects): `MoneyTests`, `RoomNumberTests`, `GuestNameTests`, `StayPeriodTests`, `CancellationPolicyTests`, `RoomTests`, `GuestProfileTests`, `ReservationTests`, plus `[assembly: Reproducible]`. Value-object boundaries, refusals with `ParamName`, order of checks, rounding, overlaps (half-open), state machine of `Reservation`, penalty boundary, `ConflictsWith`, and a "generator only draws valid values" test per generator (200-300 draws each).
- Result: green. Runs after the first green one: 12 + 25 fresh-seed runs, all green except 1 failure in the first batch (see friction 5, fixed and then 25/25 green).

## Frictions and surprises, in order
1. `dotnet test --project Tests.Regular` -> `MSBUILD : error MSB1001: Unknown switch. ... --project Tests.Regular` and then (plain `dotnet test Tests.Regular`) `Microsoft.Testing.Platform.MSBuild.targets(395,5): error : Testing with VSTest target is no longer supported by Microsoft.Testing.Platform on .NET 10 SDK and later`. The xUnit package page does not mention that on a .NET 10 SDK an opt-in is needed (`global.json` with `"test": { "runner": "Microsoft.Testing.Platform" }`). I added one at the workspace root. Docs: one line on the xunit page would save the trip.
2. `any generate ...` first run: `✗ Money: this project has not been restored, so its package references cannot be read. Restore it, then run the command again: dotnet restore`. Clear message, did what it says.
3. Tool recap is good but the `unread guard` of a *void* helper (`Validate(currency);` in `Money`) only says "unread guard at Money.cs, line 9: Validate(currency);": I had to open `Money.cs` to see it was a regex (the CLI page says a helper "the tool cannot see into" is flagged, but here the helper is in the same type and its body is a plain `Regex.IsMatch`). Fine, but a regex inside a same-type void helper stays opaque and the replacement pattern is not suggested (it is for an inline regex).
4. `RoomNumber` guard `Format.IsMatch(value)` (static readonly `Regex` field): flagged with the TODO text saying "a regex, "^[1-9][0-9]?[0-9]{2}[A-D]?$"": good, the pattern is quoted, I only had to drop the anchors.
5. A drawn value failed twice, both domain overflows (see findings): `Reservation.Cancel` -> `System.OverflowException : Value was either too large or too small for a Decimal.` (seed 350311511) because the scaffolded `Money` amount is `GreaterThanOrEqualTo(0m).WithScale(2)` and a draw can sit near `decimal.MaxValue`; and later `MoneyTests.A_negative_rate_is_refused` (`Any.Decimal().Negative()`, seed 1644796132) -> expected `ArgumentOutOfRangeException`, got `OverflowException`. The seed line in the output was immediately usable. Decision: the amounts/rates were dummies, so the domain has a hole (no upper bound on `Money`, `Cancel` mutates `Status` before computing the penalty). I bounded the rate in `AnyRoom` (a plausible price) and kept the revealing cases as skipped tests with the seed.
6. `StayPeriod`: the tool did notice `checkOut <= checkIn` and generated an `Any.OrderedPair(..., strict: true)` (nice), but the second guard (`> MaxNights` on the difference) then makes the pair draw invalid stays most of the time; it marks both parameters `to verify` and the build stops. The cheapest honest fix was to give up the pair and draw `checkIn` + `nights`; that means rewriting about 60 lines of generated code by hand and losing `WithCheckOut`. The docs cover this ("Draw a start and a duration") but the scaffolded `OrderedPair` machinery is then dead weight.
7. `Room.capacity` depends on `type` (switch expression): `to verify` on `type` and `capacity`, nothing suggested. The doc's four forms did not include "a bound computed from another parameter"; I used `_capacityRecipe.LessThanOrEqualTo(max)` inside `Generate()`. Works, but the pin has to be tracked by hand (a pinned field is just `Any.Fixed`, indistinguishable from a recipe) -> I added a `_capacityPinned` bool. Same for `Reservation.guests` vs `room.Capacity`. A `Then`-style helper in the scaffold for "parameter B depends on parameter A" would remove this.
8. After retyping to `AnyPattern`, the `<remarks>` XML comments still say `Func<AnyString, AnyString>` (stale doc comments, harmless).
9. A refinement lambda on a nullable parameter drops the `OrNull()`: `WithLoyaltyNumber(n => n)` always declares a number. This is documented ("a lambda describes a value, drawn without null") and I used it deliberately in a test; just noting it is subtle when reading `GuestProfile` tests.
10. `Any.Decimal().Negative()` and `Any.Decimal().Positive()` draw across the whole `decimal` range 1 draw in 10; the number page says so, but it is the day-to-day trap with `Money`: a "positive amount" dummy plus any multiplication overflows. I now bound money explicitly whenever the code multiplies.
11. Skipped tests: `[Fact(Skip = "...")]` is not itself a problem, but a `Skip` string with `\"` escapes made my first `sed` check clumsy; nothing for the library.
12. Caught myself: after toggling `Skip` with `sed` and restoring files from a copy, `dotnet build` did not rebuild (restored copy had an older mtime than the binaries) and 12 "runs" were of the wrong binary. Not the library's fault, noted because "fresh seeds each time" must really be a fresh build.

## What worked well
- `any` recap with the last column (`guard`, `AnyX`, `to verify`): all the int/decimal/enum/string-length guards, the `GuestName.MaxLength` constant (`.WithMaxLength(GuestName.MaxLength)`), `ThrowIfNegative`/`ThrowIfGreaterThan`, and the composed `new AnyGuestName()` / `new AnyRoom()` were right first time.
- The build-stopping `TODO_verify_...` sentinel is exactly what makes you read the constructor; the regex hint with the four places to retype was accurate.
- `Arbitrary.Reservation().WithRoom(...).WithStay(...)` style of tests: arranging only what the test is about, with the rest drawn, reads very well. Lambda refinement (`s => s.WithCheckIn(d).WithNights(5)`) composes through two levels.
- `[assembly: Reproducible]` + the printed seed made both revealed defects replayable and quoted in `Skip` messages.
- Pin errors surface at `Generate()` with the domain's own exception (`WithEmail("Not An Email").Generate()` throws `ArgumentException`), which makes "refusal" tests short.

## Fluency: 4 / 5
The scaffold plus the DSL kept the tests short and the arrange blocks honest; I rarely opened the docs after the first skim. Points lost for the .NET 10 `dotnet test --project` opt-in that is not documented, and for the cross-parameter rules (type/capacity, room/guests, check-in/nights) where the tool correctly refuses to guess but leaves a lot of hand-written generator code, including pin bookkeeping, that every user will rewrite.
