## Frictions and surprises, in order
1. **`any` before restore.** `any generate IataAirportCode ...` printed `✗ IataAirportCode: this project has not been restored, so its package references cannot be read. Restore it, then run the command again: dotnet restore`. Clear message, and the fix is one command, but the docs (`justdummies-cli.en.md`, "Requires") never say the project must be restored first. Expected: either a doc line or the tool restoring itself. Did: `dotnet restore`.
2. **`dotnet test --project Tests.Regular` does not work out of the box on the .NET 10 SDK.** First `MSBUILD : error MSB1001: Unknown switch ... --project`, then, with `dotnet test Tests.Regular`, `Testing with VSTest target is no longer supported by Microsoft.Testing.Platform on .NET 10 SDK and later ... opt-in to the new dotnet test experience`. The fix is a `global.json` with `{ "test": { "runner": "Microsoft.Testing.Platform" } }` at the root of W. Nothing in the user docs (xunit page, getting started) mentions it, although the test commands quoted in them are `dotnet test`. The brief gave the `--project` form, so the trial setup must carry it; a real team would hit this at day one.
3. **Rules tying two parameters of a value object are `to verify`, but only a hand-written `Generate()` removes the TODO cleanly.** `Route` (`origin.Equals(destination)`): both parameters marked, `TODO(any): ... — ties origin to destination`. The CLI page offers four forms; for a pair of the *same* type the `DifferentFrom` one fits (`_destination.DifferentFrom(origin)`), but that page's sample is `allele.Then(reference => allele.DifferentFrom(reference)...)` on a string, and I had to adapt it to the scaffolded fields (`_origin`/`_destination` are `IAny<T>`, which is why `DifferentFrom` there is the redrawing one, not the builder's). It worked at once; but the `With…` pins of `destination` still go through `_destination`, so `WithDestination(x)` with `x` equal to the drawn origin throws on some draws: the page does warn about that kind of consequence, good.
4. **Cross-parameter table lookups are unreadable to the tool, and the neighbour guard is dropped.** `Aircraft`: `MaximumSeatsByType.TryGetValue(typeDesignator, ...)` then `ThrowIfGreaterThan(seats, maximumSeats)`. The tool marks both `to verify`, but the `seats` row says `Any.Int32().Positive()` with nothing on the upper bound; I had to choose between a per-type seat count (hand-written `Generate()` with a copy of the table) and a conservative global bound. I took `Between(1, 78)` with a comment: valid for all types, but a 396-seat B77W is never drawn, and my generator now duplicates domain knowledge (the smallest maximum). No obvious tool fix, just noting the cost.
5. **`ThrowIfGreaterThan(blockTime, MaximumBlockTime)` is not read when the bound is a `private static readonly` field.** Flight row: `blockTime  TimeSpan  Any.TimeSpan().Positive()  to verify, guard, unread guards`. The docs say that a *public constant* is followed and a private/internal one "is copied as its value"; here it is a `static readonly TimeSpan` (not a `const`, `TimeSpan` cannot be), so the ceiling is simply lost and flagged. Expected given the page; mentioned because `TimeSpan` bounds in domain code are very often `static readonly`.
6. **Regex guards are `to verify` and I wrote the patterns myself; the marks are the hard one.** IATA/ICAO/designator were one-liners (`Any.StringMatching`) and the retype recipe on the CLI page (`AnyString` -> `AnyPattern`, 4 places) is accurate. For `AircraftRegistration` the constructor guard is a `switch` with a length cap, a first-character branch and two regexes; `any` marked it `to verify, unread guards` and kept `Any.String()`. I had to work out that a hyphenated mark must avoid a leading `N` and that the N-number pattern must stay within 7 characters (see domain finding D1). Nothing the tool could do here, but the `Any.String()` it leaves is a trap if the TODO is deleted without thinking: a random string would pass the TODO-free build and fail on nearly every run.
7. **A scaffolded `IcaoAirportCode` has reference equality, so `DifferentFrom` on `IAny<IcaoAirportCode>` can never exclude anything.** I wanted "two slots at different airports" and wrote `Arbitrary.IcaoAirportCode().DifferentFrom(first)` first in my head; because the domain type has no `Equals`, the redraw would accept the same code in a new instance. I caught it only because I had read `MODEL.md`. What worked: refine the value, `Arbitrary.IcaoAirportCode().WithValue(v => v.DifferentFrom(first.Value))`. A short remark in the `DifferentFrom` docs ("compares with the type's own equality; a class without `Equals` excludes nothing") would help; the CLI page says it for `Distinct()` only.
8. **xUnit1025 on a duplicated `InlineData`** (`14*60+59` and `15*60-1`) — xUnit's own analyzer, my slip. No JustDummies diagnostic fired on the whole project (Info rules never print in the build, as the docs say), so I do not know whether JD030 etc. would have said something.
9. **Minor: generated files live in namespace `Aviation.Domain`** (the target type's namespace) although they are in the test project. It works and is documented (`--namespace`), but my test project now has types in a production namespace; I kept it since the domain and the tests share `using` conveniences.

## What worked well
- One `any generate` call over eight types produced a compilable-after-edit graph: `Flight` picked `new AnyRoute()`, `new AnyAircraft()` ... on its own (`AnyX`), so only leaf generators needed thought.
- `to verify` + a non-compiling sentinel is exactly right for this domain: 11 guards that look harmless (`Validate(...)`, regex, `TryGetValue`) were all flagged, none silently wrong.
- The pin / lambda pair per parameter made tests read well: `Arbitrary.Flight().WithRoute(r => r.WithDistanceKm(1500))` (the distance band is the point, the rest stays arbitrary), `WithScheduledDeparture(...)`, `WithStart(...).WithDuration(...)`.
- `WithGranularity(5 min)` on `Any.DateTime()` produced valid `Slot` starts on the first try; draws are `Utc` as documented.
- `[assembly: Reproducible]` made every test seeded with zero per-test noise; no failure appeared, so I never needed a replay.
- `Any.ListOf(generator).WithCount(300)` made a cheap "generator hygiene" test.

## Domain findings (not fixed, per the brief)
- D1. `AircraftRegistration`: the N-number form `^N[1-9][0-9]{0,4}[A-Z]{0,2}$` admits up to 8 characters (`N12345AB`) but marks over 7 characters are refused first; the form and the cap disagree (tested as "too long": `N12345AB`).
- D2. `AircraftRegistration("")` throws `IndexOutOfRangeException` instead of `ArgumentException` (Skip-ped test).
- D3. `IataAirportCode("CDG\n")` and `FlightNumber("AF\n", n)` are accepted (`$` before a final line feed); the value then carries a newline (Skip-ped tests).
- D4. `Slot` accepts a start with sub-millisecond ticks (`NoonUtc.AddTicks(1)`) although it must start on a five-minute boundary (Skip-ped test).
- D5. `IcaoAirportCode` has no value equality while its sibling `IataAirportCode` does (Skip-ped test); `Slot.Overlaps` compensates by comparing `.Value`.
- D6. (not tested) `Flight.EstimatedDeparture`/`EstimatedArrival` throw `ArgumentOutOfRangeException` near `DateTime.MaxValue`, since `scheduledDeparture` is unchecked; my generator bounds it to 2020..2100.

## Fluency: 4 / 5
Everyday use is fluent: scaffold, fill in the `to verify` rows following the recipe on the CLI page, write tests with pins and lambdas, and the whole suite was green on the first run and stayed green on twelve more. The two points off are the start-up frictions the docs do not mention (project must be restored before `any`; the .NET 10 `dotnet test` needs an MTP opt-in) and the hand work that a domain full of regexes, a lookup table and cross-parameter rules inevitably costs: no tool surprise, but every `to verify` is real thinking.
