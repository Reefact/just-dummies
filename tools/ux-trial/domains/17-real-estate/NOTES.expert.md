Agent: the same model and effort as every session of this trial. Library: JustDummies 1.0.0-uxtrial.1 (packed from main).

## Frictions and surprises, in order
1. **`dotnet test --project Tests.Expert` does not work as given.** Output: `MSBUILD : error MSB1001: Unknown switch. ... Switch: --project`. The fallback `dotnet test Tests.Expert` gives `Microsoft.Testing.Platform.MSBuild.targets(395,5): error : Testing with VSTest target is no longer supported by Microsoft.Testing.Platform`. With .NET SDK 10.0.114 and `xunit.v3` 4.0.2 you need a `global.json` containing `{ "test": { "runner": "Microsoft.Testing.Platform" } }`; I created one in W. Neither the getting-started page nor the xunit adapter page says so (the adapter page only states the `xunit.v3` 4.0.2 floor). I expected the documented install to be enough to run the tests. Cost: a few minutes; I knew where to look, a newcomer might not.
2. **`any generate` before restore** stops with `✗ CadastralReference: this project has not been restored, so its package references cannot be read. Restore it, then run the command again: dotnet restore` (exit 2). Clear and actionable, but the getting-started/CLI pages do not mention it as a prerequisite. Ran `dotnet restore`, re-ran.
3. **The scaffolder gets the easy 80% right and says honestly where it did not.** `monthlyRent` → `Any.Decimal().Positive().WithScale(2)`, `price` → `.LessThanOrEqualTo(1000000000m)` with no mark, `documents` → `.WithMaxCount(Property.MaxDocuments)` referencing the public constant, `availableFrom/Until` paired in an `AnyOrderedPair` with pins. All correct. Good.
4. **`ArgumentOutOfRangeException.ThrowIfLessThan(registeredOn, signedOn)` is not recognised as an order between two parameters**, while `if (a >= b) throw` is (it paired `RentalListing`'s dates). The recap marked both `signedOn` and `registeredOn` `to verify` with the line quoted, and the TODO tells me to "write the rule" but the docs offer no copy-paste path that keeps the `WithSignedOn/WithRegisteredOn` pins working: the "derive inside `Generate()`" tip explicitly says the pins then stop reaching the draw. I ended up copying the pair/pin machinery from `AnyRentalListing.cs` into `AnyTransfer.cs` by hand. Expected: the throw-helper siblings (`ThrowIfLessThan/GreaterThan/LessThanOrEqual…` with two parameters) listed in the CLI page's table next to the single-parameter ones, or a documented recipe for pinning an ordered pair by hand.
5. **A regex guard plus a second guard on the same parameter.** Recap: `value: first unread guard at CadastralReference.cs, line 16: if (!Format.IsMatch(value)) { ..., and 1 more`. The "1 more" (`EndsWith("0000")`) is not named, so the TODO's advice ("`Any.StringMatching(pattern)` replaces the base") would produce a generator that fails about 1 draw in 10 000 (`…0000`) — a rare, seed-dependent failure far from its cause. I only caught it because I read the constructor. Expected: name every unread guard (or at least the second one's line) when there are two; the TODO says "; and 1 more" yet the whole point of the TODO is to spare me from searching the constructor.
6. **Retyping `AnyString` to `AnyPattern`** was exactly the four edits the TODO listed (field, `AnyValid…()` return type, private ctor parameter, `Func<…>` of the refining overload; plus the `<remarks>` doc text which I also updated). It compiled the first time. The instruction was accurate; it is just a lot of mechanical edit for a one-line change of intent.
7. **`Math.Round(squareMeters, 2) != squareMeters` is unread and `AnyDouble` has no scale.** The recap shows a base that `Surface`'s constructor refuses on nearly every draw (`Any.Double().Positive().LessThanOrEqualTo(Surface.MaxSquareMeters)` — any double has more than two decimals), with the sentinel stopping the build. I wrote `Any.Decimal()….WithScale(2).As(d => (double)d)`. Consequences: the factory is now an `IAny<double>`, not an `AnyDouble`, so a test cannot write `.WithSquareMeters(s => s.Except(x))` (`CS1061: 'IAny<double>' does not contain a definition for 'Except'`); I used `.DifferentFrom(x)` (documented as the redraw form for any generator) and it worked. The scaffolder does recognise the `decimal` twin (`decimal.Round(p, 2) != p` → `.WithScale(2)`); it does not recognise `Math.Round(double, 2)`. Idea: say in the recap that a `double` has no scale and point to the decimal-then-widen recipe.
8. **Derived parameter (`declaredRating` must equal `Rate(energy, emissions)`).** All four parameters came out `to verify`, each pointing at the same line 22. That is the right alarm, but the scaffold's shape (four independent `With…` pairs, `Generate()` calling the constructor with four draws) is wrong for the whole type and I rewrote the file rather than "verifying" anything. The docs' "derive one draw from another inside `Generate()`" paragraph covers it conceptually; what it does not say is that for a *derived* parameter the generated `With…` methods become dead API that should be deleted (I deleted them and offered `WithRating(...)` instead). Not a defect, a documentation gap: one sentence would do.
9. **Value that depends on a drawn aggregate (`property.CanBeLetOn(availableFrom)`).** The recap line `property: unread guard … — ties property to availableFrom` is excellent: it names the tie. The fix is again "rewrite `Generate()`": draw the property first, then the dates from its diagnosis. Worked after one iteration; the 75 repeated runs never produced an invalid listing.
10. **Private `AnyValid…()` factories**: I needed a valid issue date in tests (`AnyEnergyPerformanceDiagnosis.ValidIssuedOn()`). The page's tip (one `internal static` line in a `.Custom.cs` partial) worked verbatim. Pleasant.
11. **`Any.OrderedPair(Any.DateOnly(), Any.DateOnly())`** is the right tool for "two dates in order" in a test that builds a `Transfer` by hand (refusals of the price, null parcel). It is easy to find in the composition page, but nothing in the generator reference table (`generators/README.md`) lists it, so I found it only because the CLI page and the generated `AnyRentalListing.cs` used it. Idea: list `Any.OrderedPair` in the "Composition" table of the reference index.
12. **Analyzers were silent on my code**: `dotnet build` ends with `0 Warning(s) 0 Error(s)` every time; the only diagnostics I saw were xUnit's (`xUnit1009`, `xUnit1025` on a duplicated `InlineData` of mine). I did not look for JD diagnostics on purpose; I note only that I never needed one.
13. **`Any.Enum<PropertyKind>().Except(PropertyKind.Commercial)` as `anyResidentialKind`**: this is where I applied the "is it a dummy?" test most carefully. In the letting-calendar theory the assertion is about the rating and the dates; whether the housing is a House or an Apartment must not matter, so the kind is drawn and named `anyResidentialKind`. It is the one draw in this suite that could reveal a hidden dependence (an Apartment-only bug), which is exactly the docs' argument for drawing it. No failure in 75 runs.
14. **One of my own mistakes, and how the suite told me**: `[InlineData(1, 8.00, 0.13)]` for `PricePerSquareMeter` (1/8 = 0.125, an even-rounding midpoint, 0.12). The failure message was clear (`Expected: 0.13 Actual: 0.12`) and the seed line was printed even though the value was a literal (`[JustDummies] These arbitrary values were seeded with 1644634930…`), which is harmless but slightly noisy: the failing case drew nothing relevant. I moved the midpoint into the dedicated midpoint theory.
15. **Weight of the generated files.** 14 files, 1 247 lines for 7 types, of which about 85% is `With…` plumbing I use for maybe a third (pins on parcel, kind, rating, issue date, rent, price, dates, area). It is "code I own", but the reading cost is real: after hand-editing six of them I was spending most of the time in the 150-line files to change 10 lines. I did not find anything wrong with the generated code itself; it compiled warning-free.

## What worked well
- The `to verify` / sentinel design earns its keep: every one of the seven guards the tool could not read (regex, Unicode `\d`, rounding, `void Validate`, derived rating, throw-helper order, date/property tie) would have made a plausible but wrong generator. None slipped through silently. The only gap is #5, where "and 1 more" hides what the second guard is.
- `[assembly: Reproducible]` plus `TheoryData<…, DateOnly, …>`: one line, every case gets its own seed, nothing to wrap, and a failing draw printed `Reproduce this run with [JustDummies.Xunit.Reproducible(Seed = …)]`.
- The documents' rule "if an `anyXxx` reaches the assertion it is not a dummy" was easy to apply as a design check: boundaries, thresholds and midpoints are literals in `InlineData`; parcels, document links, kinds that do not matter, issue dates, signing dates (bounded before `AddDays`, as the date page recommends) are drawn. Where equality needs a value, the second value is drawn with `DifferentFrom(first)`, not hoped to differ.
- `Any.Uri().Web().UsingHttps()`, `Any.Decimal().WithScale(2)`, `Any.OneOf`/`.Enum().Except`, `DistinctBy`, `WithCountBetween(0, 19)` and `OrderedPair` all did what the pages said, first time. No generator ever threw a `ConflictingAnyConstraintException` or `AnyGenerationException` in 75+ runs of ~100 draws each.
- The `With…(Func<…>)` refinement idiom reads very well in tests: `Any.Property().WithDiagnosis(d => d.WithRating(r).WithIssuedOn(date)).Generate()` states exactly the two things the letting test cares about and nothing else.
- Domain defects were cheap to pin down because everything else was a dummy: three skipped tests, each re-run un-skipped to confirm the failure reason.

## Fluency: 4 / 5
The core loop (read the recap, fix the red line, write `Any.X().WithY(...)`) is fast and the generated API reads well in tests, and I never fought a draw or a flaky outcome. I deduct one point for the friction concentrated in generator completion: three of the seven types needed a rewrite of `Generate()` (derived rating, date/property tie, ordered dates behind a throw helper), the docs describe the idea but leave the plumbing to copy-paste, and #5 shows a TODO that under-reports what must be satisfied. Add the `dotnet test --project` setup gap (#1), which has nothing to do with the library but is on the first page of anyone's trial.
