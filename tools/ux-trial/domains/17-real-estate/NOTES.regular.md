## Frictions and surprises, in order
1. `any generate ...` on a fresh test project: `✗ CadastralReference: this project has not been restored, so its package references cannot be read. Restore it, then run the command again: dotnet restore`. Clear message, one extra command; I just ran `dotnet restore`.
2. `dotnet test --project Tests.Regular` (the command given in the brief and in the CLAUDE-style docs) fails on this .NET 10 SDK: `MSBUILD : error MSB1001: Unknown switch ... --project`. Without a `global.json` selecting the Microsoft.Testing.Platform runner, plain `dotnet test Tests.Regular` fails too: `Testing with VSTest target is no longer supported by Microsoft.Testing.Platform on .NET 10 SDK and later`. I created `W/global.json` with `{ "test": { "runner": "Microsoft.Testing.Platform" } }` and then `dotnet test --project` worked. Not a JustDummies bug, but the xunit adapter page says nothing about it and every consumer of xunit.v3 4.0.2 on .NET 10 hits it.
3. The scaffolded `Surface` recipe `Any.Double().Positive().LessThanOrEqualTo(Surface.MaxSquareMeters)` was tagged `to verify, guard, unread guards` on the `Math.Round(x, 2) != x` guard. That is honest, but the docs' table has the `decimal.Round(p, 2) != p` row (-> `.WithScale(2)`) and no `double` counterpart (the library has no `WithScale` on `double`), and there is no hint of what to do: I had to find "draw an integer of hundredths and divide" myself. A one-line suggestion in the TODO comment for a rounding guard on a `double` would have saved a few minutes.
4. `Transfer`: `ArgumentOutOfRangeException.ThrowIfLessThan(registeredOn, signedOn)` is marked `to verify` for both dates while the very same relation written as `if (availableFrom >= availableUntil)` in `RentalListing` got a full `Any.OrderedPair` (docs list `ThrowIfNegative` and siblings, not `ThrowIfLessThan/GreaterThan` between two parameters). I hand-copied the OrderedPair scaffolding (~50 lines: pins, copy constructor, recipe refinements) from `AnyRentalListing` into `AnyTransfer`. Costly and error-prone; a `ThrowIf{Less,Greater}Than(a, b)` between two parameters of one type is the same shape as `if (a < b) throw`.
5. A derived parameter (`declaredRating` must equal `Rate(energy, emissions)`): the tool marks all three parameters `to verify` with the same pointer ("if (computed != declaredRating)") and the file does not compile. Correct and expected, but the repair means deleting the parameter's field, recipe, two `With...` methods, constructor arguments and the factory by hand (five places), then adding the derivation to `Generate()`. I did it with a script. A documented "derived parameter" recipe in the CLI page (like the check-digit one) would help: the page covers ties between parameters, check digits and durations but not "this argument is a function of the other arguments".
6. `With...(Func<...>)` only: `Any.Property().WithDocuments(Any.ListOf(Any.DocumentLink()).WithCount(2))` -> `CS1503: Argument 1: cannot convert from 'JustDummies.AnyList<DocumentLink>' to 'IReadOnlyList<DocumentLink>'`. This is documented (no `With...` takes a generator) and the lambda form `WithDocuments(l => l.WithCount(2))` was the answer, and nicer since it keeps the `DistinctBy` of the base. The compiler message alone does not say so, though; I remembered it from the docs.
7. A pinned object goes through `Any.Fixed`, so `Any.Property().WithDiagnosis(someDiagnosis)` and then a test that uses a default `Any.Property()` with explicit dates failed on the first run in 7 tests with `InvalidOperationException: That property may not be let on that date`. That was my mistake (I used `Any.Property()`, whose diagnosis is arbitrary, in tests that build a `RentalListing` by hand with literal dates; the arbitrary diagnosis was not valid then). The seed and the stack trace made it obvious, and I introduced `Any.Property().Lettable()`. No friction with the library here, just worth noting that the dummy was not a dummy for those tests.
8. `Any.Int32().Except(0, 1, 2, 3, 4)` cast to an enum to build an undefined `DocumentKind`: fine, but there is no `Any.UndefinedEnum<T>()` or the like; I hard-coded the declared members, which breaks silently if a member is added. (Idea, not a bug.)
9. The seed report works as advertised: `[JustDummies] These arbitrary values were seeded with 3995. Reproduce this run with [JustDummies.Xunit.Reproducible(Seed = 3995)].` and pasting it on the attribute reproduced the overflow exactly (see domain findings).
10. Info diagnostics (JD030 etc.) never showed in `dotnet build`, as documented; I did not raise their severity, so I cannot say what they would have said about the scaffolded `Any.String()` / `Any.Int32()` calls.

Domain findings (kept as tests, see `Skip`):
- `RentalListing`: `MonthlyRent` has no ceiling. `MaximumDeposit` (3 x rent for `Commercial`) throws `OverflowException: Value was either too large or too small for a Decimal` when rent > `decimal.MaxValue / 3`. The scaffolded base `Any.Decimal().Positive().WithScale(2)` hits it in about 2 % of listings (66 / 3000 in a probe); `The_figures_of_any_listing_can_be_computed` is `Skip`ped with "domain defect: ..., seed 3995" and `[Reproducible(Seed = 3995)]`.
- `CadastralReference`: `"75056 000 AB 0000\n"` is accepted: `$` matches before the final line feed (documented in the model) but then `EndsWith("0000")` is false, so the "plan number starts at 0001" rule is bypassed. `A_plan_number_of_zero_followed_by_a_line_feed_is_refused` is `Skip`ped. The documented acceptance of a trailing LF and of non-ASCII digits is pinned by `The_regular_expression_is_applied_as_written`.
- Not tested, observed with a scratch test: `Surface.Add(null)` and a `null` item in `Property`'s documents both throw `NullReferenceException` (not `ArgumentNullException`); `Surface.ToString()` is culture dependent (`"12,50 m2"` under fr-FR); `DocumentLink.FileName` for `https://h.example/a/b/` is `"b/"` (the trailing slash is kept).

## What worked well
- One `any generate` command for 7 types, with `--entry-point any`, gave `Any.Property()`, `Any.Transfer()`... and the recap table told me exactly which rows to look at; the `to verify` + "does not compile until you resolve it" contract worked: I could not forget a TODO.
- Composition through the type's own generator (`new AnyCadastralReference()` inside `AnyTransfer` and `AnyProperty`) meant one regex for the whole domain.
- Lambda refinements (`WithDiagnosis(d => d.WithIssuedOn(...))`, `WithProperty(p => p.WithKind(...))`, `WithDocuments(l => l.WithCount(19))`) keep the base invariants and make the test read as only what it cares about.
- `Any.OrderedPair(..., strict: true)` for "an earlier and a later date" in the refusal tests; `DifferentFrom` on a scaffolded generator; `DistinctBy`.
- Reproducibility: `[assembly: Reproducible]` once, failure prints the seed, replay by attribute worked first time.
- Build output was clean: no analyzer warning at all on ~120 tests.

## Fluency: 4 / 5
The scaffold plus lambda refinements make most of the work routine, and the seed report paid for itself on the first real defect it revealed. What cost time was in the places the tool cannot read: a derived parameter (rating), a `ThrowIfLessThan(a, b)` between two parameters (hand-copying the OrderedPair scaffolding) and a rounding guard on a `double`, plus the `dotnet test --project` / MTP runner setup on the .NET 10 SDK that nothing in the docs mentions.
