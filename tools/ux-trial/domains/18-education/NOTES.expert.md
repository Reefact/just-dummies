## Frictions and surprises, in order
1. **`dotnet test --project Tests.Expert` does not work in this workspace.** Exact output: `MSBUILD : error MSB1001: Unknown switch. ... Switch: --project`; and `dotnet test Tests.Expert` gives `Testing with VSTest target is no longer supported by Microsoft.Testing.Platform on .NET 10 SDK and later ... opt-in to the new dotnet test experience`. The .NET 10 SDK needs `{"test": {"runner": "Microsoft.Testing.Platform"}}` in a `global.json`; the workspace had none. I created `W/global.json` (inside W). A real consumer would hit this with the template csproj the brief prescribes (and the xUnit adapter docs do not mention it). Not a library defect, but the "getting started" page never shows the test-runner side.
2. **`any generate` needs a prior `dotnet restore`.** `✗ StudentNumber: this project has not been restored, so its package references cannot be read. Restore it, then run the command again: dotnet restore`. Clear and actionable; I expected it to just work after `dotnet new`-like setup but the message is exactly right.
3. **Generated files live in the domain's namespace by default** (`namespace Education.Domain;` in a test project; "in namespace Education.Domain (--namespace to change)"). Fine for `Any.Course()` discovery (no `using` needed beyond the domain's), but it puts test code in the production namespace; I kept the default.
4. **A void `Validate(...)` helper marks every parameter `to verify`.** `Student`'s constructor calls `Validate(number, fullName, birthDate);` so the three rows are `to verify, unread guards` and three sentinels block the build, although the helper's guards (null, blank, length, date floor) are all of the shapes `any` reads in a constructor. The doc says a void helper is "marked as before", so it is documented; the cost is that I wrote `NotBlank().WithMaxLength(100)` and the date floor by hand. Also the recap line `birthDate: unread guard at Student.cs, line 6: Validate(...)` points at the call, not at the guard that matters.
5. **`Semester`: the scaffold produces something that compiles after deleting the sentinels but is wrong.** After removing the three sentinels, `Any.Semester().Generate()` would draw year, term and start independently and fail on `start.Year != expectedStartYear` most of the time. The tool did flag them (`to verify, guard, unread guards`, "first unread guard ... and 1 more"), which is honest, but the comment only says "verify against Semester.cs, line 12 ... then delete these two lines": it does not say that the three parameters are tied together. There is no extension point for "this parameter depends on that one" besides editing the generated `Generate()`, which I did. The scaffolded `OrderedPair(start, end)` is then built in the constructor (a field), so I had to remove that field to make the start year-dependent. That is a real rewrite of generated code; `--force` would erase it (the header warns of this, and the type is `partial`, but the method I changed is in the generated file, not a neighbour).
6. **A rule across the elements of a list (`sum(credits) <= 36`) cannot be expressed.** `Enrolment` caps the credits of 1-8 courses at 36. The scaffold only knew the count (`WithMaxCount(Enrolment.MaximumCourses)`) and the sentinel mentioned "and 1 more" guard. The only constructive options were a hand-written `IAny<List<Course>>` or narrowing every course (I chose `Between(1, 4)` credits, so no draw can exceed 36 but the dummy never contains a course worth 5+ credits). I documented it in a comment; this silently narrows what the Enrolment dummies exercise.
7. **Retyping `AnyString` to `AnyPattern` is manual and mechanical** (field, private ctor, `WithX(Func<...>)` overload and the remark in the XML doc) in `AnyCourse` and `AnyStudentNumber`. The TODO text says exactly what to change, so it went fast; but it is 4-5 edits per regex parameter, by hand. A scripted `--regex` or accepting the pattern as an argument would remove them.
8. **`StringMatching` base on the `^...$`-anchored pattern.** I copied the domain's anchored pattern (`^STU-(19|20)\d{2}-\d{5}$`) and it was accepted; the docs list `^...$` as supported. No friction, noted because it is the natural copy-paste.
9. **Unconstrained `Any.DateOnly()` spans 0001-9999**, so after bounding by the domain's invariants only (`>= 1900-01-01`) a drawn student is born anywhere up to year 9999, and a drawn semester can end up to 7,900 years after it starts (observed with a probe: max end-start year gap 7924, max birth year 9993). Valid by the constructor's rules, and a dummy is indifferent to it; but it shows that the domain has no upper bound on birth dates (see findings). Not a library problem, a consequence of "valid for the declared constraints".
10. **Analyzers stayed silent.** No JDxxx diagnostic appeared at all in the build of the suite (I checked the build output for warnings). Nothing to report, but also no feedback on e.g. the `Between(1, 4)` narrowing.
11. **Output of a skipped test is noisy but fine** (`skipped ... (0ms)` then the reason and a long path). The `Skip` text I wrote ("domain defect: ..., seed ...") appears verbatim, which is good.

## What worked well
- The scaffold was a very good first draft: course title/credits (`NotBlank()`, `Positive().LessThanOrEqualTo(30)`), the Grade range referencing `Grade.Maximum`, the courses `WithMaxCount(Enrolment.MaximumCourses)`, the composed `new AnyStudent()` / `new AnySemester()` in the aggregate, and the ordered start/end pair for `Semester`, all inferred without help.
- `TODO_verify_...` sentinels are the right design: the build named every gap, with the guard quoted and, for regexes, the exact retype to perform.
- `With...` methods read well in tests: `Any.Course().WithCode("ZZZ999")`, `Any.Enrolment().WithCourses(courses)`: the courses are the significant part, student/semester stay drawn and invisible. The `anyXxx` naming rule made me notice at once which values reach the assertion (almost all of the value-object tests ended up with literals; the dummies live in the constructor-refusal tests and the aggregate arrangement).
- Reusing the owner generators for the "other" arguments (`Course anyCourse = Any.Course().Generate(); new Course("bad", anyCourse.Title, anyCourse.Credits)`) means no test repeats an invariant.
- `[assembly: Reproducible]` worked without any other setup, and a red test prints `[JustDummies] These arbitrary values were seeded with 949906840. Reproduce this run with [JustDummies.Xunit.Reproducible(Seed = 949906840)].` in its output; the 15 repeated runs were all green.
- Error messages from the generators were never needed (no conflict raised).

## Fluency: 4 / 5
The docs plus the scaffolder got 5 of 6 generators to a working state within minutes, and the tests then wrote themselves around literals for what is verified and drawn objects for what is merely required. Points lost: the test-runner setup (`global.json`) is outside the library but blocks the very first run; the rules that tie parameters together (Semester's year/term/start, Enrolment's credit sum) have no declarative home in the scaffold and cost a hand-rewrite of generated code that `--force` would erase.
