## Frictions and surprises, in order
1. **`dotnet test --project Tests.Regular` does not work out of the box.** Command: `dotnet test --project Tests.Regular` -> `MSBUILD : error MSB1001: Unknown switch. ... Switch: --project`; with `dotnet test Tests.Regular` -> `error : Testing with VSTest target is no longer supported by Microsoft.Testing.Platform on .NET 10 SDK and later. If you use dotnet test, you should opt-in to the new dotnet test experience`. I expected the xUnit v3 `Exe` test project + the documented command to just run. Fixed by adding a `global.json` with `"test": { "runner": "Microsoft.Testing.Platform" }` in W. Neither the xunit adapter page nor the getting-started page mentions it (it is an xunit.v3 / .NET 10 SDK matter, but the docs install section says the adapter "is all you need"). Cost: 5 minutes.
2. **`any generate` needs a prior `dotnet restore`.** Output: `✗ StudentNumber: this project has not been restored, so its package references cannot be read. Restore it, then run the command again: dotnet restore`. Clear and actionable; I just had not restored yet. Not a defect, a small speed bump (the CLI page could mention it in the "Run it from your test project" paragraph).
3. **Every constructor with a regex, a `%`, a `switch` or a `Validate(...)` helper comes out `to verify` and does not compile — 5 of 6 types here.** `StudentNumber`, `Course` (regex), `Grade` (`value % 0.5m != 0m`), `Semester` (switch expression + cross-parameter year rule), `Student` (all three parameters flagged because the guards sit in `private static void Validate(...)`), `Enrolment` (`Select(...).Distinct()`). That is documented and the sentinel/comment per parameter is precise. But some are cheap to improve:
   - `value % 0.5m != 0m` is *the* "multiple of" guard and has a one-line equivalent (`MultipleOf(0.5m)`) that the docs themselves list for decimals; the tool does not read `%` (it is listed under "arithmetic condition").
   - The `Validate(number, fullName, birthDate)` void helper is marked on all three parameters, though only `fullName` and `birthDate` are tested in it (`ThrowIfNull(number)` is a plain null guard). The message says "every parameter is marked here", as documented; but the recap rows show `to verify, unread guards` for `number`, whose recipe `new AnyStudentNumber()` was already right.
4. **Retyping `AnyString` -> `AnyPattern` is mechanical but manual.** The sentinel comment says exactly where (the factory, the recipe field, the recipe constructor parameter, the `Func` of `WithX`), which is helpful, and the file builds as soon as all four are done. In `AnyStudentNumber` (one parameter) a global replace was enough; in `AnyCourse`, where `title` stays an `AnyString`, I had to pick lines one by one (field, factory, constructor parameter, and the two doc-remark/`Func` lines of `WithCode`) and I had to build to be sure I had them all. A tool option that applies the retype when the regex is inside the supported subset would save this edit. (idea, low)
5. **No way to add an entry point to an already-scaffolded generator without `--force`.** `any generate Grade --output Generators --entry-point any` -> `✗ .../Generators/AnyGrade.cs already exists. Re-run with --force to overwrite it. Whatever you changed in it is lost.` I had already hand-edited the generators before deciding to want `Any.Grade()`. Workaround: scaffold all types into a scratch folder outside the project with `--entry-point any` and copy only the `*.Entry.cs` files. Expected: `--entry-point` to write the second file and leave the first alone when it exists (the doc says the generator "is byte-identical whichever of the three you ask for"). (friction/idea)
6. **`Semester` is beyond what the scaffold can express and the OrderedPair machinery gets in the way.** The scaffold treated `start`/`end` as an ordered pair (good, that part was exactly right: `start < end`, strictly) but the year rule couples `start` to `academicYear` and `term`, which are separate parameters. After removing sentinels the file compiled and ... would have drawn semesters whose start year is unrelated to the academic year (I did not run that version; the constructor would refuse almost all of them), failing only at run time. I rewrote `Generate()` by hand (draw year and term, then start inside the implied year, then end after it) and dropped the pair field. That cost the most time of the whole exercise (~15 min); a documented pattern for "a parameter whose valid range depends on two others" in the composition guide would have helped (the docs show `Any.OrderedPair` and `Any.Combine`/`As`, but I did not find an example of dependent draws inside a scaffolded `Generate()`). (docs)
7. **`DateOnly` unconstrained draws span the whole type, so an `end` drawn `.After(start)` can land in year 9xxx.** Valid for the constructor (no upper bound) and documented ("An unconstrained draw spans the whole type"), just surprising when I printed a semester while debugging. Not a defect; no action taken.
8. **`\d` in the domain's regex vs the generator.** The domain uses `\d`, which in .NET matches any Unicode digit; I wrote `[0-9]` in the generator pattern on purpose so the draws stay in the domain's intended ASCII world, and wrote the Unicode case by hand as a literal (it revealed the `IntakeYear` defect below). The `any` comment suggests `Any.StringMatching("...")` as the replacement but says nothing about `\d` vs `[0-9]`; I did not test what `Any.StringMatching(@"\d")` draws.

Domain defects found (both kept as skipped tests, both deterministic so no seed):
- **StudentNumber.IntakeYear throws FormatException** for a number accepted by the format with non-ASCII digits: `new StudentNumber("STU-20٢٥-00042").IntakeYear` -> `System.FormatException : The input string '20٢٥' was not in a correct format.` (`\d` accepts Arabic-Indic digits; `int.Parse` does not). Test: `StudentNumberTests.A_number_accepted_by_the_format_has_a_readable_intake_year` (skipped). MODEL.md states the `\d` behaviour but not its consequence.
- **Enrolment constructor lets a null course escape as NullReferenceException** (`courses.Select(course => course.Code)`), instead of an `ArgumentException` like every other malformed list. MODEL.md says "null items are not checked", so this is by design; flagged low. Test `EnrolmentTests+Construction.A_null_course_in_the_list_is_refused_with_an_argument_exception` (skipped).
- Documented behaviours I pinned with characterisation tests rather than called defects: a trailing `\n` is accepted by both the student number and the course code (`$` before a final line feed); `Average()` is rounded half away from zero and `IsPassed`/`Honours` read the rounded value; `Course(null, …)` raises `ArgumentException` not `ArgumentNullException`.

## What worked well
- The `any` recap is excellent as a work list: each `to verify` points at the file, the line and the guard text, and the sentinel makes the build stop at exactly the parameter to finish. Nothing plausible-but-wrong was drawn behind my back.
- Inferred guards were right where they were read: `title` -> `NotBlank()`, `credits` -> `Positive().LessThanOrEqualTo(30)`, `Grade.Maximum` kept as the named constant, `Enrolment.MaximumCourses` kept as the named constant, composed types drawn through `new AnyStudent()` / `new AnySemester()` / `new AnyStudentNumber()`.
- `WithX(lambda)` refining the valid base (`WithCredits(c => c.Between(1, 4))`, `WithCode(c => c.DifferentFrom(...))`, `WithValue(v => v.DifferentFrom(...))`) made equality/inequality tests read cleanly, with the unrelated fields staying arbitrary.
- `[assembly: Reproducible]` + the seed in failure output: zero ceremony.
- `Any.ListOf(...).WithCount(n).DistinctBy(...)` gave distinct course codes in the test builder with no retry loops.
- `.Alpha().WithLength(n)` / `WithLengthBetween` made the name length boundary tests (100/101, padded 98+2) trivial and honest: the length is the literal, the letters are arbitrary.
- 12 repeated runs, 182 cases each, never failed; draws never contradicted a test, so every drawn value was indeed a dummy.

## Fluency: 4 / 5
I could build almost everything from memory and the tool's recap; the guard-driven scaffold plus `AnyValid…` factories is a fast loop and the dummy/literal split came naturally (credits and grades literal, student/semester/codes/titles drawn). I lose a point for the daily-work costs: the `dotnet test --project` setup on .NET 10 (needs a `global.json`), the entry point being impossible to add without `--force`, the manual `AnyString` -> `AnyPattern` retype, and above all the lack of guidance for a dependent-parameter generator like `Semester`, where the scaffold compiled after sentinel removal but would have drawn invalid values at run time.
