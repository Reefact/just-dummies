## Frictions and surprises, in order
1. **`dotnet test --project Tests.Expert` does not work as given.** Exact output: `MSBUILD : error MSB1001: Unknown switch. ... Switch: --project`. Plain `dotnet test Tests.Expert` then says `Testing with VSTest target is no longer supported by Microsoft.Testing.Platform on .NET 10 SDK and later ... opt-in to the new dotnet test experience`. The fix is a `global.json` with `{"test":{"runner":"Microsoft.Testing.Platform"}}` at the workspace root, which I created. Nothing in the xUnit adapter page says an xUnit v3 test project needs it on the .NET 10 SDK. Docs gap rather than a library defect, but it is the first thing a new user meets.
2. **`any generate` before restore:** `✗ SiteId: this project has not been restored, so its package references cannot be read. Restore it, then run the command again: dotnet restore`. Clear and actionable; I ran `dotnet restore` and went on.
3. **Everything but `Site` stops the build, by design, and the sentinels were useful.** Nine of ten generators had at least one `to verify`; for a domain made of regex-validated value objects that is honest. The `[GeneratedRegex]` pattern was resolved and quoted in the TODO (`a regex, "^[A-Z]{3}-[0-9]{2}$": Any.StringMatching(pattern) replaces the base and returns an AnyPattern, so retype AnyString to AnyPattern here, on the recipe field, in the recipe constructor and in the Func of WithValue`). I followed the recipe literally and it compiled at once. Retyping touches four places per generator; I did it with a script. A one-flag "use this pattern" would help, but the instructions were exact.
4. **`WorkingHours`: a plain order between two `TimeOnly` parameters is not paired, and the recap does not say why.** The tool wrote `opens Any.TimeOnly() to verify, unread guards` / `closes ...` with `first unread guard at WorkingHours.cs, line 14: if (closes <= opens) ...`. The CLI page promises `Any.OrderedPair` for `a >= b` between two parameters of one ordered type, and the reason it does not apply (a time of day wraps at midnight, so it has no pair) is only on the dates-and-times and composition pages. I expected either a pair or a sentence saying a `TimeOnly` pair is deliberately not offered. I wrote two disjoint ranges (opens 06-11, closes 15-22), which is valid by construction but narrower than the domain.
5. **`ShiftRequest`: a derived parameter forces edits in the generated file.** The domain ties `endTime` to `startTime` by an arithmetic length (1-12 h, wrapping midnight), which the tool rightly marks (`startTime: first unread guard ..., and 3 more`). The CLI page's remedy (derive one draw from another inside `Generate()`) is right, but to keep a `With...` for the length I had to rename a field, its recipe, its copy-constructor lines, both `With...` overloads and `Generate()`, all in the generated file, which `--force` will overwrite. The doc suggests a `partial` neighbour for added overloads; there is no seam for changing what `Generate()` draws. I accepted the cost; a documented partial hook (or an extension point for "tied" parameters) would make this survive re-scaffolding. `idea`.
6. **Compile error when I passed a generator to a `With...`:** `Any.Site().WithId(Any.SiteId().DifferentFrom(home.Id))` gave `CS1503` (cannot convert `IAny<SiteId>`). The CLI page says so in "When the lambda is not enough"; I had skimmed past it. The working spelling is a pinned value (`.WithId(Any.SiteId().DifferentFrom(home.Id).Generate())`). Cost: one build.
7. **Draws needed to be distinct across one scene.** Two sites or two employees of one roster must not collide on ids; independent `Generate()` calls collide with probability about 1e-6 (sites) which is small but not zero. `Any.ListOf(Any.SiteId()).WithCount(8).Distinct().Generate()` worked first time (JD028 is satisfied because the ids override `Equals`). Drawing ids up front into a queue is a pattern I would like to see in the composition page; I had to invent it.
8. **A scaffolded `ShiftRequest` is valid for its constructor, not for `Shift`.** First version of my Shift tests used `Any.ShiftRequest().WithSite(...)`: a date near 0001-01-01 or 9999-12-31 overflows `TimeZoneInfo.ConvertTimeToUtc`, and a drawn time can fall in the site's gap, so the test would have failed on a rare seed. I caught it by reasoning before running, not by a failure. This is the library behaving correctly (the constraint belongs to the zone-and-request pair, not to the request), but the tool offers nothing for a "pair" like `Shift(site, request)`: `any generate Shift --dry-run` correctly flags `ties site to request, and 1 more` and would leave me to write it. I wrote a one-line helper (`QuietPeriod.AnyShiftAt`) instead of scaffolding.
9. **`Reproducible` reports a seed for a test that drew nothing.** The literal-only failure for `"PAR-01\n"` printed `[JustDummies] These arbitrary values were seeded with 1486533581. Reproduce this run with [JustDummies.Xunit.Reproducible(Seed = 1486533581)].` On an assembly-level `[Reproducible]` this is expected, but it reads as if a draw were involved. Harmless noise, `idea`.
10. **Pinning `null` on a string `With...` needs a cast** (`WithFullName((string)null!)`) because `WithFullName(null)` is ambiguous between the pin and the lambda overload. The CLI page documents the cast for reference types; I wrote it from the start.
11. **Domain defects found (all by literals, none by a draw):** see the findings. Each is kept as a `Skip = "domain defect: ..."` test.
12. **My own mistakes, for honesty:** (a) I first wrote `if (accepted) ... else ...` inside two theories and rewrote them as separate facts; (b) I tried to test `ShortestRest` with a rest below 11 h, which `Assign` makes unreachable (the roster itself refuses it), so the "elapsed rest" test now uses exactly 11 h elapsed against 12 h on the wall clock; (c) a Tokyo/Paris ordering test needed re-planning because every pair of shifts must respect the 11 h rule to be assignable. None was a library problem.

## What worked well
- **The scaffolder's sentinels.** Every guard it could not vouch for stopped the build at the line, quoting the guard, the file and the line. For a regex-heavy domain that is the honest behaviour, and following the TODO text literally was enough. `Site`, `Employee` and `Meeting` composed their owned generators (`new AnySiteId()`) and picked up `Site.MaxNameLength` as a named constant.
- **Refinement by lambda against a valid base.** `Any.Site().WithZone(z => z.WithIanaId("Europe/Paris")).WithWorkingHours(Hours.NineToFive())` says exactly what the test cares about (zone and hours) and leaves id and name arbitrary. `Any.PlanningPeriod().WithWeekCount(13)` and `Any.Meeting().WithDuration(...)` read as intent, and the refusal tests (`WithName(new string('n', 81))`) are one line.
- **Dummy discipline is cheap to follow.** Identities, names, titles, ids, unused sites and "some shift" are drawn; every date, time, zone, offset choice and duration that a test is about is a literal in the test. The two stay visibly apart (`anyXxx` vs literal), which in this domain matters because a DST test is nothing but literals.
- **The entry point.** `--entry-point any` with a C# 14 extension gave `Any.Site()`, `Any.ShiftRequest()` beside `Any.Int32()`; `Any.String().OneOf(...)`, `Any.StringMatching(...).DifferentFrom(...)`, `Any.TimeOnly().Between(...)`, `Any.TimeSpan().WithGranularity(...)` behaved exactly as the pages said.
- **Chained `IAny<T>.DifferentFrom`** on a scaffolded generator (`Any.SiteId().DifferentFrom(anySite.Id)`) solved "another id than this one" without ceremony.
- **Analyzers were quiet and correct.** My code (and the generated files) produce zero JD diagnostics even with JD001-JD038 raised to warning; a probe line immediately produced JD030, JD023, JD005 and JD011, so silence meant clean, not unloaded.
- **`[assembly: Reproducible]`** gave a seed per case, silent when green.

## Fluency: 4 / 5
The library did what its pages said every time, the `any` output told me precisely where to look, and the final suite reads as intent: drawn identities, literal clock times. I lose a point for the day-one blockers outside the code (`dotnet test --project` on the .NET 10 SDK, friction 1), for the thin story around ties between parameters (frictions 4 and 5: no pair for `TimeOnly`, no seam to change `Generate()` that survives `--force`), and for having to invent the distinct-ids-up-front pattern (friction 7). None of them cost more than a few minutes, and none of the draws ever produced a false failure.
