## Frictions and surprises, in order
1. **`dotnet test --project Tests.Regular` does not work out of the box.** First attempt: `dotnet test --project .` printed `MSBUILD : error MSB1001: Unknown switch ... Switch: --project`. The SDK is 10.0.114; `--project` only exists in Microsoft.Testing.Platform mode, which needs a `global.json` with `{"test":{"runner":"Microsoft.Testing.Platform"}}`. I knew the trick; no page of the user documentation says it (the xUnit adapter page lists `xunit.v3` 4.0.2 and nothing about how to run it; only `CONTRIBUTING` uses `--project`). Wrote `W/global.json` and moved on.
2. **`any generate` before restoring**: `✗ Ipv4Address: this project has not been restored, so its package references cannot be read. Restore it, then run the command again: dotnet restore`. Clear and actionable, nothing to change; I just note that I hit it on the very first command.
3. **A type with two public constructors is scaffolded from the first one only, without saying so.** `AddressPrefix` has `(Ipv4Address, int)` and `(Ipv6Address, int)`. The recap says `constructor AddressPrefix(Ipv4Address, int)` and `2 of 2 parameters inferred, 2 to verify`; nothing hints that another constructor was ignored. I would have noticed only because I know the domain; a newcomer gets a generator that can never produce IPv6 (the whole second half of the type). Expected a line such as "2 public constructors; scaffolded the first, use --constructor ...". What I did: deleted the scaffold and wrote the generator by hand, with both families.
4. **The `to verify` marks for tied parameters are accurate, but the tool stops there, and the documented remedy collides with pins.** Packets (`protocol` ties ports, flags and the payload ceiling), `FirewallRule` (family, protocol, ports, flags), `TcpFlagMatch` (expected is a subset of mask, forbidden pairs), `RuleAnomaly` (related rule null exactly for one kind, and different from the rule) came out as 6 files with `to verify`/`ties ...` messages that named the guards well (`ties protocol, sourcePort and destinationPort`). The page offers "derive one draw from another inside `Generate()`", which makes the `WithX` pin of the derived parameter lie (the page itself says so). I ended up replacing six scaffolds wholesale with small hand-written immutable generators that carry only the `With*` pins I need. The cost is not the code (≈ 40 lines each), it is that `--force` can no longer be used on them, and the tool's value for this domain was limited to the six simple types. No fix expected, but a "this is the shape for a protocol-dependent parameter group" example in the page would have saved a decision.
5. **`AddressPrefix`'s host-bits guard is reported without its tie.** `network: unread guard at AddressPrefix.cs, line 19: if (hostBits != 0) ...` (no `— ties network and prefixLength`), unlike every other tie in the same run, because the condition goes through a local. The message under-describes the problem: reading it, the `prefixLength` recipe `Any.Int32().Between(0, 32)` looks like the full story.
6. **Sentinel on a guard the generator already satisfies.** `Verdict`'s `if (action != Allow && action != Deny)` marks `action` `to verify, unread guards` (a `&&`, documented as never read) while the scaffolded `Any.Enum<RuleAction>()` is exactly right. Cost: open the file, delete two lines. Same for the `Ipv4Packet` source guard. Low.
7. **A domain exception thrown by a `Combine` composer reaches the test wrapped.** `Assert.Throws<ArgumentOutOfRangeException>(() => Any.Ipv4Packet().WithProtocol(132).WithPayload(new byte[65504]).Generate())` failed: `Expected: typeof(System.ArgumentOutOfRangeException) Actual: typeof(JustDummies.AnyGenerationException) ---- JustDummies.AnyGenerationException : Generation failed: the composer passed to Combine(...) threw for the generated values (...) (ArgumentOutOfRangeException: An IPV4 packet of protocol 132 carries at most 65503 payload bytes. ...)`. The message is excellent and carries the seed, and the inner exception is there, but for refusal tests it means "go through the real constructor, not the generator" — my packet generators are `Combine`-based, so I built these packets directly. `composition.en.md` says "if the constraints are too loose, the factory throws, and you find out immediately", and `errors-and-conflicts.en.md` describes `AnyGenerationException` only for bounded redraws; neither says a throwing factory/composer is wrapped. Docs gap.
8. **`Any.OneOf<byte?>(null, 6, 17)` fails at run time, not at build time.** `System.ArgumentException : The values must not contain a null element; use OrNull() to make the whole generator nullable. (Parameter 'values')`. The message is good. I wanted a pool with a 25 % chance of "no protocol"; `OrNull()` is fixed at one draw in ten and a repeated `null` in the pool is (rightly) flagged by JD025 (`This value is already in the pool; a duplicate neither weights it nor widens the domain`). I rewrote it as `Any.Int32().Between(0, 3).As(choice => choice switch { ... _ => null })`. A literal `null` argument to `OneOf` seems something an analyzer could see; I found no rule for it.
9. **`[assembly: Reproducible]` prints the seed line for failures that drew nothing.** My first failing tests were wrong literal expectations in `Ipv6AddressTests` (no `Any` call at all); the output still said `[JustDummies] These arbitrary values were seeded with -614827445. Reproduce this run with [JustDummies.Xunit.Reproducible(Seed = ...)]`. Harmless, a bit misleading while debugging a literal. Same for a Theory row failing in xUnit's own data conversion (`InlineData(47)` into a `byte?` parameter, an xUnit matter I fixed with `(byte)47`). Low.
10. **`JD037` caught me.** `Any.RuleId().Generate()` inside a `Combine` lambda: `warning JD037: This draw runs inside the lambda passed to Combine, apart from the recipe: compose an offset with Any.Combine, or derive the dependent draw with Then`. Correct and useful; I passed the id in as a parameter and drew it outside. (Positive, but it was a surprise worth recording: a build warning I had not seen for months.)
11. **Capacity of a drawn policy is a hidden dependency of any test that adds rules.** The scaffolded `AnyFirewallPolicy` draws `capacity` in 1..10 000, so a test adding three rules would fail on the rare draw of 1 or 2. I did not see it fail: I saw it while reading the generated file before writing the policy tests, and constrained it once in a fixture, `WithCapacity(capacity => capacity.GreaterThanOrEqualTo(50))`; where the test is about capacity it pins (`WithCapacity(2)`). The refine-the-valid-base lambda made this a one-line fix, but nothing in the tool's recap pointed at it (the `capacity` row is simply `guard`).

## What worked well
- `any generate` with several types in one command and `--entry-point any`: twelve generators and `Any.Ipv4Address()` style call sites in one step; the recap table (`guard`, `AnyX`, `to verify`) told me exactly which six files I could trust and which six I had to own.
- `PortRange` came out as an `Any.OrderedPair` with pins that bound the other side, and `FirewallPolicy` read `MaxNameLength`/`MaxCapacity` from the constants. Both needed nothing.
- The regex `TODO(any)` comment was precise enough to do the `AnyString` -> `AnyPattern` edit mechanically; the compiler then confirmed it.
- The analyzers earned their keep (JD025, JD037). The `Between`/`LessThan`/`GreaterThanOrEqualTo` builders accept `UInt128`, `uint`, `ushort`, `byte` with no surprise; `AllowingCombinations()`, `Except(...)`, `ElementOf(array)`, `ListOf(...).WithCount(n).Distinct()` and `Then(...)` were all findable in the pages and did what they said.
- Failures are actionable: the seed line, and `AnyGenerationException` naming the composer and the generated values.
- Property tests over a drawn *small universe* of prefixes were cheap to write with `Any.OneOf` + `Combine` and exercised the anomaly analysis meaningfully (all four anomaly kinds occur; removing any flagged rule never changed a verdict).

## Fluency: 4 / 5
The DSL itself is fluent and I rarely opened the docs after the first pass. What cost time was a domain with many cross-field invariants: half of the scaffolds had to be replaced by hand, `AddressPrefix`'s second constructor was dropped silently, and I needed a `global.json` the documentation never mentions to run the suite the way the brief asks. One domain defect (`RuleId` accepts a trailing line feed) was found by a plain literal case, not by a draw; the drawn properties (strict-mode invariants, `IsReachable` against anomalies, removal of redundant rules) all held over the repeated runs.

## Domain defect found
- `RuleId`: `^[a-z](?:-?[a-z0-9])*$` as a .NET `[GeneratedRegex]` lets `$` match before a final `\n`, so `new RuleId("allow-dns\n")` is accepted (a 32-character id plus newline is rejected only by length). The MODEL says the id is letters, digits and single hyphens. Test `RuleIdTests.An_id_with_a_trailing_line_feed_is_not_an_id` is kept and skipped: `Skip = "domain defect: RuleId's pattern ends with $ ..."`. It is a literal input, so no seed is involved. Fix would be `\z` (or `RegexOptions` without multiline plus `\z`).
