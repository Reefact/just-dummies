# Regular notes — 47 international catalogue
Agent: the same model and effort as every session of this trial. Library: JustDummies 1.0.0-uxtrial.1 (packed from main).

## What I did
- Pages skimmed, in order: `PROJECT-README.md`, `guides/getting-started.en.md`, `packages/justdummies-xunit.en.md`, `packages/justdummies-cli.en.md` (whole page, it is long), `generators/README.md`, `generators/strings.en.md` (alphabet + patterns, because the domain is all about non-ASCII text), `guides/composition.en.md` (`Then`, `Combine`, `OrNull`).

  Every file except `AnyContributor` was marked `to verify`/`TODO` and did not compile (as designed). 
- Generators completed by hand (all in `Tests.Regular/Generators/`):
  - `RecordId`, `LanguageTag`, `Isbn13`, `Isbn10`, `Issn`, `CallNumber`: base replaced by `Any.StringMatching(...)` (+ `.As(...)` for the check digit/char), field and constructor retyped to `IAny<string>`, refining overload deleted (a small python script did that; see friction 4).   - `Title`, `PersonName`, `ArticleRule`, `Catalogue` name: rewritten rather than patched, because the interesting rule (letters of one script, same script for family and given names) is a tie between parameters the scaffold cannot express. `AnyTitle.InScript(script)`, `OfLength(n)`; `AnyPersonName.InScript(script)`.
  - `BibliographicRecord`: rewritten by hand. Script -> (title, subtitle, language tag) and year -> ISBN are drawn in order inside `Generate()`, stored as `Func<WritingScript, IAny<...>>`/`Func<int, IAny<...>>` so each `With...` pin still wins; contributors are `count.Then(n => ListOf(AnyContributor).WithCount(n).Distinct())`.
  - `Contributor`: scaffold kept as is.
- Tests (267 methods, 600 cases, 3 skipped): `TitleTests`, `PersonNameTests`, `ContributorTests`, `LanguageTagTests`, `IdentifierTests` (Isbn13, Isbn10, Issn, CallNumber, RecordId), `ArticleRuleTests`, `ListingCollationTests`, `BibliographicRecordTests`, `CatalogueTests`, `DuplicateRecordExceptionTests`, `ScriptCoverageTests`, `GeneratorTests` (300 draws of every generator, a safety net for the hand-written ones). `[assembly: Reproducible]` in `AssemblyInfo.cs`.

## Frictions and surprises, in order
1. **`dotnet test --project Tests.Regular` is refused in a fresh workspace.** Output: `MSBUILD : error MSB1001: Unknown switch. ... --project .`. The SDK is 10.0.114 and falls back to VSTest unless `global.json` contains `{ "test": { "runner": "Microsoft.Testing.Platform" } }`. The docs mention only `dotnet test --solution` (PROJECT-README) and the xunit page says nothing about the runner a consumer needs for xunit.v3 4.0.2. I added `global.json` in W. Cost: a few minutes; a consumer page "test project setup" would save them.
2. **`any` writes the entry point into the domain namespace** (`namespace InternationalCatalogue.Domain;` in `AnyTitle.cs`, `AnyTitle.Entry.cs`) because the domain type's namespace is the default. Fine and documented (`--namespace`), but it means `Any.Title()` appears only after `using InternationalCatalogue.Domain;` and my test generators sit in a production namespace. I kept it.
3. **The scaffolder cannot help with the heart of this domain, and `to verify` is on almost every row.** `any generate` reported `to verify, unread guards` for `title`, `subtitle`, `language`, `script`, `isbn`, `publicationYear`, `contributors`, and for every string value object. The reasons are correct (regexes, helper calls returning `out`, ties across parameters: "language ties language to script", "ties isbn to publicationYear" are even named), so no complaint on honesty. But the work left is large: the only mechanism offered for a tie other than an ordered pair is "derive inside `Generate()`", which discards the `With...` pins. I rewrote four generators from scratch (friction 6). 
4. **Replacing a `string` base by `Any.StringMatching(...).As(...)` touches six places per file** (recipe field, constructor parameter, factory return type, delete the `Func` overload, delete two TODO lines). The doc (`When the replacement is another kind of generator`) is accurate, but with 6 value objects I wrote a python script to do it; my first script silently missed `RecordId` (the tool had inferred `Any.String().WithLength(10)` instead of `Any.String()`, my regex did not match, and since the TODO sentinel was already deleted the file still compiled and drew 10-character junk). The failure came from the first run, `FormatException: A record identifier starts with a two-letter upper-case agency code`, not from the compiler. Lesson for me, but an `any generate --accept-pattern`-like helper (or leaving the sentinel until the base is replaced) would have caught it.
5. **A lone surrogate cannot be an `[InlineData]` argument.** `[InlineData("\uD800")]` runs as `text: "�"` and `Assert.Throws<ArgumentException>` reports `No exception was thrown` (xUnit serialises theory data). Not a JustDummies matter, but this domain is full of such cases: I switched to an indexed static array. Worth a line in a "testing text" tip if the library ever documents Unicode.
6. **Strings are ASCII-only by design, so every non-Latin script needs hand-written classes, and supplementary-plane characters are the one place the tooling is unhelpful.** `Any.String()` draws 128 characters; the docs say `WithChars` or `StringMatching` are the escape hatches. `StringMatching` accepts `\uNNNN` ranges inside classes (`[\u0410-\u044F]`) and that worked first time. For a supplementary ideograph (the domain counts `\U00020000` as one cluster) I probed the options in a scratch test:
   - `Any.String().WithChars("\U00020000\U00020001")` -> `ArgumentException: The character pool must not contain a surrogate ... Draw such values as whole strings with OneOf(...) instead.` plus a build warning `JD014`. Excellent message.
   - `Any.StringMatching("[\U00020000-\U00020010]{3}")` -> `ArgumentException: The regular expression pattern "[<U+D840>-<U+D840>]{3}" is invalid: character class range '<D840>-<D840>' is out of order (at position 5)` (raw surrogates printed). Loud, but the message never says "astral/supplementary character"; I had to work it out.
   - `Any.StringMatching("\U00020000{3}")` is accepted and returns length 4: a high surrogate followed by three low ones, an ill-formed string, silently (the quantifier binds to the second UTF-16 unit, as it would in .NET `Regex`). 
   - `Any.StringMatching("(\U00020000|\U00020001){3}")` works (length 6). I used alternation/literals for the astral cases.
   So the right spelling exists but the three wrong ones fail differently (clear error, confusing error, wrong value); the strings page does not mention astral characters in patterns.
7. **`AsNullable()` exists for value types only.** `new AnyTitle().AsNullable()` gives `CS0453: The type 'Title' must be a non-nullable value type`. The docs show `.AsNullable()` only on enums/ints; for a nullable reference parameter that must be present I wrote `.As(title => (Title?)title)`. Expected from the name that it would cover reference types as well (it is a no-op at runtime there, but the `Title?` typing is what the constructor wants). Minor.
8. **`Any.RecordId().DifferentFrom(x)` worked on a scaffolded generator as documented**, but `DifferentFrom` reads oddly for `IAny<RecordId>` next to `Except`: I looked up the doc twice to be sure it was available outside builders. Not a defect.
9. **No analyzer ever fired.** `dotnet build --no-incremental -v n` shows no JD diagnostics at all for 4 900 lines of generators and tests. Good (no noise), though I could not tell whether e.g. JD007/JD030 would have had something to say about `Any.StringMatching(...).Generate()` inside `[Theory]` bodies; presumably they are Info and not printed.
10. **Dummy discipline caught three mistakes of mine.** (a) `Any.LanguageTag().Generate()` can come back as `ie-Vuqk-QB`, valid for `LanguageTag` but refused by `BibliographicRecord` (`Language tag ie-Vuqk-QB names script 'Vuqk', but the record is in Latin`); the draw was a dummy and the test failed on seed -781453313: the generator, not the domain, was wrong, so I added `AnyLanguageTag.WithoutScript()`. (b) A merge test took `Like(survivor)` for the absorbed record, whose random subtitle was in another script than the one I pinned afterwards. (c) A merge test asserted that the survivor *gained* a call number while the drawn survivor already had one (`Expected: 823.914 R884 / Actual: 545.12 L2`): that value was not a dummy, I pinned `WithCallNumber(null)`. Each came with the seed in the output, which is exactly the point.
11. **`Records()`/`SameWorkAs` style helpers are easy but there is no documented pattern for "a pinned copy of an existing value".** I wrote `Records.Like(record)` chaining eleven `With...` pins. It works nicely with my hand-written generator (pins are plain values) but with a scaffolded one the lambda forms would have been needed. A one-line `FromValue(x)` in the scaffold is a wish.

## What worked well
- The scaffold's shape (private copy constructor, `With...` returning copies) is easy to extend by hand; custom partial files (`AnyIsbn13.Custom.cs`, `AnyLanguageTag.Custom.cs`) survive and read well.
- `Any.StringMatching` with `\uNNNN` classes plus `.As(...)` for check digits gave valid ISBN-13/ISBN-10/ISSN by construction; 300-draw smoke test never failed.
- `[assembly: Reproducible]` plus the seed in the failure output made friction 10 trivial to diagnose; replaying was not even needed.
- `Then`, `Combine`, `OrNull`, `Distinct`, `DifferentFrom` composed without surprises; `Any.OneOf(array)` worked with `params`.
- The refusal messages of the scaffolder (`TODO(any): verify against RecordId.cs, line 17 ...`) point at the exact guard.

## Fluency: 4 / 5
A normal day with the library for a domain that is mostly value objects and string formats: the DSL and xUnit adapter were frictionless and the seed output paid for itself three times. I lose a point because the domain's real invariants are ties across parameters (script/title/language, year/ISBN), for which the scaffold stops at `to verify` and the documented route discards pins, so most generator code was hand-written; the lack of supplementary-plane/non-ASCII support in `WithChars` and the `dotnet test --project` setup gap each cost time too.

## Domain observations (not library)
- `ScriptCoverageTests` (3 skipped theories, literals so no seed): U+3005 `々` (佐々木, 時々) makes `new PersonName("佐々木")` throw `ArgumentException: Letter U+3005 belongs to no supported script`; Hangul compatibility jamo (`ㅋㅋㅋ`) and halfwidth katakana (`ｶﾀｶﾅ`) have no script (`LetterScripts()` empty). They conform to the ranges listed in MODEL.md but refuse ordinary Japanese and Korean text.
- Not defects, but worth knowing: two records differing only by contributor roles are `SameWork` duplicates (roles ignored), so they cannot coexist; `ArticleRule.Articles` ordering uses UTF-16 length with input order for ties.
