## Frictions and surprises, in order
1. **`dotnet test --project Tests.Regular` is refused by the SDK.** Exact output: `MSBUILD : error MSB1001: Unknown switch. ... --project Tests.Regular ...` (SDK 10.0.114). Expected the documented `dotnet test --project` to work. Cause: the VSTest mode of `dotnet test` has no `--project`; it needs the Microsoft.Testing.Platform runner declared in a `global.json` (`{"test":{"runner":"Microsoft.Testing.Platform"}}`). I created that file in W (outside the domain). Neither the xUnit adapter page nor the README mention it (the README only says `dotnet test --solution` and that `global.json` pins the SDK in the repository). Low-medium, docs.
2. **`any generate` on a fresh project.** `✗ Money: this project has not been restored, so its package references cannot be read. Restore it, then run the command again: dotnet restore`. Clear and actionable; I restored and re-ran. Nothing to change except maybe mention it in the CLI page's quick start.
3. **The multi-type run is pleasant.** `any generate A B C ...` in one command, one recap per type, `The file will not compile until you resolve it. That is deliberate.` The `to verify` / `TODO` markers got me to the right 12 places quickly; the "ties upper to lower" wording on both parameters was exactly the information I needed.
4. **The scaffold stays silent about a guard written as a helper of another class.** `Guard.IncomeKinds(kinds, nameof(kinds))` (rejects `None` and unknown bits) and `Guard.Label(label, ...)` (blank / over 80) are static helpers in `Guard.cs` that return the value. `any` printed `kinds  IncomeKind  Any.Enum<IncomeKind>()` and `label  string  Any.String()` with no mark, in 12 generators (`FlatRateRule`, `ProgressiveRule`, `ThresholdExemptionRule`, `IncomeAboveCondition`, `BreakdownLine`, ...). It compiled. First test run: `ArgumentOutOfRangeException : A tax base names at least one known income kind. ... Actual value was None.` (seed -1054216543) from `IncomeAboveCondition`. This is the documented "what the tool still cannot see stays silent" case (a validator of another type that returns the value), but this is a very common domain shape (one `Guard` class for the whole domain) and the failure is a 1-in-5 draw of an enum member or a 1-in-N blank string that I found by chance of a test, not by the build. I fixed it by hand in each generator (`Dummies.TaxBase()`, `Dummies.Label()`). Idea: when a constructor passes a parameter to a helper of another type that throws, mark `to verify` like for a void helper (or at least list it under the recap).
5. **`Any.Enum<IncomeKind>()` on a `[Flags]` enum with `None` and `All`** draws one declared member (None, Employment, SelfEmployment, Investment, All) - combinations such as `Employment | Investment` never appear, and `None` does. To get "any non-empty combination" I needed `Any.Enum<IncomeKind>().AllowingCombinations().Except(IncomeKind.None)`. That worked and the docs describe `AllowingCombinations` (enums page) - but nothing connects it to the scaffold, which writes the plain draw. Low.
6. **Tied parameters.** Four constructors tie two parameters (`upper > lower`, `deduction <= gross`, `ceiling > threshold`, `credit base/per-member not both zero`), all marked `to verify ... — ties X to Y`. The docs offer four forms; `Any.OrderedPair` is the natural one but it exists only on the built-in ordered builders, and the scaffold works with `AnyMoney` (a custom value object). I ended up rewriting `Generate()` by hand in three files (draw the first value, then `Any.Decimal().Between(0.01m, ...).As(width => new Money(lower + width))` for the other), which makes the generated `WithUpper(Func<AnyMoney, AnyMoney>)` / `WithExpenseDeduction(Func...)` overloads meaningless; I deleted them and kept the pins. Doc says exactly this ("a parameter you now derive no longer draws from its field") so it is not a surprise, but it is the most expensive part of the whole trial: four types needed a hand-written `Generate()`. In hindsight `Any.OrderedPair(decimalBuilder, decimalBuilder, strict: true)` followed by `new Money(...)` would have been shorter than what I wrote; the docs only show it with built-in values and never with a custom value object around them. Idea / docs: a worked example with a value object (`.As`) around an `OrderedPair`.
7. **Abstract parameters (`ICondition`, `TaxRule`, `IncomeComponent`).** `TODO, abstract` rows, each with a three-line comment telling me to write `AnyICondition : IAny<ICondition>` by hand "choosing among the concrete types". How to choose among generators was the surprise: `Any.OneOf(gen1, gen2)` is JD012 (pool of recipes). I tried `Any.ElementOf(generators).Then(g => g)` (the `JD012` page says "choose the generator with `Then`") and got `Dummies.cs(51,16): warning JD012: Call Generate() on each pooled generator, or choose one with Then: Any.ElementOf inferred a pool of recipes ...` - the warning fires on the very pattern its own message recommends, and the JD012 page only talks about `Any.OneOf`. I replaced it with `Any.Int32().Between(0, 2).Then(i => i switch { 0 => genA.As(x => (IComponent)x), ... })`, which is clean but is an index-and-switch for what is, in every domain with a hierarchy, the most common need. Idea: first-class `Any.OneOf(IAny<T> ...)`-like combinator ("one of these generators, drawing only the chosen one"). Also: the `.As(x => (Base)x)` upcast per branch is needed because `IAny<T>` is not covariant (or I could not tell from the docs).
8. **My first "age" test was not about a dummy.** `A_inner_rule_that_does_not_apply...` used `new AgeAtLeastCondition(120)` as "a condition that fails" with a drawn taxpayer: the scaffolded `AnyTaxpayer` birth date is a dummy, and ~5 % of the draws (born 1900-1904) are 120+ in 2024. Failed at seed 481195150 on the 3rd repeated run, replayed with the seed. The value was not a dummy: the test is about the taxpayer's age. I pinned `BornIn1990` in the shared helper (`Rules.Earning`). This is the library doing what the docs promise (a drawn value revealing that a "dummy" mattered); the seed line (`[JustDummies] These arbitrary values were seeded with 481195150. Reproduce this run with [JustDummies.Xunit.Reproducible(Seed = 481195150)].`) is exactly what I needed.
9. **A second failure of my own: `anyIncome.Source + "x"`** as "a different source" overflowed the 100-char limit on seed -722315143 (a 100-char dummy). Replaced by `Dummies.Source().DifferentFrom(anyIncome.Source)`. Same lesson, same quality of seed report.
10. **The scaffolded recipe for `Money` is the full domain range.** `Any.Decimal().Between(0m, Money.MaxAmount).WithScale(2)` - correct for a `Money`, but any aggregate that sums several of them (a taxpayer with up to 30 incomes) overflows `Money` (see domain finding). I had to refine every income to `<= 10 000 000` (`new AnyMoney().WithAmount(a => a.LessThanOrEqualTo(10_000_000m))` - the refine-by-lambda form is lovely here, and it stays a refinement of the base, not a replacement).
11. **Cast for the nullable condition**: `.WithCondition((ICondition?)null)` (documented in the CLI page, "A pin still takes null too, the cast telling the value apart from a lambda"). I forgot it once -> overload ambiguity; the compiler error pointed to it immediately. Fine.
12. **`Assert.Throws` + `AnyGenerationException`.** In a test that pinned `WithThreshold((Money)null!)` while my own default ceiling lambda read `threshold.Amount`, the test saw `JustDummies.AnyGenerationException : Generation failed: the factory passed to As(...) threw for the generated value 4069194.01 (NullReferenceException ...)` instead of the NRE: an exception inside an `.As(...)` factory is wrapped. The message is very good (names the factory and the drawn value); it was my generator's fault, but it means a test that expects a domain exception through a generator can see a wrapper if the exception happens inside `.As`. Worth knowing; docs on errors page probably cover it.
13. **Domain defect found (not a library issue).** See the findings: `$` accepts a trailing newline in `JurisdictionCode` and `RuleCode`. The tests are in the suite, `Skip`-ed.

## What worked well
- `Any.OrderedPair(..., strict: true)` for every "smaller / larger" arithmetic test (`Minus`, `MinusOrZero`, `Min`/`Max`, brackets): one line, never a retry.
- `Any.StringMatching` + `.As(body => body + TaxpayerId.CheckDigitFor(body))` for the Luhn id, and the retype recipe for `AnyPattern`.
- `Any.SetOf(new AnyRuleCode()).WithCount(n)` for "n distinct codes" in a schedule of 64 rules.
- Refining a base by lambda (`WithAmount(a => a.LessThanOrEqualTo(...))`, `WithRate(f => ...)`) - it builds on the base's rules.
- `[assembly: Reproducible]`: zero ceremony, and the seed line on failure made both of my "not a dummy" mistakes trivial to replay.
- The recap wording (`ties upper to lower`, `abstract`, `unread guard at X.cs, line N`) points at the exact line; the analyzers were quiet on a 340-method test project (the only warning I hit was JD012, friction 7).
- `Any.DateOnly().Before(Taxpayer.EarliestDateOfBirth)`, `.DifferentFrom(...)` on pattern/string/decimal builders: all the "other than this one" draws I needed existed.

## Fluency: 4 / 5
Day to day the DSL (builders, `OrderedPair`, `As`, `Then`, `StringMatching`) let me write the 340 tests quickly and the reproducibility story is excellent. The score is not higher because the part of the work specific to this domain - a tree of abstract types, constructors with tied parameters, and a domain-wide `Guard` helper - made the scaffold produce either silent wrong generators (friction 4), a lot of hand-written `Generate()` bodies (friction 6) or an index-and-switch to choose among generators with a JD012 warning on the documented alternative (friction 7); and `dotnet test --project` needed an undocumented `global.json` (friction 1).
