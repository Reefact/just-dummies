# Regular notes — 50 fx settlement
Agent: the same model and effort as every session of this trial. Library: JustDummies 1.0.0-uxtrial.1 (packed from main).

## What I did
- Read `PROJECT-README.md`, `README.md`, `guides/getting-started`, `guides/core-concepts`, the xUnit page, the whole `packages/justdummies-cli` page (the part about tied parameters and `With…` refinement is the one I actually needed), then skimmed `generators/numbers`, `enums-and-choices`, `dates-and-times` and `guides/composition` as a reference for `WithScale`, `OneOf`/`ElementOf`, `Combine`, `Then`, `DifferentFrom`, `StringMatching`.
- Read `MODEL.md` and all of `Domain/` before writing anything (the domain is full of cross-parameter rules, I wanted to know which ones the scaffolder could not see).
- Created `Tests.Regular/FxSettlement.Domain.Tests.Regular.csproj` from the template, plus `W/global.json` (see friction 1) and an assembly-level `[assembly: Reproducible]`.
- `any generate Currency Money CurrencyPair ExchangeRate Lei TradeId NetPosition SettlementInstruction RateSheet SpotTrade SettlementBatch --entry-point any --output Generators --namespace FxSettlement.Domain.Tests.Regular`
  (one run, 11 types, 11 generators + 11 `.Entry.cs`). 10 of the 11 stopped the build (`to verify` sentinels); only `NetPosition` was clean.
- Generators completed by hand:
  - `AnyLei`: followed the doc ("a replacement ending in `.As` is an `IAny<T>`"): `Any.StringMatching("[A-Z0-9]{18}").As(WithCheckDigits)`, ISO 7064 mod 97-10 check digits, retyped to `IAny<string>`, refining overload deleted.
  - `AnyTradeId`: `Any.StringMatching("FX[0-9]{10}").DifferentFrom("FX0000000000")`, retyped to `AnyPattern`.
  - `AnyCurrency`: rewritten (the ISO table ties code and minor units): draws from a pool of the 17 table currencies; `WithMinorUnits(n)`, `WithMinorUnitsAtLeast(n)`, `Except(...)`, `Pool`, `IsoCodes`.
  - `AnyCurrencyPair`: kept the scaffold, `Generate()` draws the base then `_quote.DifferentFrom(base)`.
  - `AnyMoney`, `AnyExchangeRate`: kept the scaffold, `Generate()` draws the currency/pair first and applies `WithScale(...)` to the amount/value recipe afterwards (pin vs recipe told apart with `ReferenceEquals(_x, _xRecipe)`).
  - `AnyRateSheet`, `AnySettlementBatch`, `AnySpotTrade`: rewritten entirely (sheet quotes each currency once against the pivot in either direction; batch draws value date then a sheet fixed on or before it; trade draws the rate, then a dealt amount whose other leg is >= 1 minor unit and <= the money maximum, with `SettlingOn(valueDate)`).
  - `AnySettlementInstruction`: positive amount (`WithAmount(a => a.Positive())`), value date from a hand-written `BusinessDays.Any()` generator.
  - `BusinessDays.cs` (hand-written): Monday-to-Friday dates (`Combine` of a week index and a weekday), `Plus`/`Minus` in business days.
- Tests (9 files, ~200 methods, 322 cases): `CurrencyTests`, `MoneyTests`, `CurrencyPairTests`, `ExchangeRateTests`, `LeiAndTradeIdTests`, `NetPositionAndInstructionTests`, `RateSheetTests`, `SpotTradeTests`, `SettlementBatchTests`. Literals stay literals where the assertion is about them (amounts, rates, dates, the two sample LEIs whose order matters); dummies are ids, counterparties, currencies the rule is indifferent to, "some other currency", "some weekday".
- Result: green, **319 passed, 3 skipped, 0 failed**; then **12 more runs** (fresh seeds each time), all green. Before that, 2 intermediate red runs on my own tests (friction 7). Build: 0 warnings, no JD diagnostic.
- Skipped (domain defects, kept as tests): 2 on `Currency` with a trailing line feed, 1 on `SettlementBatch` accumulating past the money maximum.

## Frictions and surprises, in order
1. **`dotnet test --project Tests.Regular` does not run out of the box.** `MSBUILD : error MSB1001: Unknown switch ... --project .` — on SDK 10 `dotnet test` stays in VSTest mode unless a `global.json` selects the Microsoft Testing Platform runner. I added `W/global.json` containing `{ "test": { "runner": "Microsoft.Testing.Platform" } }`. Neither the xUnit page nor getting-started says anything about it (they only say "xunit.v3 4.0.2 or later"). Expected the documented adapter setup to be sufficient.
2. **`any generate` on 11 types in one command: it works, and the batch recap is readable.** Output lines like `✓ AnyMoney.cs — 2 of 2 parameters inferred, 2 to verify.` are slightly contradictory: both parameters carry `to verify` and recipes the tool itself says cannot be right (`Any.String()` for a `Currency` code, `Any.Decimal().Between(...)` for an amount whose scale depends on the currency). "inferred" overstates it (low).
3. **The domain's rules are almost all ties between parameters, and the scaffolder reads none of them.** Examples as printed: `amount: unread guard at Money.cs, line 20: if (!currency.Allows(amount)) ... — ties currency to amount`, `value: ... ties value to pair`, `rate: first unread guard at SpotTrade.cs, line 26: ... — ties rate to dealtAmount, and 3 more`. It is honest and the sentinel (`CS0103: The name 'TODO_verify_the_generator_for_base' does not exist`) stops the build at the right line, which I like. But the doc's three recipes for ties (`Any.OrderedPair`, derive inside `Generate()`, `Then`/`Combine`) assume you tie two parameters of the same level; my ties are "draw A, then constrain B's *scale* from A" (amount vs currency, rate vs pair) and "draw A, then B must make a derived value fall in a range" (dealt amount vs rate). I ended up replacing `Generate()` in 6 of 11 files and rewriting 4 files wholesale. Expected: a helper for "this parameter's recipe depends on that one" (`Then` is on `IAny<T>` but the scaffolded recipe fields are builders, so I could not use it without losing `With…`). What I did: draw the driver first in `Generate()`, then apply `WithScale(...)` to the stored recipe.
4. **Once `Generate()` is hand-written, `With…(Func<…>)` and pins have to be told apart by hand.** In `AnyMoney`/`AnyExchangeRate` I needed "apply `WithScale` to the recipe unless the amount was pinned"; the only way I found was `ReferenceEquals(_amount, _amountRecipe)` (a pin replaces `_amount`, a refinement sets both). It works and the `--force` warning in the docs is clear, but nothing in the docs names this trick or offers a supported "is pinned" notion. A `--force` would also erase all of it: I should have put `Generate()` in a separate partial file, but the scaffolded `Generate()` is in the generated file, so I edited in place.
5. **No weekday vocabulary on `Any.DateOnly()`.** Four constructors refuse weekends (`SettlementInstruction`, `RateSheet`, `SettlementBatch`, `SpotTrade`'s trade date) and the scaffolder tags each `Any.DateOnly()` row `to verify` with `IsWeekend(...)` quoted. The doc has `Between`, `After`/`Before` but nothing for days of week, so I wrote `BusinessDays.Any()` as `Combine(Any.Int32().Between(0, 1000), Any.Int32().Between(0, 4), ...)`. A `WeekdaysOnly()` / `OnDaysOfWeek(...)` constraint would remove a hand-written helper in every project with a business calendar (idea).
6. **Naming trap in my own helper:** a static class method called `Any()` inside `BusinessDays` shadows `JustDummies.Any`, so `Any.Combine` inside it needed `JustDummies.Any.Combine`. Not the library's fault; noting it because `--entry-point any` makes `Any.X()` the idiom and I reached for the same name.
7. **Two red runs while I was writing the batch tests, both mine, both reported with a replayable seed.** (a) `BookOfArbitraryTrades` drew sheet rates `Between(0.5m, 500m)`: a cross rate between a 0.002-worth and a 500-worth currency rounds to 0, `RateFor` threw `InvalidOperationException` in arrange — the sheet constraint was too wide for what the test needed (fixed to `Between(0.5m, 2m)`). (b) `Valuing_in_the_base_currency_carries_the_rounding...` asserted `-4.40 EUR` but left the trade side random: half the runs gave `+4.40`. The test was about a buy, so the side stopped being a dummy. Both: `[JustDummies] These arbitrary values were seeded with 1342884010. Reproduce this run with [JustDummies.Xunit.Reproducible(Seed = 1342884010)].` printed under the failure; clear and useful. Nothing flaky, just my mistakes surfaced by the draw.
8. **A trap in the default Money base:** the scaffold's `Any.Decimal().Between(-999999999999999m, Money.MaxMagnitude)` is faithful to the domain but draws near ±10^15, so any test that adds two drawn amounts overflows (`ArgumentOutOfRangeException`). I expected that from the type's bound; I refine amounts in every arithmetic test. Also noted the asymmetry the doc predicts: upper bound references `Money.MaxMagnitude`, lower bound is the copied literal `-999999999999999m`.
9. **xUnit data with decimals:** attributes cannot carry `decimal`, so I used `TheoryData` with strings and parsed them. Not library-related, but with a money domain every `[Theory]` hits it; the doc is silent on `[Theory]` with `Any` anyway (only JD008 for providers).
10. **Domain defects found:** (a) `Currency` pattern `^[A-Z]{3}$` accepts a trailing line feed (`.NET` `$` also matches before a final `\n`): `new Currency("ABC\n", 2)` is built, and `new Currency("USD\n", 0)` escapes the ISO-table lookup, so an ISO code with the wrong minor units is accepted. (b) `SettlementBatch.Book` never checks that accumulated positions stay within the 15-digit money maximum: two 10^12 EUR buys at 900 EUR/USD with one counterparty book fine, then `NetPositions()` throws `ArgumentOutOfRangeException: An amount lies within ±999999999999999. Actual value was -1800000000000000`. Same for `BankNetPosition`.

## What worked well
- The sentinel/`CS0103` mechanism: every unresolved guard stopped the build at the exact line with the guard quoted; I never shipped a generator that silently drew invalid values. `to verify` rows were all justified on this domain.
- `Any.StringMatching(...).As(...)` for the LEI check digits and `.DifferentFrom("FX0000000000")` on a pattern: two lines each, no surprises, doc matched behaviour.
- `IAny<T>.DifferentFrom(x)` by redraw made pair/currency "another one" trivially expressible; `Any.ElementOf` for pools.
- `[assembly: Reproducible]`: one line, seed printed on failure, replay snippet names the attribute.
- `WithScale(n)` on a bounded `decimal`: amounts and rates on the right grid with no extra code; 26 green runs never produced a mis-scaled value.
- Zero analyzer noise on 200 tests; `Info` JD030 rows stayed quiet as documented.
- Refinement lambdas on the scaffolded generators (`Any.CurrencyPair().WithQuote(q => q.WithMinorUnits(0))`) read well once `AnyCurrency` exposed one method.

## Fluency: 4 / 5
Day-to-day DSL (`Any.X().Between/Positive/Except/DifferentFrom`, composition, `Reproducible`) was fluent and the docs matched behaviour every time I checked. The score is held back by this domain's shape: almost every aggregate has parameters whose valid range depends on another parameter's value, and there the scaffolder rightly refuses, then leaves me to rewrite `Generate()` by hand with no supported idiom for "constrain B from A's value" on a builder, plus the missing weekday constraint and the undocumented `global.json` needed to run `dotnet test --project`.
